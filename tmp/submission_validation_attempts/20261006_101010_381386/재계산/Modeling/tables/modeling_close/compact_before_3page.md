## 제2장. AI 예측모델 개발 및 성능평가

예측 목표는 다음 한 시간의 네 15분 전력값 중 최대값이다. 직전 시간의 관측이 끝난 뒤 과거 전력·생산량과 달력 정보로 예측한다. 시간 오류와 공백을 반영해 정확한 시차가 있는 공통 기록을 비교하고, 무작위 분할 대신 과거 학습 → 다음 월 평가를 적용했다.

![그림 1. 모델 개발과 매시간 적용 흐름. OOF는 평가 월 이전에 학습한 모델의 예측이다.](figures/modeling_close/pipeline.png)

*그림 1. 모델 개발과 매시간 적용 흐름. OOF는 평가 월 이전에 학습한 모델의 예측이다.*

1~3월→4월, 1~4월→5월, 1~5월→6월 순서로 모델을 비교했다. Optuna는 각 평가 월 이전의 내부 시간순 검증에서 설정을 선택했다. Ridge·Elastic Net·SVR, HGB·XGBoost·LightGBM·CatBoost·ExtraTrees와 앙상블을 비교하고, 전체 및 일별 최대 시간의 오차를 함께 고려해 기존 HGB 설정을 유지했다.

| 대표 비교·4~6월 | 전체 MAE | 최대 시간 MAE |
|---|---:|---:|
| 직전 값 기준 | 13.793 | 36.589 |
| 기존 HGB | 6.738 | 11.751 |
| ExtraTrees | 6.825 | 11.540 |
| XGBoost | 7.131 | 12.864 |

같은 기본 A 입력·2,184시간의 비교다. ExtraTrees는 최대 시간에서 유리했지만 HGB는 전체 오차와 두 지표의 사전 선택 규칙에서 앞섰다. 마지막 15분 값 추가는 개발에서 도움이 됐으나 후반기 최대 시간까지 일관되게 개선되지는 않아, 상승 시작을 별도로 예측하는 보완으로 이어졌다.

## 제2장. 지속 상승 예측과 선택적 보완

시간 내부 산술평균이 직전 시간과 과거 6시간 중앙값보다 각각 59.5 이상 높고, 중앙값 대비 상승폭이 과거 IQR의 1.5배 이상이면 상승 시작 후보로 정의했다. 시작부터 3시간 동안 원래 기준선보다 29.75 이상 높은 상태가 유지되면 지속 상승이다. 기준은 1월에서 정했으며 실제 위험 한계값은 아니다.

Logistic은 과거 정보로 지속 상승을 경고한다. 경고가 있을 때만 상태 입력을 보완한 HGB B1을 사용하고, 다른 시간에는 기본 HGB B0를 쓴다. 경계는 과거 OOF에서 음성 오경보 1% 이내로 정했다. 경과시간 입력 제거 후 경계는 0.4554612321이다.

![그림 2. 같은 7~8월 예측에서의 성능과 경고 변화. 회귀 1,344시간, 분류 정답 1,340시간, 일별 최대는 완전한 56일이다.](figures/modeling_close/performance_and_alarms.png)

*그림 2. 같은 7~8월 예측에서의 성능과 경고 변화. 회귀 1,344시간, 분류 정답 1,340시간, 일별 최대는 완전한 56일이다.*

기본 HGB 대비 상승 시작 MAE는 20.037→18.205(9.1% 감소), 상승 평균 과소예측은 19.419→16.342(15.8% 감소), 일별 최대 시간 MAE는 13.179→12.574(4.6% 감소)였다. 전체 MAE는 6.335→6.317로 0.28% 줄었다. 보완은 7시간에만 적용했다.

5~6월 개발에서는 상승 12건 적중·오경보 0건을 유지했다. 후속 분류는 1~6월 4,336시간, 회귀는 2~6월 3,598시간으로 한 번 학습해 7~8월에 고정했다. 입력만 매시간 갱신했고 7월로 재학습하지 않았다. 이전 표와 회귀 학습 범위가 다르므로 점수를 직접 합치지 않는다. 7~8월은 이미 본 기간으로, 이번 개선은 탐색적 재평가다.

## 제3장. 영향요인 및 오류분석

초기 경고의 오경보 38건은 모두 추적 상태의 경과시간이 180~227시간으로 학습 최대 64시간을 넘는 구간이었다. 상승 분류기에서 이 입력만 제거하니 기존 적중 7건은 유지되고 오경보는 0건으로 줄었다. HGB는 그대로 두어 경고 대상을 바꾼 효과를 확인했다.

![그림 3. 개선 사례(7/12)와 미탐지 사례(8/13). 음영은 지속 정답 구간이며 세로 점선은 직전 관측 완료 시점이다. 개선 4건의 개선폭 중앙 순위, 미탐지 6건의 실제 최대값 중앙 순위 사례를 선정했다.](figures/modeling_close/transition_cases.png)

*그림 3. 개선 사례(7/12)와 미탐지 사례(8/13). 음영은 지속 정답 구간이며 세로 점선은 직전 관측 완료 시점이다. 개선 4건의 개선폭 중앙 순위, 미탐지 6건의 실제 최대값 중앙 순위 사례를 선정했다.*

7/12 08시 실제 최대값 198에 대해 예측은 181.13→192.52로 가까워졌다. 8/13에는 경고가 없어 두 예측이 같았고 실제 207을 182.40으로 낮게 예상했다. 경고 7건 중 개별 오차 개선은 4건, 악화는 3건이므로 모든 경고가 개선을 보장하지 않는다.

Logistic의 표준화 입력×계수를 직접 분해했다. 적중·미탐지 상승의 과거 전력 평균 로짓 기여는 13.86·4.16, 달력 기여는 0.30·-1.22였다. 과거 전력도 판단에 기여했지만 경고 7건은 모두 월요일 08시였다. 이는 모델 계산의 설명이며 물리적 원인의 증명이 아니다.

공통 상승 13건 중 7건을 찾아 재현율 53.8%, 경고 정밀도 100%(7/7)였다. 6건은 놓쳤다. 사후 월요일 08시 규칙은 8건 적중·오경보 1건, 일별 최대 MAE는 모델과 같았다. 따라서 오경보 억제와 선택적 보완의 성과로 설명하며, 전반적인 상승 탐지나 하락 예측의 완성을 주장하지 않는다.

## 제4장. 현장 활용방안

직전 시간의 전력·생산량 관측 완료 → 다음 시간 최대 전력과 지속 상승 경고 확인 → 경고 시 보완 예측을 담당자가 검토하는 흐름을 제안한다. 담당자는 예정된 가동과 동시 사용 조건을 함께 보고 조정 가능 여부를 판단한다. 입력 시차가 없으면 보완 예측을 보류하고 자료 상태를 표시한다.

경고가 없어도 기본 HGB의 예측은 계속 확인한다. 미탐지가 남아 있으므로 무경고를 안전 판정으로 사용하지 않는다. 자동 설비 제어나 절감량을 평가한 결과는 아니며, 가동 조정과 전력·비용 절감은 현장 적용 제안의 범위다.

## 제5장. 창의성 및 차별성

전체 전력의 기본 예측과 지속 상승 시작의 판정을 결합해 필요한 시간에만 보완 모델을 적용했다. 데이터 진단에서 확인한 경과시간의 학습 범위 초과를 입력 설계에 반영해 오경보 38건을 없애고 상승 과소예측 15.8% 감소를 유지했다. 단순한 알고리즘 추가보다 오류 원인을 확인하고 적용 대상을 조절한 과정이 차별화 요소다. 단순 주간 규칙 대비 추가 이득은 작고 후속 결과는 탐색적이라는 범위를 함께 제시한다.

## 제6장. 코드 구성 및 재현성

원본 CSV, 입력·사건 정의, 모델·경계 설정, 전체 Python 코드와 저장 예측을 같은 폴더 구조로 보존한다. 정규 CPython 3.13에서 원자료 → 정확한 시차·정답 구성 → 시간순 학습·OOF 경계 → 고정 추론 → 결과 파일 생성까지 재실행했다. 분류 1,428개와 회귀 4,032개 예측이 기존 결과와 일치했다.

현재 환경에서 고정 방법을 재현한 결과이며 새 환경 설치 검증과 과거 Optuna 전체 재탐색은 별개다. CSV 저장·읽기의 수치 표현 순서를 명시했다. modeling_reproduce_selected.py에 --output-dir로 새 폴더를 지정하면 재현할 수 있다. 실행 위치는 Modeling/scripts이며 상세 원고 4.12~4.13에 전체 코드·명령·근거표를 연결했다.
