# 045 — 고최대 날짜와 월최대 기준의 재배치 결과 재집계

작성: 2026-09-28 | 실행: 2026-09-29 | **두 질문의 재집계·독립 검증 완료.** 사용자가 이번 세션에서 계산 보류를 해제했다. A044 저장값만 재집계했으며 새 최적화·예산 탐색·모델 학습·경보 평가는 실행하지 않았다.

## 이전 결과에서 생긴 질문

[E024](../../../EDA/jsw/reports/09.28_024_guidebook_domain_interpretation.md)는 정상 시각 241일 중 일최대 182 이상인 날짜가 105일이고, 비슷한 일최대에도 하루 평탄도와 높은 칸 수가 다름을 확인했다. 고전력 시간의 빈도와 월최대 발생 위치도 같지 않았다. 낮은 전력 분위수는 월·생산 기록·반복 가중에 따라 달라 단일 기저값으로 고정하지 않았다.

[A044](09.28_044_demand_management_scope.md)는 날짜별 기록값 합의 0·5·10%를 이동 예산으로 가정한 자유 재배치 결과를 계산했다. 주 결과인 일최대 감소 중앙값은 최대가 낮은 날을 포함한 전체 241일을 요약한다. 따라서 **일별 감소 중앙값으로 보인 개선이 고최대 날짜와 월최대라는 관리 지표에서도 유지되는가**를 확인할 필요가 있다. A044는 저부하 분위수를 바닥 제약으로 사용하지 않았으므로 E024의 저부하 결과가 기존 계산을 무효화하지는 않는다.

## 사용할 기존 결과와 고정 범위

- 입력: A044의 [날짜별 시나리오](../tables/09.28_044_redistribution.csv), [날짜별 집중도](../tables/09.28_044_daily_concentration.csv), [기간 요약](../tables/09.28_044_scenario_summary.csv), [월별 최대](../tables/09.28_044_monthly_max.csv). E024의 [날짜별 표](../../../EDA/jsw/tables/09.28_024_daily_concentration.csv)와 [월최대 위치](../../../EDA/jsw/tables/09.28_024_monthly_max_ties.csv)는 범위·값 대조에 사용한다.
- 1~8월 정상 시각의 완전한 241일, 1~6월/7~8월 구분, 0·5·10% 예산, 원래 0인 칸의 수신 허용/금지 조건을 그대로 유지한다. 새 최적화 알고리즘이나 예산 탐색 없이 저장된 결과를 재집계한다.
- 높은 날짜는 **조정 전 일최대 182 이상**으로 고정한다. E024의 105일과 일치하는지 먼저 확인한다. 182는 기존 탐색 기준이며 운영 한계가 아니다.
- 시각 오류가 있는 7월 이틀은 A044와 동일하게 재배치 대상에서 제외한다. 월별 완전 날짜 수를 함께 적고, 7월 결과를 31일 전체의 조정 결과로 해석하지 않는다. 9월은 포함하지 않는다.

## 질문 1: 고최대 105일에서도 전체 날짜와 비슷한 감소가 나타나는가

기간·예산·0칸 정책별로 전체 날짜, 조정 전 일최대 182 이상 날짜, 182 미만 날짜를 비교한다. 날짜 수와 원래 최대 수준을 표시하고, 일최대 감소량·감소율의 중앙값과 사분위 범위를 집계한다. 1~6월의 반복 프로필 영향을 확인하기 위해 각 집단 안에서 동일한 96값 전력 프로필을 한 번씩 센 결과도 비교한다.

고최대 날짜의 감소 크기가 전체 요약과 다르면 피크 관리 설명에는 해당 집단의 수치를 사용한다. 방향이 같더라도 전체 날짜 중앙값을 고최대 날짜의 대표 수치로 바꾸어 부르지 않는다. 집단 차이는 기록 형태의 사후 비교이며 설비별 조정 가능성이나 원인 효과가 아니다.

## 질문 2: 월최대는 얼마나 낮아지고, 최대를 만드는 날짜가 바뀌는가

각 월·예산·0칸 정책에서 **그 달 모든 대상 날짜의 조정 후 일최대 중 최대**를 계산한다. 원래 월최대 날짜만 추적하지 않는다. 다른 날짜가 조정 후 월최대를 만들 수 있기 때문이다.

월별로 조정 전후 최대값, 감소량·감소율, 전후 최대 발생 날짜와 모든 동률 날짜, 발생 날짜 집합의 유지·일부 겹침·완전 교체 여부를 기록한다. 조정 후 최댓값 동률에는 저장된 부동소수점 값의 수치 오차만 허용하는 고정 허용오차를 사용하고 실행 시 명시한다. A044 결과에는 조정 후 96칸의 실제 배치가 없으므로 조정 후 최대의 **시각**을 만들어내지 않는다.

월최대의 감소 크기나 순위가 일별 감소 중앙값과 다르면 두 지표를 별도로 보고한다. 동일 전력 프로필 날짜를 중복 제거해도 최대 연산 자체는 바뀌지 않아야 하며, 발생 날짜의 달력상 동률은 그대로 보존한다. 최대 발생 날짜가 바뀌면 원래 최대 날짜만 확인하는 방식이 놓치는 값을 구체적으로 기록한다.

## 실행 시 확인할 기준과 종료 조건

0% 예산에서 원래 일·월최대와 발생 날짜 집합이 재현되는지, 모든 날짜가 각 시나리오에 한 번씩 있는지, 고최대 집단이 105일인지 확인한다. A044의 전체 날짜 요약을 재현하고, 월최대가 해당 월의 어떤 조정 후 일최대보다 작지 않은지 확인한다. 원본과 A044 결과는 수정하지 않는다.

두 질문의 답으로 전체 날짜 요약을 유지할지, 고최대 날짜·월최대 기준으로 설명을 나눌지 판단하면 A045를 종료한다. 결과가 기존 판단과 같아도 기록하고 기준을 추가 탐색하지 않는다. 자유 재배치의 사후·일별 예산·기록값 합 보존 가정은 유지되므로 월최대 감소도 실제 설비 성과, 공식 청구 피크, 에너지·원화 절감이 아니다.

위 계획의 범위와 종료 조건을 유지해 아래 결과를 생성했다. 다음 절은 실제 실행 결과이며, 원본·A044·EDA·modeling·루트 공용 문서는 수정하지 않았다.

## 실행 계약과 입력 검증

[고정 설정](../tables/09.28_045_frozen.json)에 입력 10개 해시, 고최대 기준 182, 예산 0/5/10%, 0칸 수신 허용/금지, 기간·집단·가중법을 실행 전에 기록했다. 시나리오 키는 `date, budget_fraction, receive_zero`다. 정상 날짜 241개에 각각 6개 시나리오가 있고 전체 1,446행에 중복·누락이 없다. 날짜 형식·기간·월·프로필·원래 최대·예산 합·감소량·감소율을 대조했다. 고최대 집단은 조정 전 값으로 고정했으며 1~6월 69일, 7~8월 36일, 합계 105일이다. 그 미만은 112·24일, 합계 136일이다.

날짜 가중은 모든 관측 날짜를 센다. 프로필 가중은 같은 기간·집단에서 동일한 96값 전력 프로필을 한 번씩 센다. 원본 독립 검증에서 프로필 ID와 96값 배열의 대응도 확인했다. 전체 126개, 1~6월 67개, 7~8월 59개이며 고최대는 각각 61·26·35개다. 같은 프로필의 원래·조정 후 최대가 시나리오별로 같아 이 방식은 프로필당 동일 총가중치 비교와 같다. 가중법 두 개를 새 표본 수로 합치지 않는다.

감소량은 `original_max−optimal_max`, 감소율은 이를 원래 최대로 나눈 값이다. 감소량·감소율 각각의 중앙값과 25/75백분위를 선형 보간으로 계산했다. 두 중앙값을 서로 나누어 감소율을 만들지 않았다. 원래 최대 0이면 감소율은 미정의로 남기며 이번 범위에는 해당 날짜가 없다. 동률은 **`rtol=0, atol=1e-8`**로 고정했다. 반올림한 표시값으로 동률을 정하지 않았다.

월최대 절대 감소 범위는 5%에서 **38.91~55.32**, 10%에서 **55.52~71.82**다. 월최대 감소율 범위 19.65~24.92%·28.04~32.35%는 앞의 날짜별 감소율 중앙값과 별도 지표다. 각 월의 최고 날짜를 다시 고르는 연산이므로 같은 성과 숫자로 합치지 않는다.

원래 월최대 날짜만 추적했다면 3월 10%에서 **143.58**을 월최대로 잘못 보고했을 것이다. 실제는 3월 28일의 **150.56**으로 **6.98** 높다. 7월도 원래 19일의 169.38·153.09 대신 다른 모든 날짜를 비교한 172.58·154.01을 써야 한다. 5월 10%에는 최대 발생 날짜가 바뀌며 차이가 0.018885에 불과하지만 이는 동률 허용오차보다 크다. 표시 소수 두 자리의 유사함으로 날짜 집합을 합치지 않았다. 조정 후 96칸 배치가 저장돼 있지 않아 **조정 후 피크 시각은 산출하지 않았다.**

### 7월 오류 날짜를 그대로 두는 보조 가정

주 결과는 정상 시각 **29일**만의 월최대다. 7월 13·15일의 48행·192칸은 시각 미배정으로 재배치에서 제외했다. 두 날짜의 원래 최대 190·202는 조정 전 정상 월최대 222보다 작지만, 정상 날짜가 조정된 뒤에도 작다는 보장은 없다.

[오류 날짜 민감도 6행](../tables/09.28_045_excluded_date_sensitivity.csv)은 이틀을 조정하지 않고 원래 최대를 유지하는 **별도 보조 가정**이다. 원본 독립 순회로 두 후보 최대도 확인했다.

| 예산·두 0칸 정책 공통 | 정상 29일 조정 후 최대·날짜 | 오류 이틀 원래 최대 유지 시 보조 최대·날짜 | 원래 222 대비 보조 감소 |
|---|---|---|---:|
| 0% | 222·7월 19일 | 222·7월 19일 | 0 (0%) |
| 5% | 172.58·7월 28·30일 | **202·7월 15일** | **20 (9.01%)** |
| 10% | 154.01·7월 28·30일 | **202·7월 15일** | **20 (9.01%)** |

양수 예산에서는 190과 202 모두 정상 29일의 조정 후 최대를 넘는다. 원래 값을 유지하면 7월 최대 후보가 오류 날짜로 옮겨가며, 예산을 5%에서 10%로 늘려도 이 보조 최대는 더 낮아지지 않는다. **31일 모두 같은 조건으로 조정한 결과가 아니다.** 시각을 복원하거나 오류 날짜에 새 재배치를 적용하지 않았다. 따라서 정상 29일의 22.26·30.63% 감소를 7월 전체 효과로 표현할 수 없다.
