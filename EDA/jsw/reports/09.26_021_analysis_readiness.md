# 21차: 다음 분석을 위한 기록 시간 연결과 입력 사용 조건

작성일: 2026-09-26 | 작업 번호: 09.26_021 | 성격: 데이터 준비 점검·후속 분석 설계

## 1. 이전 근거와 이번 질문

[20차 점검](09.23_020_eda_review.md)에서 현재 CSV의 기본 EDA를 잠정 마감했다. [변수표](../../../data/origin/데이터_변수표.md)와 [14차 정의 점검](09.23_014_definition_audit.md)에는 비정상 시간 48행, 전력·생산량이 함께 0인 17행, 전력의 단위·시각 기준·생성 방식 미확인이 남아 있다. 사용자가 주최측 답변을 기다리는 동안 진행 가능한 분석을 요청하고 계속 진행하도록 지시했다.

이번 질문은 **기존 오류 구간을 유지할 때 이후 시간 분석에 필요한 과거 기록이 얼마나 확보되는가, 그리고 어떤 열을 언제 이용할 수 있는가**다. 새로운 전력 패턴·상관·예측 성능을 추가하지 않고, 이후 분석에서 사용할 대상과 보류 조건을 구체화한다.

실행 전 판단 기준:

- 시간 연결은 정상 날짜·시간 키의 정확한 차이로 확인한다. 행 순서만 이동해 오류 날짜 양옆을 붙이지 않는다.
- 1·24·168시간 전 한 지점의 존재와 직전 1·24·168시간 전체의 존재를 구분한다. 일주일은 과거 자료 범위 예시이며 필요한 입력 길이를 확정한 것이 아니다.
- 전력 0 구간을 포함한 창은 별도로 표시한다. 실제 정지·계측 누락의 정의가 없어 삭제 대상으로 채택하지 않는다.
- 결과는 기록 키의 연결 가능성이다. 실제 측정 구간의 시작·끝, 수집·처리 지연, 예측 시점 이용 가능성은 주최측 답변 전 확정하지 않는다.

## 2. 데이터와 처리

- 입력: [원본 CSV](../../../data/origin/okm_augumented_2021.csv), SHA-256 `8f7af2e49366c93e1d6f5fdef4b5e350066c1792ac463c2c2886e370f4674830`. 기존 보고서의 원본과 일치한다.
- 원본 6,168행·18열 중 날짜·시간·전력 네 열·평균·생산량 8개 열만 읽었다. 9월 값은 분석·집계에 사용하지 않았다.
- 1~8월 5,832행에서 시간 0~23인 5,784행·241일을 대상으로 한다. 48행은 원본에 남아 있고 이번 연결 범위에서만 제외한다.
- `record_key = 날짜 + 시간(hour)`는 정상 시간에만 생성한 임시 기록 키다. 실제 측정 시작 시각이라는 의미를 부여하지 않는다.
- 대상 키를 `s`라고 하면 단일 시차는 `s-h`의 기록 존재 여부이고, 연속 과거는 `s-1`부터 `s-h`까지 모두 존재하는지다. 현재 대상 기록은 과거 입력에 포함하지 않는다.
- 결측 대체·시간 복원·보간·반복 날짜 삭제·관측값 변환은 하지 않았다. 전력·생산량은 이번 대상 범위에 결측이 없다.

## 4. 필요한 과거 범위에 따라 대상 수가 달라진다

분모는 정상 시간 대상 5,784개다. 아래 대상은 이후 비교할 기록 후보이며 학습 샘플을 확정한 것이 아니다. 0 기록은 유지한다.

| 필요한 과거 정보 | 해당 시점 한 값이 있는 대상 | 직전 구간 전체가 있는 대상 | 연속 과거 확보 비율 | 연속 과거가 부족한 대상 |
|---|---:|---:|---:|---:|
| 1시간 | 5,781 | 5,781 | 99.9% | 3 |
| 24시간 | 5,712 | 5,712 | 98.8% | 72 |
| 168시간 | 5,568 | 5,424 | 93.8% | 360 |

1시간의 3개는 각 연속 구간의 첫 기록이다. 24시간의 72개는 각 구간의 처음 24개다. 168시간의 360개는 첫 구간의 168개, 하루짜리 둘째 구간의 24개, 셋째 구간의 168개다.

**일주일 전 값 하나를 쓰는 경우와 직전 일주일 전체의 평균·변동을 쓰는 경우는 다르다.** 전자는 5,568개, 후자는 5,424개다. 단일 시차 입력에 일주일 전체 연속 조건을 불필요하게 요구하지 않고, 연속 구간 통계에는 중간 기록의 존재를 확인한다. 24시간의 두 대상 수가 같은 것은 이번 오류 날짜 배치의 결과이며 일반 규칙이 아니다.

영향은 7월에 집중된다. 정상 7월 기록 696개 중 직전 일주일 전 한 값이 있는 대상은 648개(93.1%)지만, 직전 일주일 전체가 있는 대상은 504개(72.4%)다. 8월은 744개 모두 직전 일주일이 확보된다. 서로 다른 입력 길이의 결과를 나중에 비교할 때 7월 표본 구성 변화도 함께 보고해야 한다.

근거: [전체 확보 수](../tables/09.26_021_coverage_overview.csv), [월별 확보 수](../tables/09.26_021_coverage_by_month.csv).

### 전력 0 구간을 표시하면 영향을 받는 대상은 더 넓다

| 직전 연속 과거 길이 | 연속 과거가 있는 대상 | 대상 또는 과거에 전력 네 칸 모두 0인 행이 있는 대상 |
|---|---:|---:|
| 1시간 | 5,781 | 18 |
| 24시간 | 5,712 | 41 |
| 168시간 | 5,424 | 78 |

전력 0은 17행이지만 이를 포함하는 과거 구간의 통계까지 영향을 받을 수 있다. 마지막 표는 **문제 기록을 삭제한 결과가 아니라 영향 표시**다. 168시간의 78개는 8월 말로 분석 범위가 끝나므로 이후 영향을 모두 센 값은 아니다. 9월을 추가해 계산하지 않았다.

현재 채택: 0 기록을 유지하고 영향 여부만 저장한다. 주최측이 실제 관측이라고 설명하면 유지하고, 계측 누락이라고 설명하면 해당 구간과 이를 포함하는 입력 창의 처리 전후를 같은 대상으로 비교한다. 생성 규칙이 확인되지 않은 채 결과가 좋아지도록 창을 삭제하지 않는다.

## 5. 입력 변수의 사용 조건

이 표는 미래 분석을 준비하는 후보 구분이다. 아직 예측 대상·기간·모델을 확정하거나 학습하지 않았다. '과거'는 대상 구간 전에 측정이 완료되고 분석 시점까지 도착한 기록을 뜻한다.

| 열 또는 정보 | 현재 판단 | 다음에 필요한 조건 |
|---|---|---|
| 대상 날짜·시간·요일·월 | 달력 후보 | 기록 시각 앵커 확인 후 실제 분석 시각에 맞춤 |
| 과거 전력 네 값·평균 | 과거 입력 후보 | 단위·측정 구간·관측 완료 및 도착 시점 확인. 원전력과 계산 평균의 중복 정보 고려 |
| 대상 구간 전력 네 값·평균 | 결과 기록 또는 평가 대상 후보 | 같은 구간의 평균을 설명·예측하는 입력에 그 평균 구성값을 넣지 않음 |
| 과거 생산량 | 조건부 후보 | 정의와 수집 지연 확인 후 사전 이용 가능 여부 판단 |
| 대상 구간 생산량 | 보류 | 실제 실적이면 해당 구간 전에 알 수 없음. 계획값인지 확인 전 미래 입력으로 가정하지 않음 |
| 과거 기상 | 조건부 후보 | 관측지·시간·집계 기준과 도착 시점 확인 |
| 대상 구간 기상 실황 | 보류 | 미래 관측 실황을 사전 입력으로 넣지 않음. 현재 CSV만으로 당시 이용 가능 예보는 확보되지 않음 |
| 공장인원 | 독립 인원 입력으로 채택하지 않음 | CSV에서는 생산량/전력 합계와 일치. 공식 정의 확인 전 노동 인원으로 해석하지 않음 |
| 전기요금(계절)·인건비 | 정의 확인 전 보류 | 실제 단위·계수와 사전 확정 여부 확인. 원화 비용·절감액 계산 근거로 사용하지 않음 |

근거: [변수 계산·누출 진단](../../../data/origin/데이터_변수표.md), [7차 관계 점검](09.23_007_connected_eda.md). 같은 구간의 결과값을 입력에 넣어 답을 미리 알려주는 것을 정답 누출이라고 한다.

## 6. 이후 검증을 준비하는 기준

검증은 앞부분 자료로 분석 방법을 정하고 뒤 날짜에서 확인하는 절차다. 이번에는 자료를 학습·평가하거나 성능을 계산하지 않았다.

- 시간 순서를 유지한다. 전체 날짜를 무작위로 섞으면 반복된 하루 기록과 미래 정보가 앞뒤에 섞일 수 있다.
- 기존 003·007의 1~6월/7~8월 구분은 후보 기간으로만 유지했다. 최종 설정은 과제의 목표 구간 확인 후 정한다. 설정·변수 선택은 개발 기간 안에서 진행하고, 뒷기간 점수를 보고 계속 수정하지 않는다.
- 과거 기록이 부족한 시점을 다른 날짜로 대체하지 않는다. 서로 다른 입력 길이의 성능을 비교할 때는 공통 평가 대상 결과와 전체 가용 대상 결과를 구분한다.
- 순차 한 구간 분석이면 각 대상 전에 완료된 과거 실황을 사용할 수 있으나, 한 번에 여러 미래 구간을 다루면 중간에 새로 관측될 실제값을 미리 사용할 수 없다. 021의 과거 확보 수는 후자의 장기 예측 샘플 수가 아니다.
- 기록 키와 출처 행 번호를 남겨 기간 경계와 원본 값을 추적한다. `window_touches_zero_*`와 `target_all_power_zero`는 대상의 실제 결과를 이용한 **사후 점검용 표시**라서 예측 입력으로 사용하지 않는다.
- 007은 1~6월과 7~8월 사이 정확한 하루 전력 패턴 교차 중복이 없음을 이미 확인했다. 이 수치를 재계산하지 않았으며, 정확한 중복이 없다는 사실이 실제 독립 관측을 보장하지는 않는다.
- 모든 기간은 초기 EDA에서 이미 탐색됐다. 보류한 9월도 완전히 미관찰한 시험자료라고 부르지 않는다. 향후 기간 비교는 이 데이터 안에서 수행하는 과거 시점 검증으로 설명한다.

## 7. 판단 갱신과 다음 작업

**확인된 사실:** 기본 EDA를 반복하지 않고도 시간 오류가 이후 입력 구성에 미치는 범위를 구체화할 수 있었다. 단순 시차 입력과 연속 과거 통계는 대상 수가 다르며, 17시간 전력 0의 영향은 해당 행에만 한정되지 않는다.

**유지한 판단:** 원본 시간 오류를 복원하지 않고 0 기록을 보존한다. 생산량 0·동일 전력·비용 열을 실제 운영 원인이나 비용으로 해석하지 않는다. 기본 EDA 잠정 마감과 제공처 정의 확인 필요성은 그대로다.

**수정한 판단:** 이후 분석에 사용할 수 있는 자료 수를 정상 시간 5,784개라는 숫자 하나로 표현하지 않는다. 입력에 필요한 시간 연결, 전력 0 처리 조건, 물리 시각·도착 지연을 따로 확인한다.

이번 기록 연결·입력 조건 점검은 여기서 종료한다. 주최측 답변 전에 더 긴 과거 창을 임의로 늘려 반복 계산하지 않는다.

다음 작업은 답변 내용에 따라 다음과 같이 연결한다.

1. 시간 정의·정정 자료가 오면 원본과 별도의 파일로 관리하고, 이 021의 시간 키·연속 구간·영향 수만 갱신한다. 정정 파일과 열·기간·원본 해시를 먼저 대조한다.
2. 전력·생산량의 정의와 과제의 대상 구간이 확인되면 **분석 대상 값·분석 시점·사전 이용 가능한 입력·개발/검증 기간**을 고정한 문서를 작성한다. 대상 평균·네 구간·최댓값 중 어느 것을 다룰지는 아직 확정하지 않는다.
3. 반복·증강 방식과 0 표기가 확인되면 중복·0 처리의 유지/변경 근거를 정하고 해당 부분만 비교한다. 기존 CSV-only EDA 범위에서 예측 모델을 자동으로 시작하지 않는다.
4. 공식 답변이 일부만 오면 해결된 정의만 갱신하고 미확인 항목을 남긴다. 답변 지연을 추정으로 채우지 않는다.
