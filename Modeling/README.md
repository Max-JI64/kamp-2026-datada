# Modeling 진행 계획

2026-10-03 작성. 현재 상태는 **계획 작성 완료, 새 모델 학습·평가 미실행**이다. 새 EDA와 Analysis 3.1~3.4의 결과를 바탕으로 진행한다. 백업 및 이전 모델 결과를 재사용하지 않는다. 현재 Analysis에서 수행한 3.2의 선행 예측 실험은 실패·한계의 근거로만 참고하고, 최대전력 모델의 새 성과로 합치지 않는다.

## 1. 해결할 문제

**관측을 마친 직전 시간의 정보로 다음 한 시간의 최대전력을 예측하고, 실제 최대전력이 높은 시간의 과소예측을 줄일 수 있는가?**

주 예측 대상은 다음 시간의 네 15분 전력값 중 최댓값이다. 과거 평균·최대에 마지막 15분 값을 추가하는 방법을 핵심 비교로 삼는다. 전력 수준 예측과의 연결을 위해 시간 평균도 보조 목표로 평가하는 것을 계획한다. 두 목표의 성과는 별도로 보고하며, 실제 미래 평균을 알고 최대값을 복원하지 않는다.

최대전력은 연속값으로 예측한다. 새 이진 피크 기준을 정하거나, 생산량 0→양수 전환을 피크 발생으로 대신하지 않는다. 예측값의 단위는 원자료 척도로 유지하며 kW·kWh·전기요금 절감으로 임의 환산하지 않는다.

## 2. 이전 결과와 이번 비교의 연결

| 근거 | Modeling에서 확인할 질문 |
|---|---|

| 3.1: 생산량 0→양수의 절대 전력 변화가 양수 지속보다 25.5% 큼 | 실제로 이 조건에 예측오차나 과소예측이 집중되는가? |
| 3.2: 과거 평균 전력이 전환 구분에 유용했지만 전환 확률을 전력 예측에 연결한 효과는 불안정 | 과거 전력을 직접 사용하는 기준을 충분히 비교한다. 전환 확률·혼합 구조를 기본 구성으로 재사용하지 않는다. |
| 3.3: 달력·생산 등을 고려한 날씨 관계는 약함 | 과거 날씨가 예측에 추가 가치를 주는지 제한된 입력 비교로 확인한다. |
| 3.4: 과거 평균·최대를 고려한 마지막 값과 다음 최대값의 관계 +0.409, 엄격한 동일 평균 비교에는 예외 존재 | 마지막 값의 추가가 여러 평가 기간에서 실제 오차 감소로 이어지는가? |

## 3. M01 — 예측 조건과 평가 자료 구성

### 정보 시점

목표 시간의 시각을 `t`라 하면, `t−1`시간의 네 전력값과 생산량을 관측한 뒤 `t`시간의 결과를 예측한다. 예측은 매시간 갱신한다. 실제 기록 보고 지연은 현 자료에서 미식별이므로, 관측을 마친 기록을 이용할 수 있다는 가정을 문서화한다.

| 구분 | 사용 방식 |
|---|---|
| 목표 시간의 시간대·요일·월 | 사전에 알 수 있는 달력 입력 |
| `t−1` 및 그 이전의 전력·생산 기록 | 과거 입력 |
| `t−1` 및 그 이전의 날씨 | 추가 가치 검증용 입력 |
| 목표 시간의 실제 생산량·날씨·평균·최대값 | 정답 또는 사후 진단에만 사용 |
| 목표 전력으로 계산되는 공장인원 등 | 입력 제외 |
| 하루 전체의 전력 배열·실제 일별 최대 시간 | 반복성·오류 사후 점검에만 사용 |

### 자료와 시차

- 현재 승인된 출발 범위는 1~8월 정상 241일·5,784시간이다. 기존 오류 48행을 제외하고 0·극단값은 유지한다.
- 날짜·시간으로 정확한 시차를 연결한다. 누락 날짜를 건너뛴 이전 행을 직전 시간으로 간주하지 않는다.
- `t−1`, `t−2`, `t−24`, `t−168`의 연결 가능 시간 수를 기록한다. 시차가 긴 입력의 비교는 같은 유효 평가 행에서 수행하고, 전체 운영 가능 시간 수와 구분한다.
- 과거 값이 부족한 시간의 처리 규칙은 평가 전에 정한다. 예를 들어 전주 기록이 없으면 전날, 그것도 없으면 직전 기록을 쓰는 순서를 사전 고정할 수 있다. 주 비교에서는 공통 표본을 우선해 입력 효과와 표본 차이를 분리한다.
- 필요한 결측 대체·스케일링은 각 학습 기간 안에서만 정한다. 미래값으로 과거 기상 결측을 보간하지 않는다.
- 최대값·평균값과 입력의 시각을 원본으로 독립 대조하고, 원본 해시·유효 표본·제외 이유를 저장한다.

### 시간순 평가 초안

실행 전에 아래 초안으로 표본 수와 기간별 조건을 확인한 뒤 설정 파일을 고정한다. 무작위 행 분할은 사용하지 않는다.

| 역할 | 학습 | 평가 | 사용 목적 |
|---|---|---|---|
| 개발 비교 1 | 1~3월 | 4월 | 기준·입력·모형 비교 |
| 개발 비교 2 | 1~4월 | 5월 | 개선의 기간별 반복 확인 |
| 개발 비교 3 | 1~5월 | 6월 | 앞선 판단의 안정성 확인 |
| 고정 후 후반기 평가 | 1~6월 | 7~8월 | 개발에서 고정한 방법의 후반기 결과 보고 |

7~8월은 EDA·Analysis와 선행 실험에서 이미 살펴본 기간이다. 새 독립 시험이라고 부르지 않으며, 결과를 보고 설정을 바꿔 같은 기간을 반복 평가하지 않는다. 개발 기간도 탐색에 사용된 이력이 있어 내부 시간순 평가라는 범위를 명시한다.

원본의 9월 336행은 이번 계획의 개발 자료에 자동으로 넣지 않는다. 최종 확인용으로 사용할지는 실행 설계에서 기존 열람·사용 이력과 평가 역할을 먼저 확인한다. 현재 계획에서는 미편입이며, 이를 사용하지 않아도 1~8월 내부 평가의 한계를 명시하고 비교를 수행할 수 있다. 추가 자료 확보를 전제로 하지 않는다.

각 분할에서 동일 하루 전력 배열의 학습·평가 겹침과 새로운 배열의 결과를 사후 점검한다. 전체 평가에서 반복 기록을 삭제하지 않고, 기본 결과와 반복의 비중을 낮춘 보조 결과를 함께 확인한다. 이 점검만으로 자료 생성의 독립성이 입증된다고 쓰지 않는다.

**M01 산출물:** 입력·목표 정의, 분할별 행 수, 시차 가용성, 정보 시점 검증, 반복 배열 점검, 실행 전 조건 파일. 여기서 오류가 있으면 학습 전에 해당 구성만 수정한다.

## 4. M02 — 단순 기준과 기본 모형

### 먼저 비교할 단순 기준

다음 최대전력에 대해 직전 시간 최대값, 전날 같은 시간 최대값, 전주 같은 시간 최대값을 그대로 사용하는 세 기준을 비교한다. 보조 평균 목표도 같은 방식으로 비교한다. 전날·전주 비교는 최초 Analysis 계획에서 남은 질문을 해결하는 단계다.

전체 오차와 월별·생산조건별 결과를 확인해 이후 모형이 넘어야 할 기준을 정한다. 최종 평가 기간에서 잘 나온 기준을 사후 선택하지 않는다.

### 학습 모형

초기 비교는 규제 선형 회귀(Ridge)와 작은 부스팅 트리 회귀(HistGradientBoostingRegressor)를 계획한다. 모형의 복잡도가 다른 두 계열을 비교하며, 설치된 정규 Python 3.13 환경에서 패키지 가용성을 먼저 확인한다. 구체 설정과 제한된 후보 수는 M01 설정에 기록한다.

기본 입력은 달력, 과거 생산량과 0 여부, 직전·그 이전 평균 및 최대 전력이다. 설정은 개발 평가에서 선택하고, 비슷한 성과이면 단순한 구성을 우선한다. 많은 알고리즘을 결과가 좋을 때까지 추가하지 않는다.

**M02 판단:** 단순 기준을 충분히 넘지 못하면 예측 정렬·달력 패턴·오류 조건을 먼저 점검한다. 근거 없이 더 복잡한 모형으로 확대하지 않는다.

## 5. M03 — 마지막 15분 값의 추가 가치

주 질문은 **같은 모형·설정·학습 기간·평가 행에서 마지막 값 하나를 추가하면 성능이 개선되는가**다.

| 입력 비교 | 확인 목적 |
|---|---|
| A. 달력 + 과거 생산 + 과거 평균·최대 | 기준 성능 |
| B. A + 직전 마지막 15분 값 | 3.4의 핵심 가설 검증 |
| C. 기준에 전날·전주 전력 추가, 마지막 값 유무를 다시 비교 | 마지막 값의 이득이 단순한 계절 시차 누락 때문인지 확인 |
| D. 선택한 개발 구성에 과거 날씨 추가 | 3.3의 남은 예측 가치 확인 |

C·D는 기준과의 변경 사항을 하나씩 구분한다. 마지막 값의 효과를 다른 변수·설정 변경과 섞지 않는다. 처음부터 전체 네 구간·변환·전환 확률을 모두 넣지 않는다. 추가 입력은 실제 오류나 잔여 질문이 생겼을 때만 비교한다.

**M03 판단:** 전체 평균 점수뿐 아니라 개발 월별 방향과 최대전력 시간의 오차를 함께 본다. 입력 추가가 불안정하면 필수 입력으로 채택하지 않는다. 마지막 값 추가가 실패해도 결과를 보존하고 원인을 M04에서 확인한다.

## 6. M04 — 예측오차와 최대전력 과소예측 분석

### 공통 지표

- MAE를 기본 오차로, RMSE를 큰 오차의 보조 지표로 보고한다. 개선율에는 기준 오차와 평가 시간 수를 함께 적는다.
- 평균 과소예측량은 모든 평가 행에서 `max(실제−예측, 0)`의 평균이다. 평균 과대예측량도 반대 방향으로 계산한다. 해당 방향의 오류가 없는 행에는 0을 포함한다.
- 발생 비율과 발생한 행에서의 평균 크기는 별도로 계산한다. 크기 감소를 횟수 감소로 표현하지 않는다.
- 0값이 있으므로 단순 MAPE를 주 지표로 쓰지 않는다.
- 실제 일별 최대전력이 발생한 시간도 별도로 평가한다. 완전한 하루의 가용성을 확인하고, 동률 최대 시간은 하루 가중치 합이 1이 되도록 처리한다. 전 시간 평균과 일별 최대 시간 평균의 분모를 구분한다.
- 일별 상대적 최대는 낮은 전력의 날에도 존재한다. 최대값 자체의 크기와 오류를 함께 제시하고, 모든 일별 최대를 절대적으로 위험한 피크라고 부르지 않는다.

### 이전 결과에서 정한 오류 조건

먼저 생산량 0→양수·양수 지속·양수→0·0 지속, 기존 낮은 전력 구간의 지속·변화, 월·평일/주말·시간대별 오류를 본다. 실제 목표 생산량·전력으로 나눈 조건은 사후 오류 진단이다. 운영 시 미리 아는 상태로 사용하지 않는다.

각 조건의 표본 수·전체 오류 기여를 같이 보고, 오차가 집중된 조건에서만 추가 원인을 진단한다. 표본이 적은 교차집단의 유리한 결과를 대표 성과로 선택하지 않는다. 일별 오차 차이와 기간별 결과를 보고 반복 기록의 영향을 점검한다.

### 수정과 재검증

1. 이전 결과에서 어느 조건의 어떤 오류가 남았는지 적는다.
2. 구현·정보 시점·표본 구성 문제인지, 입력 정보나 모형의 한계인지 구분한다.
3. 변경 이유와 판단 지표를 먼저 기록하고 하나의 변경을 적용한다.
4. 영향을 받는 개발 비교만 재실행하고 전후 결과를 남긴다.
5. 개선이 반복되지 않거나 새 근거가 없으면 중단한다. 고정 후 평가를 보고 반복 조정하지 않는다.

과소예측에 대한 비대칭 손실·분위수 예측 등은 실제 오류 분석에서 필요성이 확인될 때만 검토한다. 그 경우 과대예측 증가와 예측 구간의 적정성까지 함께 평가한다. 현재 확정된 핵심 방법으로 미리 내세우지 않는다.

## 7. M05 — 고정 평가와 필살기 채택 판단

개발에서 입력·모형·전처리·평가 지표를 고정한 뒤 후반기 평가를 실행한다. 각 목표 시각의 정답·예측값과 모델 버전, 사용한 입력 시각을 저장한다.

차별적 성과로 채택하려면 다음 근거를 함께 제시해야 한다.

- 비교 가능한 기준보다 최대전력 예측오차 또는 중요한 최대시간의 오차를 개선했는가?
- 과소예측 감소가 과도한 과대예측 증가나 전체 성능 악화로 얻어진 것은 아닌가?
- 개선이 한 월·소수 사례·반복 배열에만 의존하지 않는가?
- 입력 추가의 이득을 같은 조건의 비교로 설명할 수 있는가?

허용할 전체 오차·과대예측의 악화 범위와 최종 선택 규칙은 개발 결과를 바탕으로 후반기 평가 전에 명시한다. 현장 비용 비율이 미식별이므로 임의의 경제적 최적값을 주장하지 않는다. 상충하는 결과는 숨기지 않고 조건별 장단점으로 남긴다. 큰 안정적 개선이 없으면 마지막 값 추가를 필살기로 포장하지 않는다.

## 8. M06 — 관리시간과 저감방안의 제안

예측 결과를 바탕으로 최대전력 상승이 예상되는 시간의 점검과 생산·가동 시점 조정 검토 방안을 제안한다. 현재 자료에는 설비별 이동 가능 부하와 생산 제약이 없어 실제 최적 일정·절감 전력·비용을 입증하지 못한다. 이전에 제외한 가정 기반 재배치 실험을 자동으로 재개하지 않는다.

기본 예측은 매시간 다음 한 시간을 보는 방식이다. 이 방식으로 하루 전체를 사전에 알고 관리시간을 골랐다고 표현하지 않는다. 같은 수의 관리시간에서 높은 최대전력을 더 잘 찾는 성과까지 제시하려면, **동일한 예측 시점에 비교할 미래 구간과 관리 가능 시간 수**를 먼저 정해야 한다. 여러 시간 앞 예측이나 사전 일정 제안이 필요한 경우에는 별도 예측 문제로 정의하고 검증한다. 현재 계획에서 성과로 보장하지 않는다.

저감방안은 실제로 확인된 예측 가능 범위·실패조건과 함께 기술한다. 제안과 실행된 절감 효과를 구분한다.

## 9. 기록·산출물과 실행 순서

| 순서 | 남길 산출물 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| M01 | 자료·정보 시점·분할 조건, 시차·중복 검증 | 시각 정렬과 입력 경계 확인 |
| M02 | 단순 기준 및 기본 모형 개발 결과 | 비교 기준과 오류 맥락 확보 |
| M03 | 동일 조건 입력 추가 비교 | 마지막 값·시차·날씨의 가치 판단 |
| M04 | 조건별 오류·최소 수정 전후 기록 | 채택 또는 중단 이유 정리 |
| M05 | 고정 설정, 후반기 예측 CSV, 통합 평가 | 성과와 한계 확정 |
| M06 | 관리·저감 제안, 보고서·재현 절차 | 관찰·예측·제안의 근거 연결 |

실행 시 `Modeling/scripts/`, `Modeling/tables/`, 필요한 `Modeling/figures/`를 만든다. 회차별 기록에는 이전 근거 → 질문·선택 이유 → 조건 → 결과 → 판단 변경 → 다음 단계 또는 종료 이유를 적는다. 실패한 방법도 기록하되 보고서 본문에는 결론을 설명하는 핵심 비교를 담는다.

정규 CPython 3.13으로 실행·검증하고 원본은 보존한다. 예측 수치의 독립 재계산, 정보 시점, 고정 설정과 원본 해시를 확인한다. 최종 재현에는 코드·실제 사용 패키지 버전·실행 명령·평가 예측 파일을 포함한다. 계획 작성과 학습 완료, 검증 완료, 제출 완료를 각각 구분한다.
