## S06 실행 결과: 경과시간 입력 제거로 오경보 억제, 상승 탐지 범위의 한계

**상세 원고 반영:** [4.12 지속 상승 예측과 선택적 HGB 보완](04_Modeling_원고.md#412-지속-상승-예측과-선택적-hgb-보완)에 S01~S06의 정의·학습·성능·오경보 개선·활용과 사용 코드를 연결했다. [regime_manuscript_documents.py](scripts/regime_manuscript_documents.py)로 추가 전 원고를 보존하고 기존 4.1~4.11 본문과 수치·링크를 검증했다. 최종 보고서는 방법·성능을 제2장, 오류 개선을 제3장, 차별성을 제5장에 배치한다.

2026-10-06 사용자 승인으로 상승 Logistic에서 `prior_state_age` 하나만 제거했다. **5~6월의 탐지를 유지하면서 이미 관측한 7~8월 오경보 38건을 0건으로 줄였다.** HGB 결합의 전체 MAE 악화도 해소했다. 다만 공통 상승 13건 중 7건만 탐지해, 사전에 정한 재현율 80% 기준에는 여전히 미달했다. 이번 결과는 실패 원인을 보완한 탐색적 성과로 보존하며, 급등·급락 전반을 안정적으로 예측한다는 결론으로 확대하지 않는다. 이 절의 판단이 아래 S05의 현재 방법에 대한 안내보다 우선한다.

### 이전 근거와 한 가지 변경

S05의 8월 오경보 38건은 모두 경과시간 180~227시간 구간에서 발생했다. 학습 최대값은 64시간이었고, 38건 모두 이 변수의 선형 로짓 기여가 가장 컸다. 따라서 사건 정의나 경고 경계를 오류 시간에 맞추기보다, 원값의 선형 외삽을 만드는 입력 하나를 제거해 그 영향을 확인했다.

분류 입력을 24개에서 23개로 줄이고 Logistic 설정·학습 시점·정답 확인 조건·과거 예측으로 경계를 정하는 알고리즘을 유지했다. 경계 숫자를 이전 값에 고정하는 대신, 변경된 점수에 같은 과거 전용 알고리즘을 적용했다. 새 경계 0.4554612321은 4~6월 OOF 2,182시간·상승 18건에서 산정했고 적중 18건·오경보 0건이었다. 7~8월의 정답으로 경계를 조정하지 않았다.

**이번 변경은 상승 분류기의 경과시간 입력에만 적용했다.** B0·B1 HGB의 입력과 예측값은 기존 결과를 그대로 사용했다. B1에는 기존 경과시간 입력이 남아 있으므로, 모든 모델에서 이 변수가 불필요하다고 해석할 수 없다. 새 분류 학습은 4~6월용 3회와 6월 말 고정용 1회이며, 새 회귀 학습은 없다.

### 개발 평가 후 조건부 후속 평가

4월은 순위 평가, 5~6월은 이전 월에서 나온 예측과 당시까지 확인된 정답으로 자동 경고 경계를 정했다. 5~6월 1,462시간에서 기존·변경 분류기 모두 상승 12건 적중·오경보 0건이었다. 경고 시간도 같아 S04의 상승 MAE 13.8%·과소예측 10.8% 감소와 전체 MAE 0.2% 감소가 유지됐다. 개발 탐지·회귀 결합 기준을 통과해, 사전 계약에 따라 후속 평가를 진행했다.

6월까지 정답이 확인된 1~6월 4,336시간으로 변경 분류기를 한 번 학습했다. 그 모델과 과거 OOF 경계는 7~8월에 고정하고 직전 관측만 갱신했다. 7월 정답으로 8월을 다시 학습하지 않았다. 7~8월은 여러 번 확인한 기간이고, 이번 가설도 S05 오류에서 나왔으므로 **새 독립 시험이 아닌 탐색적 재평가**다.

S06은 B0 대비 상승 시작 MAE **9.1%**, 상승 과소예측 **15.8%**, 일별 최대 시간 MAE **4.6%**를 줄였고, 전체 MAE도 **0.28%** 감소했다. 기존 S05의 45회 적용이 7회로 줄었으며 나머지 1,337시간은 B0 예측과 같다. 새로 찾은 상승이 늘어난 효과가 아니라, 같은 7개 적중을 유지하면서 불필요한 38회 적용을 없앤 효과다. 월별 전체 MAE는 7월 6.528→6.498, 8월 6.180→6.171이었다. 일별 최대 평가는 24시간 공통 예측이 모두 있는 56일을 하루 동일 가중치로 계산했다. 미래 지속 정답이 없는 네 시간도 회귀 평가에는 유지했다.

사전 판단 기준에서 **회귀 결합은 통과했지만 분류기는 재현율 부족으로 통과하지 못했다.** 오경보를 줄인 선택적 보완 후보와 모든 상승을 찾아야 하는 탐지기 역할을 구분한다. 하락 탐지 모델의 입력이나 성능은 이번 실험에서 개선하지 않았다.

### 월요일 08시 규칙과의 사후 대조

경고 7건이 모두 월요일 08시여서, 그 시간에 항상 B1을 적용하는 단순 규칙을 추가 학습 없이 대조했다. 이 규칙은 결과를 본 뒤 정했으므로 사후 진단이며 채택 후보로 바꾸지 않았다. 다른 요일·시간이나 경계를 탐색하지 않았다.

### 검증, 보존과 판단 갱신

분류기 4개 재로딩·독립 재학습, 표준화의 학습 범위, 과거 OOF 경계, 분류 지표 24개와 회귀 지표 150개를 별도 코드로 검증했다. 원본의 정상 시각 5,784시간과 최대값을 대조하고, B0/B1 예측 재사용·경고에 따른 선택·일별 최대와 시작 후 3시간 오차도 확인했다. 모두 통과했다. 월요일 규칙은 별도 스칼라 선택 대조를 통과한 사후 진단으로 보존한다.

경과시간 제거 비교는 여기서 종료한다. 이번 결과를 근거로 같은 기간에서 변환·임계값·모델을 더 늘리지 않는다. 보고서에는 탐색적 재평가에서 확인한 오경보 억제와 선택적 보완 효과를 쓸 수 있으나, 13건 중 6건의 미탐지와 단순 주간 규칙 대비 작은 추가 기여를 함께 적어야 한다. 추가 상승 탐지 개선을 시작하려면 놓친 6건과 적중 7건의 사전 관측 조건이 구별되는지를 먼저 확인해야 하며, 이번 실행에서는 새 탐지 후보를 학습하지 않았다.

## S05 실행 결과: 고정 후속 확인과 경과시간 외삽의 실패 조건

2026-10-06 사용자 승인으로 S05를 실행했다. **현재 상승 Logistic 경고와 G1 회귀 선택은 최종 채택 기준을 통과하지 못했다.** 공통 평가의 지속 상승 13건 중 7건을 찾았지만 8월 오경보가 38건 발생했다. 상승 시작 MAE·과소예측·일별 최대 시간 오차의 개선은 남았으나 전체 MAE가 5.5% 증가했다. S03·S04의 개발 성과와 후속 확인의 한계를 구분해 보존한다. 이 절의 판단이 아래 과거 실험의 다음 작업 안내보다 우선한다.

### 이전 근거 → 고정 후속 확인

S03의 5~6월 지속 상승 12/12 탐지·오경보 0과, S04의 경고 시간에만 보완 HGB를 쓰는 G1에서 상승 시작 MAE 13.8%·과소예측 10.8% 감소를 확인했다. 다만 당시 모든 상승이 08시였고 08시 규칙도 같은 상승값을 사용했으므로 기간이 바뀌어도 경고가 필요한 시간을 선별할 수 있는지 확인해야 했다.

### S03 근거와 고정한 S04 조건

S03은 지속 상승 12/12건·오경보 0건을 확인했지만, 전환 확률이 최대 전력값 예측에 추가로 기여하는지는 미확인 상태였다. S04에서는 같은 원시 과거 입력을 통제해 그 질문을 분리했다. 목표는 다음 시간의 네 15분 전력값 중 최대값이고, 평균 수준 전환의 정답은 S01 정의를 유지했다.

S03의 이전 월 학습 모델이 낸 저장 확률을 사용했다. 상승은 Logistic, 하락은 HGB로 가족을 고정하고 모델 표본이 부족했던 초기 상승 2~3월은 당시 달력 발생률로 대체했다. 모델 가용 여부도 B1에 함께 넣어 확률 입력의 효과와 구분했다. 1월 전체로 정한 사건 정의를 1월에 이미 알았던 것처럼 역적용하지 않도록 회귀 학습을 2월부터 시작했다. 모든 회귀 구성을 동일한 2월 이후 행으로 다시 학습했다. 기존 1월부터 학습한 M03 수치를 이번 기준 성능으로 재사용하지 않았다.

정답 t+2 확인 시각이 평가 월 시작보다 앞선 공통 행을 학습했다. 4월·5월·6월의 학습 행은 각각 **1,414·2,134·2,878시간**, 평가 행은 **720·744·718시간**이다. 6월 끝 두 시간은 지속 정답 미확정으로 제외했다. 기존 공통 시차 조건과 입력 시각을 유지했고, 24시간이 모두 평가되는 90일만 일별 최대 시간 비교에 사용했다. 5~6월의 일별 비교는 60일이다. 최대값 동률은 하루 가중치 합이 1이 되도록 나눴다.

회귀 HGB는 기존 설정 잎 수 15·반복 150·학습률 0.05·최소 잎 표본 20·L2=1·조기 종료 미사용·시드 42로 고정했다. B0는 기존 18개 입력, B1은 동일한 동적 과거 입력과 모델 가용 여부를 보완한 31개 입력이다. B2 상승·하락은 각 확률 하나를 추가한 32개, 양방향은 33개다. 직전 평균·생산량의 정확한 중복 열은 추가하지 않았다. 새로운 회귀 학습은 15회, 분류 재학습·Optuna·클리핑은 0회다.

4월에는 학습에 상승 모델의 OOF 확률이 없어 초기 진단으로 남겼다. 상승 결합의 주 평가는 5~6월 12건·1,462시간, 하락은 4~6월 15건·2,182시간이다. 입력 조합을 실행 결과로 고르는 평가가 아닌 고정 비교이며, S03 결과를 보고 시작한 개발 실험이다. 새로운 독립 시험으로 표현하지 않는다.

### 차별성으로 쓸 수 있는 내용과 한계

이번 조합의 기여는 **다음 시간에 시작할 지속 상승을 따로 예측하고, 그 경고 시간에만 과거 상태를 반영한 회귀 모델을 적용해 상승 오차를 줄인 것**이다. 확률을 직접 회귀 입력으로 넣으면 전력값이 더 정확해진다는 설명은 쓰지 않는다. 같은 전환 정답과 실제 적용 경고로 탐지 성과와 회귀 오차를 연결할 수 있게 됐다.

08시 규칙 역시 실제 상승 12건의 같은 B1 값을 사용하므로 상승 시작 오차는 G1과 완전히 같다. G1은 **61시간 중 상승이 아닌 49시간의 회귀 교체를 피하고 12시간에만 적용**했다. 일별 최대 MAE는 G1 8.740·08시 규칙 8.825로 G1이 작지만, 전체 MAE는 08시 규칙 5.594가 G1 5.608보다 작다. 따라서 모든 비교에서 가장 좋은 모델·달력 규칙보다 상승값을 더 잘 맞힌 모델로 주장하지 않는다. 49시간은 이번 상승 사건이 아닌 시간의 추가 회귀 교체 횟수이며, 그 교체가 모두 해로웠다는 의미나 측정된 현장 조치·비용 절감은 아니다.

평가의 상승은 모두 08시였고, S03에서 확인한 새 하루 배열 사건도 3건뿐이다. 이번 좋은 결과는 이 제한된 개발 조건의 지속 상승에 해당한다. 하락·다른 시각의 무전조 급등·좁은 박스권·복귀 시각·정확한 유지 길이로 확대하지 않는다. 최초 4월 초기 확률 부족과 하락 실패를 삭제하지 않고, 보고서에서는 핵심 상승 기여에 범위와 단순 규칙 상충을 붙인다.

## S03 실행 결과: 지속 상승·하락 시작의 다음 시간 예측

2026-10-05 사용자 승인으로 S03을 실행했다. **직전 시간까지의 관측과 목표 시간의 달력으로 지속 상승·하락이 다음 시간에 시작할 확률을 예측했다.** 5~6월 지속 상승 12건을 모두 탐지했고 오경보는 없었다. 4~6월 지속 하락은 15건 중 8건을 탐지했고 오경보는 10건이었다. 두 방향 모두 사전에 정한 제한된 개발 기여 기준을 통과했다. 전환 시작을 직접 예측한 결과이며, HGB 회귀와 결합해 전력값의 오차까지 줄였다는 성과는 아직 아니다. 현재 선택과 다음 작업은 이 절을 기준으로 하고 아래 S01·S02와 기존 실험은 당시 기록으로 보존한다.

### 이전 근거 → 질문 → 비교 조건

S02에서 지속 전환 직전의 변화량·시간 내부 마지막 값·최근 기울기 차이를 확인했으나 상승의 동일 조건 비교는 4/10건에 그쳤다. 또한 1~3월 지속 상승 10건 중 8건이 08시에 몰려, 달력만으로 얻는 성과를 넘어서는지 확인해야 했다. 따라서 사건 정의와 24개 입력을 고정하고 달력 발생률·직전 변화량·최근 6시간 기울기·Logistic·HGB를 비교했다. 목표 시간의 전력·변화량·사건 정답·하루 전체 배열은 입력에서 제외했다.

학습은 이전 모든 월의 정답 중 t+2 확인 시각이 평가 월 시작보다 앞선 행만 사용했다. 월별 예측은 2~6월에 생성하고 주 개발 결과는 4~6월에 비교했다. 학습에 지속 사건 8건·5개 날짜가 없는 상승 2~3월은 모델 학습을 생략했다. 상승 4월에는 확률 순위를 평가할 수 있지만 경계를 정할 과거 모델 예측이 없어 자동 경고 성과는 계산하지 않았다. 따라서 주 경고 비교의 상승은 5~6월 1,462시간, 하락은 4~6월 2,182시간이다. 방향 사이의 분모를 합쳐 같은 범위인 것처럼 제시하지 않는다.

Logistic은 C=1·학습 내 표준화, HGB는 잎 수 7·반복 100·학습률 0.05·최소 잎 표본 20·L2=1·조기 종료 미사용으로 고정했다. 분류기 학습은 총 16회이며 Optuna 튜닝은 하지 않았다. 평가 월 전에 생성된 시간순 예측 중 정답까지 확정된 공통 행으로 모델과 단순 기준을 각각 선택했다. 선택 점수는 사건 수로 가중한 월별 AP이며, 현재 평가 월 결과를 보고 모델을 바꾸지 않았다. 그 결과 상승 5~6월은 Logistic, 하락 4~6월은 HGB가 선택됐다.

각 방법의 경고 경계는 같은 과거 공통 예측에서 음성 경고 비율 1% 이하를 지키면서 사건 적중을 최대화해 정했다. 이후 평가 월에 그대로 적용했다. 최대 적중이 같으면 오경보가 적은 경계, 그다음 높은 경계를 택했다. 경계와 선택은 매월 갱신하지만 현재 월 정답을 사용하지 않았다. 달력은 학습 내 시각×주말 여부 발생률을 평활화하고 표본이 작은 조건은 시각, 전체 발생률 순서로 대체했다.

### 좋은 결과의 범위와 남은 실패

상승 경고 12건은 12개 날짜·11개 하루 배열에 있었으며 **모두 08시**였다. 직전 시간 평균은 49~64.25에서 시작 시간 159.5~189.5로 상승했다. 직전 시간에 이미 평균 증가 25.5~44와 마지막 값−평균 33.75~67.5가 관측돼 사전 단서가 있었다. 이 입력들의 조합을 사용한 성과이며 특정 변수 하나의 독자적 기여나 설비 가동의 원인을 확인한 결과는 아니다. 같은 달의 모든 시간에서 오경보를 평가했지만 다른 시각의 지속 상승, 예고 없이 발생한 모든 급등·완만한 추세 전환을 검증한 것은 아니다.

당시 학습에 없던 하루 전체 배열의 상승 3건도 모두 탐지했다. 전체 동적 입력 13개가 과거 학습 행과 정확히 같은 사건은 12건 중 1건이었다. 반면 새로운 하루 배열의 사건 3건만으로 넓은 일반화를 입증할 수는 없다. 하루 배열은 사후 진단에만 사용하고 예측 입력이나 선택 기준에는 넣지 않았다.

하락은 학습에서 본 하루 배열 7건 중 6건을 잡았지만, 새 배열 8건 중에는 **2건**만 잡았다. 전체 7건 미탐지와 10건 오경보가 남아 상승과 같은 강도로 성과를 주장하기 어렵다. 실제 시작 뒤 1·2시간의 경고는 [사건별 예측표](tables/regime_forecast/event_predictions.csv)에 따로 저장하고 사전 적중으로 합산하지 않았다. 이번 주 평가의 짧은 하락 31건에서는 선택 모델 오경보가 없었다. 4~6월에는 짧은 상승이 없어 상승의 일시적 튐 구분 성능까지 검증했다고 쓰지 않는다.

이번에는 3시간 이상 기준에서 벗어나는 시작 여부를 예측했다. 이후 전력값의 정확한 박스권, 복귀 시각과 유지 기간은 아직 예측하지 않았다. 기록된 시간의 직전 관측으로 다음 시간 전체를 예측하는 설계이며, 실제 공정 전환 시각보다 반드시 60분 먼저 경고한다는 운영 효과도 측정하지 않았다.

### 판단 갱신과 다음 S04

**지속 상승의 시작 예측은 보고서에서 다룰 만한 개발 근거를 확보했다.** 핵심 주장은 현재 자료의 08시 지속 상승을 선행 관측으로 구분한 성과다. 하락은 보조 성과와 새 배열 실패를 함께 남긴다. 과거 M04의 최대값 급등·오류 경고와는 목표 정의·평가 행이 달라 수치를 그대로 비교해 모든 성능이 개선됐다고 쓰지 않는다. 7~8월 자료를 새로 읽거나 재평가하지 않았다.

다음 질문은 **이미 원시 입력에 들어 있는 상승 단서를 통제한 뒤에도, 예측 전환 확률을 HGB에 추가하면 전환 시간의 최대 전력 오차가 줄어드는가**다. S04에서는 B0 기존 회귀 입력 → B1 동일한 과거 상태 입력 추가 → B2 그 입력과 과거만으로 생성한 전환 확률 추가를 같은 시간 행에서 비교한다. 주 후보는 상승 확률이고, 하락·양방향 추가는 별도 비교로 둔다. 학습용 확률은 해당 행 정답을 학습하지 않은 시간순 예측이어야 하며, 확인되지 않은 초기 모델의 확률을 채울 규칙·공통 행·회귀 선택 기준을 실행 전에 고정한다. 이번 S03의 저장 모델을 이용해 과거 학습 행을 다시 예측한 확률을 학습용 OOF로 사용하지 않는다. 전체 오차·지속 전환 오차·일별 최대 시간·과소예측을 함께 비교해 정보 추가 효과와 평상시 악화를 구분한다. S03의 성공을 회귀 개선의 성공으로 대체하지 않는다.

## S01·S02 실행 결과: 전력 수준 전환의 시작과 지속

### 이전 근거와 이번 선택

기존 EDA·Analysis는 낮은 20~26 구간의 지속과 진입·이탈을, M04는 시간 최대값 증가 93 이상의 급등을 다뤘다. 사용자는 상승·하락의 시작과 전환 이후 수준의 지속을 예측하는 목표를 명확히 했다. 이에 시간 평균의 큰 변화와 이후 유지 여부를 먼저 정답으로 구성했다. 원고 4.11의 큰 과소예측 검토 우선순위는 이 목표의 핵심 필살기에 해당하지 않으며 보조 실험으로 보존한다.

### S01의 고정 정의

원본의 1~6월 정상 시각 4,344시간을 사용했다. 직전 여섯 시간 평균 전력의 중앙값을 기준 수준으로 삼고, 정확한 여섯 시간 이력이 있는 4,338시간을 시작 판정 대상으로 뒀다. 3시간 정답까지 확인 가능한 평가 행은 마지막 두 시간 등을 따로 구분한다. 기존 M01의 시차 168시간 공통 표본과 다른 범위이므로 기존 사건 수·오차를 그대로 비교하지 않는다.

1월의 양의 시간 평균 증가량 90분위수는 **59.5**, 음의 변화 절댓값 90분위수는 **42.925**였다. 이 두 경계를 고정했다. 주 정의는 현재 시간의 직전 대비 변화와 여섯 시간 기준 대비 변화가 모두 해당 방향 경계 이상이고, 기준 대비 변화가 과거 IQR의 1.5배 이상인 경우다. 기준이 0 근처여도 비율만으로 사건을 정하지 않는다. 95분위수의 상승 80.7125·하락 66.0875는 사전 민감도 비교로만 남겼다.

시작 직후 기준 수준을 고정한다. 같은 방향으로 기준에서 절반 경계 이상 벗어난 상태가 이어지면 같은 시작을 반복 집계하지 않고, 복귀·반대 방향의 새 적격 전환·결측에서 추적 상태를 갱신한다. 같은 방향의 추가 큰 변화는 후보 열에 남기지만 이번 주 정의의 새 시작으로 세지 않는다. 따라서 이번 범위는 모든 작은 계단 변화나 완만한 추세 전환을 포함하지 않는다.

시작 시간과 이후 두 시간 모두 같은 방향으로 절반 경계 이상 벗어나 있으면 **3시간 지속 전환**, 그 전에 복귀하면 **짧은 변화**다. 다음 두 시간을 확인할 수 없으면 미확정이다. 입력으로 사용 가능한 시작·과거 추적 상태와 미래 두 시간이 필요한 지속 정답을 별도 열로 저장했다.

지속시간은 시작 당시 기준으로부터 절반 경계 이상 벗어나 있는 연속 시간 수다. 이는 같은 값의 좁은 박스권이 유지된 시간은 아니다. 서로 다른 기준을 가진 상승·하락 사건의 지속 구간은 겹칠 수 있으므로 전체 시계열을 상호 배타적 상태로 나눈 결과로 해석하지 않는다. 종료 시점의 수준·변동 범위 예측과 완만한 변화는 후속 질문으로 남긴다.

본 회차 1~6월 정상 기록의 시간 평균 최댓값은 202, 네 구간 최대값의 최댓값은 222였다. 사용자가 든 1980은 이번 범위의 관측 수치가 아닌 설명용 예시로 취급한다.

### S02: 전환 직전의 단서와 비교 가능한 범위

목표 시점의 달력과 직전 수준·여섯 시간 기울기/IQR/범위·직전 증가량·마지막 값과 평균의 차이·과거 생산량·과거 추적 상태의 나이를 후보 입력으로 구성했다. 목표 시간 전력·증가량·지속 정답과 날짜 전체 배열 식별자는 예측 입력에서 제외했다.

선행 조건은 목표 시점이 1~3월인 기록에서 비교했다. 지속 사건의 해석은 이후 두 시간 기록을 사용한다. 월·시각·직전 수준 구간이 같은 조건에서 새 시작이 없는 시간을 대조했고, 직전 수준 구간 경계도 1월에서 정했다. 시작 없음에는 이미 높은·낮은 상태가 이어지는 시간도 포함한다.

같은 조건에서 전환이 두 건 이상·대조가 다섯 시간 이상인 주 비교는 지속 상승 **4/10건(40%)**, 지속 하락 **17/28건(60.7%)**을 포함했다. 상승은 두 조건뿐이고 대조 시간도 열 개여서 전체로 확대하기 어렵다. 한 건 조건을 허용한 민감도와 전체 조건 구성 차이를 함께 보존했다.

| 선행 입력의 같은 조건 내 평균 차이 | 지속 상승 − 새 시작 없음 | 지속 하락 − 새 시작 없음 |
|---|---:|---:|
| 직전 시간의 평균 변화 | +36.313 | −8.471 |
| 직전 마지막 값 − 직전 평균 | +32.925 | −7.713 |
| 최근 6시간 기울기 | +7.110 | −1.895 |

방향에 맞는 앞선 변화가 남아 양방향 분류를 시도할 근거가 있다. 다만 상승의 적은 비교 표본·시각 구성·반복 배열이 섞여 있어 예측 가능성이나 특정 변수의 독자적 효과를 입증한 결과는 아니다.

지속 전환과 짧은 변화끼리도 비교했다. 조건을 맞추지 않은 1~3월 상승 사건에서 직전 변화의 평균은 지속 22.025, 짧은 변화 −30.25였고, 직전 마지막 값−평균은 각각 24.625와 −4.542였다. 하락에서는 마지막 값−평균이 지속 −19.223, 짧은 변화 −7.829였다. 이는 사건끼리의 기술적 차이이며 해당 조건으로만 분류하면 잘 맞힌다는 검증은 아니다.

시간대도 반드시 넘어야 할 단순 기준이다. 1~3월 지속 상승 10건 중 8건은 08시, 나머지는 16시·21시였다. 지속 하락 28건 중 27건은 00시·07시·08시에 모였다. 따라서 달력별 과거 발생률보다 모델이 더 잘 구분하는지 후속 평가해야 한다. 마지막 값만 추가해 얻은 효과로 주장하지 않는다.

### 판단 갱신과 S03의 구체적 실행 조건

이번 결과는 사용자가 원하는 지속 전환이 관측되고 선행 단서도 일부 존재한다는 근거다. 핵심 필살기는 전환 시작·지속의 사전 예측으로 유지한다. 반면 다음 사실 때문에 최초 모델 계획을 좁힌다.

1. 1~3월 지속 상승은 10건·지속 하락은 28건이다. 여러 희소 집단을 한 번에 나누는 다중분류 대신 **지속 상승 / 지속 하락의 두 이진 예측**을 먼저 비교한다. 짧은 변화는 지속 사건에 대한 비사건이며 별도 오류 조건으로 남긴다.
2. 2월에는 주 정의의 상승 시작이 없다. 그 달 상승 AP는 정의 불가로 기록하고 평균에서 좋은 점수나 0으로 대체하지 않는다. 내부 튜닝에 유효 사건을 가진 월이 충분한지 방향별로 따로 확인한다.
3. 최초 비교는 달력 발생률·직전 기울기 규칙·Logistic·HGB의 고정 설정으로 한다. 과거 학습에서 지속 사건이 적어도 8건·5개 날짜 있고 음성도 존재할 때 해당 방향을 학습한다. 이 조건이 안 되는 초기 월은 학습을 건너뛰고 달력 기준을 남긴다.
4. 최초 설정은 Logistic C=1·학습 내 표준화, HGB 잎 수 7·반복 100·학습률 0.05·최소 잎 표본 20·L2=1·조기 종료 미사용·시드 42다. 최초 결과 뒤 새 근거가 있고 과거 내부 검증에 방향별 사건 3건 이상인 월이 두 개 이상 확보된 경우에만 동일 예산의 Optuna 최대 20회/모델/외부 월을 검토한다. 초기부터 희소 상승을 기준 조정·튜닝 확대의 대상으로 삼지 않는다.
5. 목표 t의 지속 정답은 t+2가 끝나야 확인된다. 학습 종료를 넘는 정답 행을 제거하고 공통 비교 행을 만든다. 시작 라벨과 지속 정답 확인 시각은 저장 표에서 바로 대조할 수 있다.
6. 최초 경고 경계는 과거 시간순 검증에서 음성 경고 비율 1% 이하 조건으로 정하고, 사건 적중·100시간당 오경보·방향·월을 함께 평가한다. AP는 경계 선택과 별도로 보존한다. 과거 검증이 불가능한 초기 방향은 자동 경고 성과를 주장하지 않고 고정 모델의 확률 순위와 후속 검증 가능성을 기록한다.
7. 유용한 방향의 개발 기여 기준은 동일 내부 경고 부담에서 고른 단순 기준보다 외부 적중이 최소 2건 많고 상대적으로 20% 이상 많으며, 실제 외부 오경보가 100시간당 0.5건 이상 추가되지 않는 것이다. 기준이 0건이면 상대 개선은 계산하지 않고 절대 증가로 판단한다. 모든 달의 승리는 요구하지 않지만 월별 차이와 반복 배열·특정 사례 집중을 함께 제시한다. 이 기준은 S03 학습 전 계약에 고정한다.

이번에는 S03 학습·튜닝과 HGB 결합을 실행하지 않았다. 다음 실행은 위 조건을 계약으로 고정하고 과거만으로 지속 상승·하락 확률을 생성하는 비교다. 전환 모델의 기여가 확인된 뒤에 B0/B1/B2 결합으로 이어간다. 결과가 약하면 그 원인에 맞는 최소 변경이나 분기 종료를 결정한다.

### 1. 목표와 기존 작업의 연결

이번에 답할 질문은 다음과 같다.

1. 현재 전력 수준에서 다음 시간에 위쪽 또는 아래쪽으로 크게 이동하는가?
2. 그 변화는 곧 복귀하는 일시적 변동인가, 여러 시간 이어지는 수준 전환인가?
3. 전환이 예상될 때 이후 전력 수준과 변동 범위를 얼마나 예측할 수 있는가?
4. 예측한 전환 정보를 HGB에 넣으면 전환 시점의 최대값 오차가 줄어드는가?

예를 들어 100→200→100은 짧은 상승 후 복귀, 100→200→195→205는 높은 수준으로의 전환, 100→20→22→21은 낮은 수준으로의 전환이다. 숫자는 설명용이다. 사용자가 든 1980 같은 값도 실제 관측 여부·척도를 확인하기 전 데이터의 사실로 기입하지 않는다. 전력 기록의 물리 단위나 실제 설비 운전 상태는 현재 자료에서 확인되는 범위로만 해석한다.

기존 HGB의 주 예측 대상은 다음 한 시간의 네 15분 값 중 최대값이다. 이번 상태 분석에는 시간 평균을 함께 사용한다. 전체 예측오차가 작은 것과 전환 시작을 잘 찾는 것은 다른 성과이므로 각각 검증한다.

### 3. S01: 사건 정의를 먼저 확정

**자료와 관측 단위.** 정상 시각의 네 15분 기록으로 시간 평균과 최대값을 다시 대조한다. 정확히 연속된 시각만 연결하고, 누락·시간 오류·자료 시작과 끝은 경계로 처리한다. 20~26 구간만으로 모든 저전력·고전력을 규정하지 않는다. 같은 하루 배열의 반복과 0 구간도 보존하며 발생 횟수와 독립성의 해석에 반영한다.

**초기 정의 검토 범위.** 정의 후보의 사례와 의미는 먼저 1~3월에서 확인한다. 내부 검증을 2월부터 시작할 경우 수치 경계의 산정 자료는 정답 확인까지 끝난 1월 기록으로 제한한다. 1~3월 전체로 수치 경계를 산정해야 한다면 그 기간을 정의 개발에 사용한 것으로 표시하고 2~3월을 같은 정의의 순수한 시간순 성능 근거로 쓰지 않는다. 어느 경로를 택할지 S01에서 고정한다. 주 분석의 예측 성능을 보기 전에 사건 규칙을 확정하며 전체 기간 그림을 이미 봤으므로 새로운 독립 발견으로 표현하지 않는다.

**기준 수준과 전환 후보.** 최초 검토안은 직전 6시간 평균 전력의 중앙값을 기준 수준으로 삼고, 현재 시간 평균이 그 수준과 얼마나 달라졌는지 계산하는 것이다. 현재값과 직전값의 차이도 같이 보아 큰 변화가 시작되는 위치를 확인한다. 기준창의 IQR·기울기로 과거가 안정됐는지, 이미 상승·하락 중인지 구분한다. 초기부터 불안정한 기록을 삭제하지 않고 별도 조건으로 남긴다.

**변화 크기.** 절대 차이와 과거 변동폭에 대한 차이를 함께 확인한다. 작은 기준값이나 0 부근에서는 상대 변화율만으로 급등을 판정하지 않는다. 상승·하락의 분포가 다르면 각 방향의 기준을 따로 추정한다. 고정 93은 이전 최대값 급등의 정의이므로 새 평균 수준 전환에 그대로 적용하지 않는다.

**지속 여부.** 최초 검토안은 시작 시간부터 3시간을 주 확인창으로 두는 것이다. 첫 시간에 큰 변화가 발생하고 이후 두 시간도 과거 수준으로 복귀하지 않는지 확인한다. 복귀 판정에는 시작 순간에 고정한 기준 수준과 완화된 복귀 경계를 사용해 경계 근처의 작은 진동이 사건을 여러 번 만드는 것을 줄인다. 정확한 크기·복귀 경계는 1~3월 관측 진단을 거쳐 S01 계약에 명시한다. 1시간·6시간은 지속 정의의 민감도 표로 함께 보며 가장 좋은 모델 점수가 나오는 창을 선택하지 않는다.

주 정의를 정할 때 학습 기간의 변화량 분위수, 대표 사례의 전후 경로, 짧은 변동과 지속 구간의 구별 여부, 방향별·월별 사건 수를 함께 기록한다. 후보 규칙과 선택 이유를 남기고 한 개의 주 정의를 확정한다. 정의가 모호하면 S01에서 수정하며, 모델 평가 후 유리한 정의로 다시 바꾸지 않는다.

**사건과 상태의 구분.** 같은 방향의 높은 상태가 10시간 이어지면 시작 사건 1개와 지속시간 10시간으로 기록한다. 시작 사건을 정할 때 기준 수준은 고정하고, 복귀·반대 전환·큰 추가 전환이 나타날 때 구간을 종료하거나 새 사건으로 분리하는 규칙을 정한다. 상태 유지 시간과 새 전환 시작 시간을 별도 열로 관리한다. 단순히 직전 6시간 기준을 매번 바꾸어 같은 상승을 중복 집계하지 않는다.

사건 목록에는 시작 시각, 방향, 전환 전 기준 수준, 첫 시간 평균·최대값, 이후 수준, 관측 지속시간, 종료 이유, 미래 확인 가능 시각을 남긴다. 후속 창이 결측이나 자료 끝에 걸리면 지속 여부를 미확정으로 표시한다. 관측 종료 시점까지 유지된 사건은 잘린 지속시간으로 남겨 완결된 길이로 취급하지 않는다.

**초기 정답 구성.** 매 예측 대상 시간에 상승 후보 시작·하락 후보 시작·새 시작 없음으로 표시하고, 시작 사건은 짧은 복귀·3시간 지속·확인 불가로 세분한다. 각 집단의 수를 보고 단일 다중분류 또는 방향별 이진분류를 결정한다. '새 시작 없음'에는 이미 높은·낮은 수준이 유지되는 시간과 완만한 변동도 포함되므로 '안정 상태'와 같은 뜻으로 쓰지 않는다.

산출물은 정의와 수치 추정 기간을 기록한 계약, 전 시간 라벨표, 사건표, 방향·월·지속시간별 집계, 대표 사례 목록이다. 사례는 큰 전환·짧은 복귀·누락 경계·정의가 애매한 경우를 정해진 기준으로 확인한다. 시각화는 정의를 확인하는 데 필요한 소수 사례에 한정한다.

### 4. S02: 전환 전에 알 수 있는 조건 확인

S01 사건 시각을 t라고 할 때 t−1까지의 정보만 후보 입력으로 만든다.

- 달력: 목표 시각, 요일, 주말 여부, 월.
- 전력: 직전 수준, 1·2·3·6시간 변화, 최근 기울기·범위·변동폭, 직전 시간의 네 값 모양.
- 상태 이력: 과거만으로 확인한 현재 수준과 그 지속시간, 마지막 관측 전환 이후 경과시간, 결측 경계 여부.
- 생산량: 관측을 마친 과거 생산량·0 여부·변화. 목표 시간의 실제 생산량은 사후 해석에만 사용.
- 기존 HGB 예측: 필요하면 같은 시점에 생성 가능한 값으로 사용하고, 기존 예측만으로 설명되는 부분을 통제.

'현재 수준·지속시간' 입력은 전체 시계열을 사후 분할한 정답에서 가져오지 않는다. 과거 자료만으로 매시간 갱신한 상태를 사용한다. 실제 전환이 언제 확정되는지와 당시 입력이 무엇인지 저장해 대조한다.

전환과 비전환을 단순 전체 평균으로만 비교하지 않고, 같은 월·시간대·직전 전력 수준에서 비교한다. 상승·하락, 짧은 복귀·지속 전환을 구분하고 비교 가능한 표본 비율을 함께 표시한다. 같은 달력 조건의 사건 비율, 최근 기울기·변동폭·과거 상태 지속시간의 차이를 확인한다. 공통 조건이 부족하면 그 범위를 명시하며, 생산량·시간대의 연관을 원인으로 단정하지 않는다.

1~3월에서 단서를 정리하고 4~6월은 이후 모델 평가에 남긴다. 4~6월의 정답 기반 조건 분석이 추가로 필요해지면 개발 진단으로 명시하고 독립 검증으로 부르지 않는다. S02 결과는 모델 입력을 늘리는 목록이 아니라 어떤 단순 기준을 반드시 넘어야 하는지 정하는 근거로 사용한다.

### 5. 시간순 평가와 정답 확인 시점

랜덤 분할은 사용하지 않는다. 외부 개발은 1~3월 학습→4월, 1~4월→5월, 1~5월→6월의 순서로 비교하고 각 학습 기간 안에서 이전 월→다음 월 확장 검증을 사용한다. 모든 방법은 같은 입력 가용 시점과 평가 행을 공유한다.

지속 3시간 정답은 시작 이후 두 시간이 끝나야 알 수 있다. 따라서 분할 경계에서는 정답 확인창이 학습 종료를 넘어가는 행을 학습에서 제외한다. 향후 수준을 6시간으로 예측하는 비교라면 그만큼 더 긴 확인 지연을 적용한다. 경계 제거는 필요한 최소 기간으로 적용하고 제외 수·이유를 기록한다. 사건의 끝까지 보아야 하는 지속시간 정답은 아직 끝나지 않은 사건을 완결 사건처럼 사용하지 않는다.

스케일링·결측 대체·변수 선택·경고 경계·확률 보정·튜닝은 각 학습/내부 검증 안에서 수행한다. 정답 정의의 의미는 외부 월 사이에서 유지한다. 학습 기간의 통계를 다시 추정하는 입력 변환과 정답 사건의 정의를 구분한다.

HGB에 넣는 전환 확률은 학습 자료에서도 과거만으로 학습한 모델이 다음 구간에 낸 예측이어야 한다. 전환 모델이 자기 학습 행에 낸 확률을 바로 회귀 입력으로 쓰지 않는다. 내부 튜닝 단계에서도 그 내부 분할에 맞춰 확률을 생성하고 정답 확인 지연을 적용한다. 이렇게 만든 공통 학습 행으로 기본 HGB도 다시 맞춰 학습량 차이를 통제한다.

7~8월은 이미 여러 분석과 M05에서 확인한 자료다. S05를 실행해도 추가 독립 시험이라고 부르지 않는다. 6월 말까지 조건을 고정하고 한 번 후속 확인하는 용도로 사용하며 결과를 보고 같은 기간에 맞춰 재튜닝하지 않는다.

### 6. S03: 양방향 전환 시작과 지속 예측

예측 시점은 t−1 관측 완료 직후이며, 주 목표는 t에 시작하는 상승·하락 전환이다. 지속 여부는 같은 시점에 함께 예측한다. 주 확인창을 3시간으로 확정했다면 '다음 시간에 시작하고 3시간 이어질 전환'의 확률을 내도록 한다. 전환이 발생한 뒤 빨리 알아채는 현재 상태 탐지는 사전 예측과 별도 성과로 표시한다.

**단순 기준.** 항상 새 전환 없음, 과거 학습에서 추정한 달력별 발생률, 직전 기울기·최근 범위로 만든 단순 규칙을 둔다. 조건부 발생률의 표본이 적으면 학습 안에서 더 넓은 조건으로 합치는 규칙을 고정한다. 기존 HGB가 예측한 최대값 변화는 보조 기준으로 남기되, 평균 수준 전환과 목표가 다름을 명시한다.

**첫 모델 비교.** 표준화 Logistic과 HGB 분류기를 우선 비교한다. 둘 모두 동일 입력·분할·사건 정의를 사용한다. 방향·지속별 사건 수가 충분하면 하나의 다중분류를, 부족하면 상승·하락을 나눈 이진분류와 지속 여부의 조건부 분석을 사용한다. 전체 사건 수뿐 아니라 서로 다른 날짜·반복 배열을 확인해 학습 가능성을 판단한다.

튜닝은 Optuna로 모델·외부 월당 최대 20회부터 시작한다. 최적화 목표는 방향별 희소 사건의 AP를 균형 있게 반영하도록 학습 전에 정한다. 특정 내부 검증에 사건이 없으면 AP를 0이나 좋은 점수로 임의 처리하지 않고 사건 수·정의 불가 상태를 남긴다. 학습 가능한 분할만 비교 가능한지 점검하고, 사건이 지나치게 적으면 모델 수나 튜닝을 늘리지 않고 단순 기준·사례 분석으로 그 분기를 종료한다.

**평가 단위.** 사건마다 시작을 한 번 맞히는 것이 핵심이다. 주 평가는 다음 시간의 정확한 시작 시점에 맞춘 방향별 TP·FP·FN, 정밀도·재현율이다. 100시간당 오경보와 날짜당 경고 수도 제시한다. 긴 고전력 구간 안에서 반복 경고한 횟수를 여러 적중으로 세지 않는다. 연속 경고를 한 묶음으로 취급하는 보조 평가는 묶는 규칙과 일대일 사건 대응을 먼저 고정한다.

AP는 확률 순위 비교에 사용하고 실사용 경계에서의 탐지와 구분한다. 경계는 내부 검증에서 정한 동일 오경보 부담으로 비교한다. 평가 기간의 정답을 보고 각 모델의 경계를 맞추지 않으며 실제 외부 오경보 수가 달라지면 그대로 보고한다. 시작 후에 잡은 경우의 지연시간도 따로 집계한다. 필요시 ±1시간 허용 결과를 보조로 제시하되 사전 예측과 늦은 탐지를 합쳐 성과를 부풀리지 않는다.

지속 여부는 사건을 실제로 찾은 경우만 골라 평가하지 않는다. 지속 상승·지속 하락의 전체 사건에 대해 시작과 지속을 함께 맞힌 비율을 주 결과로 두고, 시작을 맞힌 사건 안의 지속 분류는 보조로 제시한다. 첫 단계에서 정확한 종료 시각까지 예측하려고 범위를 넓히지 않는다.

### 7. S04: 전환 정보를 HGB에 연결

먼저 다음 세 구성을 같은 시간·같은 학습 행으로 비교한다.

| 구성 | 입력과 역할 | 분리해서 확인할 효과 |
|---|---|---|
| B0 | 기존 B 입력의 HGB | 공통 표본에서의 기준 성능 |
| B1 | B 입력 + S02에서 선택한 과거 상태·변화 변수 | 과거 정보를 추가한 효과 |
| B2 | B1 + 과거만으로 생성한 상승·하락·지속 확률 | 전환 확률 자체의 추가 기여 |

첫 결합 비교에서는 HGB 설정을 고정해 입력 효과를 분리한다. B2가 도움이 되면 동일 내부 검증과 동일 Optuna 예산으로 B0~B2를 함께 조정하는 후속 비교를 검토한다. 새 변수와 튜닝 이득을 섞어 전환 모델의 효과라고 설명하지 않는다.

핵심 평가는 상승·하락 시작 사건의 최대값 MAE, 상승 시 과소예측, 하락 시 과대예측이다. 지속 전환 이후 첫 3시간 오차와 평상시 전체 MAE·RMSE·편향도 함께 본다. 지속시간이 긴 사건 하나가 평가를 지배하지 않도록 사건별 평균 후 사건 균등 요약과 시간별 요약을 같이 제시한다. 실제 최대 시간 성능도 기존 기준과 연결해 보조로 보존한다.

사용자가 말한 전력의 '박스권'은 후속 전력 수준과 변동 범위로 구체화한다. 우선 평균 수준의 예측을 별도 보조 출력으로 검토하고, 범위가 필요하면 사전 고정한 예측 구간을 비교한다. 예측 구간은 포함률과 폭을 함께 평가해야 하며 점 예측 MAE 개선으로 범위 예측 성공을 대신하지 않는다. 실제 미래 전환 상태를 알려준 성능은 한계 진단에만 사용할 수 있고 제출 모델의 성능으로 보고하지 않는다.

전문가 모델을 상태별로 나누어 확률 가중 결합하는 방식은 B2의 실패 원인이 상태별 값 예측 차이에 있다는 근거가 있을 때만 후속 후보로 검토한다. 처음부터 회귀·분류·전문가·앙상블을 모두 탐색하지 않는다.

### 8. 성과 판단, 계획 변경과 중단 기준

완벽한 전환 예측이나 모든 달의 동시 개선을 필수로 요구하지 않는다. 대신 다음 중 실제로 확인된 기여를 정확한 범위로 채택한다.

- 상승 전환만 유용하다면 상승에 대한 성과로 한정한다. 급락까지 잘 맞힌다고 확대하지 않는다.
- 지속 전환에서 유용하고 짧은 변동에서는 약하면 지속 전환을 적용 대상으로 둔다.
- 전환 시작 탐지가 개선됐으나 HGB 오차 개선이 없으면 탐지 성과와 값 예측 성과를 구분한다.
- B2가 B0보다 좋지만 B1보다 좋지 않으면 전환 확률의 독자적 기여는 확인되지 않은 것으로 판단한다.
- 사건 몇 건이나 특정 반복 배열에만 이득이 집중되면 원자료 사례와 월별·배열별 결과로 적용 범위를 좁힌다.

S01 사건 수와 S02 단순 기준을 확인한 뒤 S03 학습 전에 최소 사건 수·허용 경고 부담·실용적 개선 크기를 숫자로 계약에 남긴다. S04도 공통 표본의 기준 오차를 확인한 뒤 실행 전에 전환 오차 개선과 평상시 악화 허용 범위를 정한다. 이 숫자는 결과를 본 뒤 통과시키기 위해 완화하지 않는다. 운영 비용이 자료에 없으므로 비용 절감 목표를 임의로 만들지 않는다.

부정적 결과는 원인을 좁힐 구체적인 단서가 있을 때 한 번의 최소 변경으로 연결한다. 예를 들어 탐지 순위는 좋지만 경계가 흔들리면 과거 자료 안의 경계 선택을, 탐지는 맞지만 값이 틀리면 회귀 결합을 검토한다. 새 단서가 없거나 같은 방식의 실패가 반복되면 해당 분기를 종료한다. 종료는 목표를 오류 검토 우선순위로 바꾸어 달성했다고 선언하는 것이 아니다.

현재 원고 4.11과 과거 실행 결과는 보조 기록으로 보존한다. 이번 계획 작성에서는 원고·압축본을 수정하지 않는다. 즉시 다음 작업은 S01의 원자료·정의 후보 진단과 S02의 선행 조건 분석이며, 완료 뒤 사건 수와 기준 성능을 근거로 S03 실행 조건을 확정한다.

## 하루 2회 검토 우선순위: 개발 성과 반영

사용자가 완벽한 월별 성과보다 보고서에 쓸 수 있는 실용적 기여를 검토하도록 요청해, 자동 경고와 별도로 하루 2회 검토 우선순위를 평가했다. 매시간 이전 월 점수·남은 횟수·시간만 사용하는 규칙을 먼저 고정했다. 4 ~ 6월 91일간 각 방법이 똑같이 182시간을 선택했으며 보조 모델은 큰 과소예측 27건, 가장 좋은 단순 기준은 20건을 선별했다. 7건·35.0% 증가로 사전의 최소 5건·20% 개선과 2개월 이상 개선 조건을 통과했다.

제한된 개발 성과로 [상세 원고 4.11](04_Modeling_원고.md#411-하루-2회-검토를-위한-과소예측-우선순위)에 반영했다. 보조 모델의 월별 적중은 7·6·14건이며 가장 좋은 단순 점수는 6·8·6건이다. 5월 열세, 전체 184건 중 157건 미선택, 주별 재표집의 증가 범위 −6 ~ 19건도 함께 남겼다. 35%는 이 개발 조건의 관측 개선률이고 새 독립 시험이나 자동 경고 채택을 뜻하지 않는다. 이 절이 아래 과거 실험의 다음 작업 안내에 우선한다.

부모 error_warning 코드·모델·점수는 아래 절과 원고 코드표에 모두 연결했다. 새 학습·튜닝은 0회이며 반복 실행으로 유리한 규칙을 고르지 않았다. 기존 자동 경고 후보의 미채택 판정과 M05를 유지하고 압축본은 변경하지 않았다. 보고서에서는 예측오류 점수와 제한된 확인 횟수를 연결한 보조 활용으로 기술하며 일반적인 성능 우위나 실제 절감 효과를 주장하지 않는다. 이 비교는 종료하고, 동일 개발 기간에서 수치를 더 높이기 위한 규칙 탐색은 확대하지 않는다.

## 과소예측 위험 경고 비교 결과

### 이전 근거와 이번 질문

새 가설은 ‘직전 마지막 값이 같아도 앞선 부하의 모양과 지속시간이 다르면 다음 시간의 크기·모양이 다를 수 있다’다. 검증할 방법은 **과거 네 구간의 순서와 관측 이력을 이용해 다음 시간의 네 값을 예측하고, 그 예측값의 최대를 계산하는 방식**이다. 기존 최대값 직접 예측과 비교하여 실제 이득이 있을 때만 채택한다. 네 값을 예측한다는 사실 자체를 필살기로 쓰지 않는다. 급등 탐지는 별도 목표이며 최대 시간 오차 개선과 혼동하지 않는다.

### P01. EDA: 높은 전력이 어떤 모양으로 나타나는가

이전 근거는 EDA 2.5의 시간대별 네 구간 차이와 EDA 2.2·Analysis 3.1의 낮은 전력 지속·단일 0 구간이다. 기존 결과표로 답할 수 있는 내용은 재계산하지 않는다. 기존 월별 전력선·생산량·날씨 분석도 유지한다.

- 같은 시간 안에서 최댓값이 나타난 구간, 동률 개수, 최대−평균 차이, 네 값의 범위와 순서를 확인한다. 한 구간만 높은 경우와 여러 구간이 함께 높은 경우를 연속적인 수치부터 비교한다.
- 관측된 낮은 상태와 높은 기록이 얼마나 이어지는지 월·시간대별로 집계한다. 실제 일별 최대, 절대적으로 높은 기록, 직전 시간 대비 급등을 서로 다른 대상으로 표시한다. 낮은 날의 상대적 최대를 큰 부하로 과장하지 않는다.
- 기술 EDA는 기존 정상 1 ~ 8월 전체 범위를 유지한다. 예측에 사용할 고전력 경계나 형태 구분이 필요하면 P02의 각 학습 자료 안에서 별도로 산정한다. 전체 자료에서 본 구분을 예측 규칙으로 그대로 옮기지 않는다.
- 정확히 반복되는 하루 배열과 새 배열, 날짜 수·연속 구간 수를 함께 표시한다. 네 기록을 네 개의 독립 사례로 세지 않는다. 시각 표기의 불확실성은 유지하며 네 열의 순서를 임의의 정확한 운영 시각으로 해석하지 않는다.

산출물은 기존 `EDA/tables` 아래의 형태·지속시간 표와 EDA 상세 원고의 관련 절 보완이다. 그림은 표만으로 설명하기 어려운 경우에만 기존 그림 규칙에 맞춰 추가한다. **형태 차이가 작으면 네 구간 출력 분기의 우선순위를 낮추고, 차이가 있으면 그 차이를 과거 정보로 구분할 수 있는지 P02로 연결한다.** 기록 형태만으로 예측 가능성을 결론내리지 않는다.

### P02. Analysis: 관측 이력이 다음 전력을 구분하는가

현재 B는 직전·두 시간 전의 대표값과 직전 마지막 값에 주로 의존한다. 기존 C의 24·168시간 전 대표값과 달리, 이번에는 최근 시간의 연속된 네 값 및 상태가 이어진 길이를 확인한다. 이미 비교한 직전 한 시간의 기울기·범위 입력만 다시 시험하지 않는다.

| 입력 묶음 | 확인할 정보 | 비교 목적 |
|---|---|---|
| 기준 B | 기존 18개 입력 | 강한 비교 상대 유지 |
| 네 구간 모양 | B + 직전 두 시간의 순서 있는 네 값 | 대표값으로 요약하면서 빠진 정보 확인 |
| 짧은 이력 | B + 최근 6시간의 네 값·과거 상태 지속시간 | 잠깐 낮아진 경우와 이어진 낮은 상태 구분 |
| 긴 이력 | B + 최근 24시간의 네 값·과거 상태 지속시간 | 전날부터 이어진 흐름의 추가 가치 확인 |

지속시간은 예측 시점 직전까지 관측한 길이다. 미래에 언제 끝났는지, 그날 전체가 어떤 유형이었는지 입력하지 않는다. 자료 시작·결측으로 앞부분을 모르면 그 경계를 표시하며, 결측을 건너뛰어 연속 구간으로 연결하지 않는다. 시간 시차는 행 순서가 아닌 실제 시간으로 연결한다.

같은 시간대·직전 전력 수준에서도 이력에 따라 다음 최대값·형태가 달라지는지 표로 확인한다. 집단별 차이는 연관 근거이고, 추가 예측력은 별도의 비교로 확인한다. P01에서 정보가 있는 묶음만 고정 HGB의 제한된 비교로 시험한다. 최대 세 추가 묶음이며 먼저 대규모 Optuna를 돌리지 않는다. 선택 규칙과 동률 처리·입력 목록은 학습 전에 고정하고, 이력 묶음의 선택은 각 외부 학습 기간 안의 시간순 내부 검증에서 수행한다. 4 ~ 6월 결과를 본 뒤 임의의 길이를 계속 추가하지 않는다.

산출물은 `Analysis/tables` 아래의 조건별 표·관측 시점 검사와 기존 Analysis 상세 원고의 보완이다. 예측 비교 코드는 `Modeling/scripts`에서 관리하고 서로 링크한다. **이력이 다음 값을 구분하지 못하고 제한된 예측 비교에서도 이득이 없으면 이 분기를 종료한다.** 동일 배열의 재등장에서만 효과가 나면 새로운 패턴에 적용 가능한 개선으로 주장하지 않는다.

### P03. Modeling: 입력 효과와 출력 설계 효과를 나눠 비교

P01·P02의 결과를 보고 아래 비교의 실행 여부를 확정한다. 두 방향 모두 근거가 있으면 같은 HGB 설정으로 네 조합을 비교한다.

| 비교 | 입력 | 예측 목표와 최종 출력 |
|---|---|---|
| 기준 | 기존 B | 다음 시간 최대값 직접 예측 |
| 입력만 변경 | B + 선택한 모양·이력 | 다음 시간 최대값 직접 예측 |
| 출력만 변경 | 기존 B | 다음 시간 네 값을 각각 예측한 뒤 그중 최대 |
| 입력·출력 변경 | B + 선택한 모양·이력 | 다음 시간 네 값을 각각 예측한 뒤 그중 최대 |

각 구간별 HGB 네 개로 시작해 모델 계열 변경을 섞지 않는다. 네 값 모두 같은 예측 시점에 한꺼번에 예측한다. 첫 구간의 실제 정답을 받은 뒤 다음 구간을 예측하는 더 쉬운 문제로 바꾸지 않는다. 네 예측의 최대가 최대값 직접 예측보다 좋다는 보장은 없으므로, 같은 시간의 실제 최대에 대한 오차로 판정한다.

입력만 효과가 있으면 최대 직접 예측을 유지하고, 출력만 효과가 있으면 불필요한 이력을 제외한다. 둘 다 효과가 없으면 이 비교를 종료한다. 고정 설정에서 근거가 생겼을 때만 후속 Optuna를 계획한다. 그 경우 기준·후보에 동일한 내부 시간순 검증과 예산을 적용하고, 검색 범위·trial 수·중단 조건을 실행 전에 기록한다. 알고리즘 종류 확대·딥러닝·앙상블 추가는 자동 후속으로 삼지 않는다.

### P04. 같은 조건에서 성과와 실패를 확인

- 개발 외부 평가: 1 ~ 3월 학습→4월, 1 ~ 4월→5월, 1 ~ 5월→6월. 각 월의 모든 적격 시간을 평가하며 랜덤 분할하지 않는다. 내부 선택도 각 외부 학습 구간 안에서 월 단위 확장 검증을 사용한다.
- 긴 이력 때문에 적격 행이 줄면 기준·후보 모두 같은 학습 행과 평가 행으로 맞춘다. 제외 수와 이유를 기록하고, 기존 전체 표본 점수와 새로운 공통 표본 점수를 직접 비교하지 않는다. 입력·설정·학습 행이 같을 때만 저장 모델과 예측을 재사용한다.
- 주요 지표는 전체 MAE, 실제 일별 최대 시간 MAE, 최대 시간의 평균 과소·과대예측이다. 최대 동률은 기존 날짜 균등 가중을 유지한다. 전체 RMSE·월별·반복/새 배열·낮은 유지·상승 및 급등 오차와 표본 수도 함께 기록한다.
- 최대 예측의 채택 목표는 이전 회차의 최대 시간 MAE·과소예측 5% 이상 개선, 전체 MAE 1% 이내 악화, 월별 악화 5% 이내 및 과대예측 허용폭을 유지한다. 기존 A와 B를 새 공통 표본에 맞춰 비교한다. 날짜 하나에 개선이 집중되는지도 확인한다. 수치 기준은 통계적 유의성이나 절감액을 뜻하지 않는다.
- 네 구간 MAE·최대 구간 위치의 일치율은 출력 설계의 보조 지표다. 동률 처리와 기준 모형을 미리 정한다. 이 보조 지표만 좋아졌다고 기존 최대 예측의 채택 실패를 성공으로 바꾸지 않는다.
- 개발에서 고정한 후보가 있을 때만 1 ~ 6월 한 번 학습→7 ~ 8월 고정 재평가를 수행한다. 기존 M05를 보존한다. 4 ~ 6월은 반복 사용한 개발 자료이고 7 ~ 8월도 이미 확인한 자료이므로 새 독립 시험으로 표현하지 않는다. 후반기 결과를 보며 후보·임계값을 다시 고르지 않는다.

시기별 관계 변화가 P02와 기존 오류표에서 확인되면, 최근 기간 학습·주기적 갱신을 별도 가설로 계획할 수 있다. 이때 고정 모델과 적응 모델을 서로 다른 운영 조건으로 명시하고 정보 시점을 다시 검사한다. 고전력 경보·검사 우선순위는 예측 출력에 근거가 생겼을 때 별도 평가한다. 사후에 하루 전체 점수를 보고 상위 시간을 뽑는 방식은 실시간 조기 경보 성과로 사용하지 않는다.

### P05. 원고와 재현 자료에 연결

EDA는 관측 형태와 지속시간, Analysis는 과거 이력의 정보와 조건부 차이, Modeling은 같은 조건의 성능·기여·실패 분석을 맡는다. 최종 보고서에서는 제1장에 필요한 관측 근거, 제2장에 최종 비교와 선택 이유, 제3장에 줄어든 오류와 남은 실패, 제4장에 예측 시점과 담당자의 판단·조치, 제5장에 검증된 차별성, 제6장에 전체 재현 절차를 연결한다.

새 결과는 기존 상세 원고에 연결하고 계산·학습·검증·그림 생성 Python 코드와 담당 함수를 빠짐없이 적는다. 설정·입력 해시·동일 시각 예측·지표·채택/기각 이유를 저장하고 제출 보존 목록도 갱신한다. 상세 원고·과거 실패 실험·원본은 보존한다. 최종 압축은 별도 단계이며 선택 모델의 중요한 실패조건은 짧게라도 남긴다. 현재 자료에서 식별되지 않는 운영 원인·단위는 미식별로 명시하며 실측하지 않은 비용·전력 절감을 성과로 쓰지 않는다.

**계획 당시 첫 작업은 P01이었다. 현재는 위 실행 결과의 종료 판단을 따른다.** EDA 2.5와 관련 기존 결과표를 먼저 대조한 뒤, 없는 항목인 최대 구간·동률·최대−평균 차이·연속 형태를 최소 집계한다. 결과를 보고 P02의 입력 묶음을 확정한다. 각 회차 끝에 이전 근거→이번 질문→핵심 결과→유지/수정 판단→다음 최소 작업을 남기며, 계획 변경의 이유와 시점을 기록한다. 차별성이 없으면 해당 가설을 종료하고, 새로운 관측 근거가 생긴 경우에만 다음 비교를 연다.

## 이전 재개발 계획과 실행 결과: R01 ~ R04

상태: R01·R02·R03 및 결과에 따른 R03b 추가 비교를 실행·독립 검증했다. 새 적격 후보가 없어 R04 후반기 재평가는 생략했다. 결과와 전체 코드 설명은 원고 4.10에 반영했다. 현재 다음 작업은 문서 맨 위 P01 ~ P05 계획을 따른다. 상세 원고와 M01~M05 결과·코드·모델은 보존한다. 이번 목표는 전체 정확도를 유지하면서 중요한 최대 시간의 오차와 과소예측을 줄이는 방법을 찾고, 어떤 정보와 설계가 개선에 기여했는지 설명하는 것이다. 급등 탐지는 별도 성과로 평가한다.

### 최우선 목표: 차별성의 입증

사용자는 필살기의 명확한 입증을 프로젝트의 핵심 목표로 요구했다. HGB가 단순 기준보다 좋다는 사실만으로 이 목표를 달성했다고 판단하지 않는다. 제안한 입력·예측 설계를 제거한 비교 상대와 같은 조건에서 평가해, 중요한 최대 시간의 오차·과소예측을 얼마나 줄였는지 보여줘야 한다.

최종 근거는 ① 기존 강한 모델 대비 개선표 ② 제안 요소를 넣고 뺀 기여 비교 ③ 전체·최대 시간·월별 성과와 남은 실패조건 ④ 개선 사례와 실패 사례를 같은 방식으로 선택한 시계열 그림으로 구성한다. 대표 사례만으로 전체 성과를 대신하지 않는다. 이 근거가 충족되기 전에는 차별성을 입증했다고 쓰지 않는다. 성과를 보장할 수는 없으므로, 기대한 개선이 없으면 원인과 새로 확인할 수 있는 가설을 판단한다.

회차의 종료는 프로젝트 목표의 달성과 구분한다. 후보가 모두 미달이면 해당 비교를 종료하고 차별성 목표는 미해결로 남긴다. 새 근거가 있는 다음 설계는 검토하되, 같은 시도를 반복하거나 평가 기준을 완화해 성공을 만들지 않는다.

### 현재 실행 결과와 남은 질문

[재개발 상세 원고 4.10](04_Modeling_원고.md#410-후반기-오류를-반영한-예측-설계-재개발)과 [실행 기록](10.05_R01_R04_차별성재개발_실행기록.md)에 결과를 연결했다. R01은 3,528개 A/B 예측쌍과 원자료 시차를 대조했다. R02는 Optuna 360회·새 학습 1,095회로 네 모델×입력 조합의 고정 및 재튜닝을 비교했고 기존 HGB B의 균형이 가장 좋았다. R03은 같은 HGB B의 목표만 변화량으로 바꿔 3회 학습했으나 최대 시간 MAE가 7.589→8.953으로 악화했다.

이 결과에 따라 R03b를 추가했다. 모델·입력·설정을 고정하고 과거 학습 자료의 실제 일별 최대 시간 비중만 바꿨다. 새 계약에 가중 7개와 내부 선택 기준을 먼저 정했고, 새 Optuna 없이 75회 학습·21개 내부 설정 비교를 했다. 4·5월은 가중 1, 6월은 1.5가 선택됐다. 최대 시간 MAE 7.589→7.551의 0.5% 개선은 사전 5% 목표에 미달했다. 저장 모델 3개를 독립 가중으로 재학습해 예측을 대조했다.

이번 비교에는 새 채택 후보가 없으며 차별성 목표는 미해결이다. 기존 M05 판정은 그대로 유지하고 7~8월 후보 탐색은 하지 않았다. 사용한 전체 Python 코드는 41개로 늘었으며 원고 4.5·4.10과 제출 보존 목록에 연결했다. 상세 원고는 보존했고 최종 압축·삭제·현장 적용은 하지 않았다.

당시 남긴 미해결 질문은 '같은 직전 상태에서도 시기가 바뀌면 다음 전력과 과소예측의 관계가 달라지는가, 아니면 학습에서 드문 전력 상태가 후반기에 늘었는가'다. 근거는 R01의 above26 최대 시간 오차와 직전 상승 조건에서 개발 개선이 후반기 악화로 바뀐 점이다. 최소 후속은 각 외부 학습 자료로 정한 입력 범위·분포와 평가 입력을 비교하고, 기존 예측의 범위 안/밖·월별·전력 수준별 오차를 분리하는 것이다. 이를 확인한 뒤 학습 기간 변경을 시험할 근거가 있는지 판단한다. 이 후속 진단과 학습 기간 변경은 아직 실행하지 않았다. 같은 Optuna·입력·가중 탐색은 이번 결과를 근거로 종료한다.

### 출발 근거와 해결할 질문

- M03 개발에서 A→B의 전체 MAE는 8.1%, 실제 일별 최대 시간 MAE는 35.4% 감소했다. M05에서는 전체 개선이 0.92%로 줄고 최대 시간 MAE는 3.19% 악화했다. 마지막 값의 효과가 약해진 조건을 먼저 확인한다.
- M02의 A 입력 비교에서는 HGB의 전체/최대 시간 MAE가 6.738/11.751, ExtraTrees가 6.825/11.540이었다. A로 선택한 HGB에 B를 적용했으므로, B 입력에서도 HGB가 가장 적합한지는 미확인이다.
- M05 급등 6건에서 G의 탐지는 3→4건, 오경보는 16→14건으로 개선됐지만 8월 탐지는 2→1건으로 감소했다. 8월 9일은 B/G 점수가 같고 경보 경계가 달라 G만 놓쳤다. 예측값·점수의 문제와 경보 경계의 문제를 구분한다.
- 이미 비교한 직전 시간 기울기·범위·변화량, 상승 가중 전문가, 전체 상태 분류, Q90을 새 근거 없이 반복하지 않는다.

R02의 고정 비교는 각 모델의 기존 A 선택 설정을 그대로 A/B에 적용한다. 설정·학습 행·입력 해시가 일치하면 저장 예측을 재사용한다. 재튜닝 비교는 각 모델×입력×외부 월에 Optuna 30회, seed 42, 같은 내부 월과 기존 모델별 검색 범위를 사용한다. 4조합×3외부 월로 최대 360회이며 반복 실행·학습 횟수와 trial 수는 따로 기록한다. 기존 결과와 동등한 실행을 재사용할 경우 예산 차이를 명시한다. 결과를 보고 예산을 임의로 연장하지 않는다.

R03은 R02에서 선택한 한 모델과 B 입력만 대상으로 한다. 고정 설정으로 목표의 효과를 먼저 분리하고, 새 대규모 튜닝은 자동 실행하지 않는다. 학습 목표는 학습 행에서만 만들고 추론 시점에는 미래 전력을 사용하지 않는다. 출력 음수 처리 등도 직접 예측과 같은 규칙을 실행 전에 정한다.

### 평가 설계

- 주 목표·정보 시점·common 표본은 M01을 유지한다. 다음 시간의 네 전력값 중 최대를 예측하며, t−1 관측이 끝난 뒤 이용 가능한 입력만 사용한다. 실제 미래 생산량·날씨·최대 여부를 입력하지 않는다.
- 외부 개발 비교는 1~3월→4월, 1~4월→5월, 1~5월→6월이다. 해당 월의 모든 적격 시간을 평가한다. 매시간 관측 입력은 갱신하지만 모델은 평가 월 안에서 고정한다.
- 각 외부 학습 구간 안에서 1월→2월부터 월 단위 확장 검증으로 튜닝한다. 랜덤 분할을 하지 않는다. 전처리·새 조건 경계·튜닝은 해당 학습 구간 안에서 정한다.
- 4~6월 역시 이미 여러 비교에 사용한 개발 기간이다. 시간순 검증이 시간 누출을 줄여도 반복 선택 이력이 사라지지는 않는다. 7~8월은 이번 가설 형성에 사용한 후반기 자료다. 현재 자료에서 새 독립 시험을 확보했다고 주장하지 않는다.
- 후보 선택은 4~6월 내부·외부 결과를 바탕으로 고정하고, 7~8월 수치를 보고 후보·경계·예산을 바꾸지 않는다. 후반기 결과는 이전 M05와 별도 버전으로 기록한다.
- 월별 재학습·최근 기간만 학습·새 손실함수·다중 전문가 확대는 이번 기본 비교에 섞지 않는다. 현재 회차의 결과가 구체적인 새 질문을 만들 때만 별도 계획으로 검토한다.

### 무엇을 좋아졌다고 판단할 것인가

전체 MAE와 실제 일별 최대 시간 MAE를 주 비교 지표로 유지한다. 최대 시간의 평균 과소예측과 평균 과대예측, 월별 오차, 반복/새 배열, 급등 및 낮은 유지 구간의 오차를 함께 저장한다. 하루 최대가 여러 시간이면 기존 날짜 균등 가중을 유지한다. 실제 최대 전력 크기와 표본 수도 병기한다.

튜닝은 기존 M02의 두 MAE와 직전 기준 대비 상대오차의 최댓값을 이용한 선택 방식을 따른다. 재튜닝으로 좋아진 성과를 순수한 입력 추가 효과로 쓰지 않고, 고정 설정 비교를 별도로 제시한다.

새 회차의 개발 채택 기준안은 다음과 같다. R01 후 학습 시작 전에 계약 파일에 확정하며, 수치를 바꾸면 사유와 시점을 남긴다. 기존 M05의 기준·합격 여부는 수정하지 않는다.

| 항목 | 새 회차의 개발 채택 기준안 |
|---|---|
| 비교 상대 | 기존 HGB A와 B를 모두 표시한다. 입력의 효과는 같은 모델의 A/B로도 확인한다. |
| 핵심 개선 | 후보의 일별 최대 시간 MAE와 평균 과소예측이 기존 A와 B 각각보다 5% 이상 감소한다. |
| 전체 오차 | 전체 MAE가 기존 A와 B 각각의 1.01배 이내다. |
| 과대예측 | 최대 시간 평균 과대예측의 증가량이 각 기준의 최대 시간 MAE의 5%를 넘지 않는다. 기준 과대예측이 작은 경우의 비율 폭증을 피하려는 원자료 척도의 허용폭이다. |
| 월별 안정성 | 각 월의 전체 MAE와 최대 시간 MAE가 기존 B보다 5% 넘게 악화되지 않는다. 월별 절대 차이도 공개한다. |
| 의존성 진단 | 날짜별 오차 차이, 반복/새 배열, 개선 기여 상위 날짜를 확인한다. 한 날짜를 하나씩 제외했을 때 개선 방향이 뒤집히면 안정적 효과 주장을 보류한다. 평가 행을 실제로 삭제해 점수를 높이지 않는다. |

1%·5%는 이번 비교에서 사용할 수치 허용폭·개선 목표의 제안이며 통계적 유의성이나 경제적 손익 기준이 아니다. 요건을 통과한 후보 중 전체·최대 시간의 기준 대비 상대오차 최댓값이 작은 방법을 선택하고, 동률이면 추가 단계가 적은 방법을 우선한다. 기준 미달 후보도 비교표에는 남긴다. 모두 미달이면 새 최종 후보가 없다고 기록한다.

급등은 기존 증가량 93 이상 정의를 유지하고 건수·사례 날짜·MAE·과소예측을 함께 본다. 경보 채널을 제안할 경우에는 과거 내부 예측에서만 경계를 정하고 AP, TP/FP/FN, 재현율·정밀도·실제 오경보율을 모두 비교한다. 급등 6건 중 한 건의 개선을 안정적 일반 성과로 확대하지 않는다. 61.6 기준이나 다른 허용률은 보조 민감도이며 주 기준 실패를 성공으로 바꾸는 데 쓰지 않는다.

### 변경·중단·기록 원칙

각 회차는 이전 근거 → 질문 → 실행 전 조건 → 결과 → 해석 변경 → 다음 작업 또는 종료 이유를 남긴다. 개선이 충분하면 조건부 R03을 생략할 수 있다. R01이 다른 원인을 시사하면 R02의 우선순위를 조정하되, 실행 전에 변경 범위와 이유를 기록한다. 새 근거가 없거나 R02·조건부 R03에서 개선이 없으면 같은 탐색을 확대하지 않고 종료한다.

산출물은 회차별 조건 JSON, 사용 코드, 원본·부모 산출물 해시, 같은 시각의 후보별 예측, 비교표, 날짜별 오류, 선택·기각 사유, 독립 검증 기록으로 구성한다. 새 경로는 실행 전에 정하고 기존 m03/m04/m05 결과를 덮어쓰지 않는다. 새 코드가 생기면 상세 원고의 코드 목록과 제출 보존 목록에 함께 연결한다.

현재 상세 원고 4.1~4.9는 유지한다. 재분석이 끝나면 최종 방법을 선택한 이유가 이어지도록 해당 절을 개편하고, 미채택 실험의 자세한 내용은 재현 근거로 보존한다. 최종 결과가 뒷받침하는 범위 안에서 차별성을 표현하며, 실제로 측정하지 않은 전력·비용 절감을 성과로 적지 않는다.

## 1. 해결할 문제

### 제출 코드와 정리 전 보존 목록

[상세 원고 4.5](04_Modeling_원고.md)에 사용한 Python 코드 41개를 파일별 역할·주요 함수·실행 순서와 함께 모두 연결했다. 직접 실행하는 코드뿐 아니라 import하는 공통 모듈, 독립 검증, 그림 생성, 문서 생성·검증, 환경 점검 코드까지 포함한다. 코드의 전체 소스는 링크된 `.py` 파일을 같은 상대 폴더 구조로 보존한다.

[보존 목록](submission_manifest.json)은 원자료·설정·결과·모델·그림·직접 참고 파일의 경로·크기·해시와 Python 내부 import 관계를 기록한다. [requirements.txt](requirements.txt)는 현재 정규 Python 3.13의 직접 사용 라이브러리 버전이다. 이 목록은 Modeling 범위이며 EDA·Analysis 전체의 삭제 기준은 아니다. 원고에 직접 링크가 없는 결과 파일도 부모 해시·모델 재사용·독립 검증에 필요하므로 보존한다.

파일 정리 전 [modeling_submission_audit.py](scripts/modeling_submission_audit.py)를 `--verify`로 실행한다. 의도적인 수정 후에는 결과·문서를 확인한 다음 `--record`로 목록을 갱신한다. 두 명령은 삭제·학습을 하지 않는다. Codex 실행은 루트 AGENTS.md의 최초 승격 Start-Process 경로를 따르며, 구체적인 명령과 전체 실행 순서는 원고 4.5에 있다. 최종 제출과 새로운 환경의 전체 재학습은 아직 수행하지 않았다.

**관측을 마친 직전 시간의 정보로 다음 한 시간의 최대전력을 예측하고, 실제 최대전력이 높은 시간의 과소예측을 줄일 수 있는가?**

주 예측 대상은 다음 시간의 네 15분 전력값 중 최댓값이다. 과거 평균·최대에 마지막 15분 값을 추가하는 방법을 핵심 비교로 삼는다. 전력 수준 예측과의 연결을 위해 시간 평균도 보조 목표로 평가하는 것을 계획한다. 두 목표의 성과는 별도로 보고하며, 실제 미래 평균을 알고 최대값을 복원하지 않는다.

최대전력은 연속값으로 예측한다. M04에서는 학습 자료의 증가량 경계93을 별도 급등 평가·위험 출력에 사용하며, 주 목표인 연속값 예측과 구분한다. 생산량 0→양수 전환을 전력 급등으로 대신하지 않는다. 예측값의 단위는 원자료 척도로 유지하며 kW·kWh·전기요금 절감으로 임의 환산하지 않는다.

### 필살기의 정의와 이 Modeling의 역할

이 프로젝트에서 검증할 필살기 후보는 **최대전력이 높아질 시간을 미리 찾아내고, 그 크기를 작게 예상하는 문제를 줄이는 예측**이다. 마지막 15분 값을 활용해 기존 방법보다 최대전력을 안정적으로 예측하고, 중요한 최대 시간의 과소예측을 줄이는 것이 목표다. 입력 하나를 추가했다는 사실만으로 차별적 성과가 되는 것은 아니다.

Analysis 3.4는 이 방법을 시험할 근거를 마련했다. 직전 평균·최대 등을 고려한 마지막 값과 다음 최대값의 관계는 +0.409였지만, 엄격한 동일 평균 비교의 초기 기간에는 관계가 거의 없었다. 따라서 관계 분석의 수치를 성능으로 옮겨 쓰지 않고, 여기서 실제 예측값으로 이득과 실패조건을 확인한다.

| 단계 | 필살기 검증에서 맡는 역할 |
|---|---|
| M01·M02 | 정보 시점과 공통 표본을 검증하고, 직전·전날·전주 단순 기준 및 기본 모형의 성능을 확인한다. |
| M03 | 같은 모형·설정·학습 기간·평가 행에서 마지막 15분 값만 추가해 이득을 비교한다. 전날·전주 전력을 넣어도 이득이 남는지 확인한다. |
| M04·M05 | 전체 및 일별 최대 시간의 오차·과소예측·과대예측을 함께 보고, 월별·반복 배열별 안정성을 확인해 채택 여부를 결정한다. |
| M06 | 확인된 예측 가능 범위와 실패조건을 관리·저감방안 제안으로 연결한다. |

필살기로 채택하려면 비교 기준보다 최대전력 예측오차와 중요한 최대 시간의 과소예측이 줄고, 전체 오차나 과대예측의 악화가 사전에 정한 허용 범위 안에 있어야 한다. 개선이 특정 월·소수 사례·반복 배열에만 의존하면 큰 안정적 성과로 제시하지 않는다. 구체적인 선택 규칙은 아래 M05에 따라 후반기 평가 전에 고정한다.

또한 '같은 수의 관리시간으로 높은 최대전력 시간을 더 잘 찾아낸다'는 주장은 예측오차 감소와 별도로 검증해야 한다. 관리시간 선택 시점, 비교할 미래 구간, 관리 가능 시간 수와 선택 규칙을 정해야 하며, 매시간 다음 한 시간을 예측한 결과만으로 하루 사전 관리계획의 성과를 주장하지 않는다. 해당 범위는 M06에서 구분한다.

**현재 마지막 값 추가로 개발 MAE와 실제 일별 최대 시간의 과소예측이 줄어든 것을 확인했다. 급상승 전환의 오류는 해결되지 않았고, 후반기 안정성·최종 필살기 채택·실제 절감 효과는 아직 미확인이다.**

### 결과에 따른 계획 갱신 원칙

M01에서 시작해 M02 기본 비교를 수행하고, 첫 예측부터 M04의 오류진단을 병행한다. M03 입력 비교와 M04 진단에서 얻은 결과에 따라 다음 실험을 선택한다. 재현 기록은 처음부터 남기고 현장 판단 흐름도 개발 중 검토한다. 개발에서 선택을 마친 뒤 M05 고정 평가로 확인하고, M06의 활용안을 실제 결과에 맞춰 정리한다.

| 관찰한 결과 | 후속 계획의 변경 방향 |
|---|---|
| 단순 기준이 학습 모형보다 좋거나 월별 우열이 바뀜 | 시각 정렬·표본·달력 및 반복 구조를 먼저 진단하고, 확인된 원인에 맞춰 입력·학습 조건을 수정한다. 단순 기준도 최종 선택 후보로 유지한다. |
| 마지막 값 추가가 여러 개발 기간에서 안정적으로 개선됨 | 전날·전주 입력을 넣어도 이득이 남는지, 일별 최대 시간의 과소예측도 줄었는지 확인해 채택 범위를 정한다. |
| 마지막 값의 이득이 작거나 특정 조건에만 나타남 | 동일 시간의 오차 차이로 조건과 기여를 확인하고, 선택 입력으로 제한하거나 제외한다. 새로운 근거가 있으면 다른 입력·모형 비교로 질문을 바꾼다. |
| 전체 오차는 줄지만 최대 시간 과소예측은 악화됨 | 오차의 방향·실제 최대값 크기·조건별 집중을 진단하고, 필요성이 확인된 경우 손실함수 등 하나의 변경을 개발 자료에서 비교한다. |
| 반복 배열에 개선이 집중되거나 새로운 배열에서 실패함 | 중복 비중과 새로운 배열의 오차를 함께 보고, 비교 설계·학습 가중 등 확인된 문제에 맞는 변경을 검토한다. 유리한 결과를 위해 반복 날짜를 일괄 삭제하지 않는다. |

이 표는 분기의 예시이며 모든 방법을 순서대로 실행할 목록이 아니다. 기본 모델 계열과 마지막 값 추가는 초기 후보로 두고, 결과가 다른 질문을 요구하면 후보·우선순위·후속 분석을 갱신한다. 현재 자료로 답할 수 있는 구체적인 질문과 판단 기준이 있어야 다음 실험을 시작한다.

계획 변경은 **이전 근거 → 새 질문 → 변경 이유·범위 → 비교 조건·판단 기준 → 결과 → 채택·기각·종료 이유**로 기록한다. 비교할 목표·정보 시점·표본·지표는 회차 실행 전에 정하고, 변경 시에는 이전 결과와 비교 가능한 공통 조건을 확보한다. 자료 범위와 정보 누출 방지 원칙을 지키며, 기존 승인 범위 밖의 문제로 자동 확대하지 않는다.

M05의 고정은 개발 중 계획 변경을 막는 규칙이 아니다. 후반기 결과를 선택에 다시 사용하지 않고, 개발에서 정한 방법을 평가하기 위한 구분이다. 후반기 결과가 새로운 질문을 남기면 실패와 한계를 기록한다. 이후 별도 개발로 이어갈 때에는 해당 기간의 선택·열람 이력을 밝히고, 같은 자료의 재평가를 새로운 독립 검증으로 표현하지 않는다.

## 3. M01 — 예측 조건과 평가 자료 구성

**2026-10-04 실행 완료.** [M01 실행 기록](10.04_M01_자료시차평가조건_검증기록.md), [조건 파일](config/m01_contract.json), [분할별 실제 표본](tables/m01/split_counts.csv), [독립 검증](tables/m01/independent_verification.json)에 결과를 저장했다. 정규 CPython 3.13으로 준비·독립 검증이 모두 종료 0이었다. 원본은 보존했다.

정상 5,784시간에서 정확한 1·2·24·168시간 시차는 각각 5,781·5,778·5,712·5,568시간이다. 모든 시차가 있는 common 5,520시간을 주 비교, 직전 1·2시간이 있는 core 5,778시간을 보조 비교로 정했다. common 개발 평가 4·5·6월은 720·744·720시간, 후반기 7~8월은 1,344시간이다. 후반기 core 1,436시간과 common의 점수를 같은 표본의 비교로 섞지 않는다.

common 개발 평가 중 학습과 같은 하루 배열은 4월 0/30일·5월 17/31일·6월 26/30일이다. 6월의 새로운 배열은 4일뿐이므로 전체 점수만으로 안정성을 주장하지 않고 겹침·새 배열 결과를 함께 보고한다. 후반기 common은 직접 같은 배열이 없지만 이미 관찰한 기간이며 독립성 증명이 아니다. 이 조건으로 M02·M03의 비교와 오류진단을 실행했다.

### 정보 시점

목표 시간의 시각을 `t`라 하면, `t−1`시간의 네 전력값과 생산량을 관측한 뒤 `t`시간의 결과를 예측한다. 예측은 매시간 갱신한다. 실제 기록 보고 지연은 현 자료에서 미식별이므로, 관측을 마친 기록을 이용할 수 있다는 가정을 문서화한다.

| 구분 | 사용 방식 |
|---|---|
| 목표 시간의 시간대·요일·월 | 사전에 알 수 있는 달력 입력 |
| `t−1` 및 그 이전의 전력·생산 기록 | 과거 입력 |
| `t−1` 및 그 이전의 날씨 | 추가 가치 검증용 입력 |
| 목표 시간의 실제 생산량·날씨·평균·최대값 | 정답 또는 사후 진단에만 사용 |
| 목표 전력으로 계산되는 공장인원 등 | 입력 제외 |
| 하루 전체의 전력 배열·실제 일별 최대 시간 | 반복성·오류 사후 점검에만 사용 |

### 자료와 시차

- 현재 승인된 출발 범위는 1~8월 정상 241일·5,784시간이다. 기존 오류 48행을 제외하고 0·극단값은 유지한다.
- 날짜·시간으로 정확한 시차를 연결한다. 누락 날짜를 건너뛴 이전 행을 직전 시간으로 간주하지 않는다.
- `t−1`, `t−2`, `t−24`, `t−168`의 연결 가능 시간 수를 기록한다. 시차가 긴 입력의 비교는 같은 유효 평가 행에서 수행하고, 전체 운영 가능 시간 수와 구분한다.
- 과거 값이 부족한 시간의 처리 규칙은 평가 전에 정한다. 예를 들어 전주 기록이 없으면 전날, 그것도 없으면 직전 기록을 쓰는 순서를 사전 고정할 수 있다. 주 비교에서는 공통 표본을 우선해 입력 효과와 표본 차이를 분리한다.
- 필요한 결측 대체·스케일링은 각 학습 기간 안에서만 정한다. 미래값으로 과거 기상 결측을 보간하지 않는다.
- 최대값·평균값과 입력의 시각을 원본으로 독립 대조하고, 원본 해시·유효 표본·제외 이유를 저장한다.

### 시간순 평가 조건

M01에서 아래 분할의 실제 표본 수를 확인하고 `m01-v1` 조건으로 저장했다. 무작위 행 분할은 사용하지 않는다. 이후 근거 있는 개발 변경은 회차별 버전과 이유를 기록한다.

| 역할 | 학습 | 평가 | 사용 목적 |
|---|---|---|---|
| 개발 비교 1 | 1~3월 | 4월 | 기준·입력·모형 비교 |
| 개발 비교 2 | 1~4월 | 5월 | 개선의 기간별 반복 확인 |
| 개발 비교 3 | 1~5월 | 6월 | 앞선 판단의 안정성 확인 |
| 고정 후 후반기 평가 | 1~6월 | 7~8월 | 개발에서 고정한 방법의 후반기 결과 보고 |

7~8월은 EDA·Analysis와 선행 실험에서 이미 살펴본 기간이다. 새 독립 시험이라고 부르지 않으며, 결과를 보고 설정을 바꿔 같은 기간을 반복 평가하지 않는다. 개발 기간도 탐색에 사용된 이력이 있어 내부 시간순 평가라는 범위를 명시한다.

원본의 9월 336행은 이번 계획의 개발 자료에 자동으로 넣지 않는다. 최종 확인용으로 사용할지는 실행 설계에서 기존 열람·사용 이력과 평가 역할을 먼저 확인한다. 현재 계획에서는 미편입이며, 이를 사용하지 않아도 1~8월 내부 평가의 한계를 명시하고 비교를 수행할 수 있다. 추가 자료 확보를 전제로 하지 않는다.

각 분할에서 동일 하루 전력 배열의 학습·평가 겹침과 새로운 배열의 결과를 사후 점검한다. 전체 평가에서 반복 기록을 삭제하지 않고, 기본 결과와 반복의 비중을 낮춘 보조 결과를 함께 확인한다. 이 점검만으로 자료 생성의 독립성이 입증된다고 쓰지 않는다.

M01에서 보조 목표와 과거 평균은 반올림 전 평균으로, 모델 학습은 분할별 한 번으로 정했다. 필수 과거 시차는 대체하지 않고 해당 표본에서 제외하며, 단순 기준의 보조 대체 규칙은 별도로 저장했다. 초기 후보·개발 선택 규칙은 조건 파일에 있고, 최종 전체 오차·과대예측 허용 범위는 개발 결과 확인 후 M05 전에 명시한다. [공통 입력 코드](scripts/m01_prepare.py)의 `load_frame()`과 `feature_columns()`를 통해 같은 정의로 후속 비교를 구성한다.

**M01 산출물:** 입력·목표 정의, 분할별 행 수, 시차 가용성, 정보 시점 검증, 반복 배열 점검, 실행 전 조건 파일, 재현 절차의 초기 구성. 여기서 오류가 있으면 학습 전에 해당 구성만 수정한다.

**기존 HGB를 유지한다.** 전체/최대 시간 MAE는 기존 6.738/11.751, ExtraTrees 6.825/11.540, 가중 앙상블 6.872/13.035였다. ExtraTrees의 최대 시간 개선과 전체·상승·낮은 유지 악화를 구분한다. 새 5계열은 정한 범위에서 두 지표를 모두 개선한 후보가 없었다. 기존 HGB는 초기 개발에서 설정을 선택한 참조이고, 새 5계열은 평가월 이전 내부 검증으로 선택했다는 차이를 밝힌다.

HGB도 두 차례 설정을 비교했다. 초기에는 최대 잎 수 7·15만 비교했고, 확장에서는 5개 하이퍼파라미터를 Optuna로 평가월별 30회·총 90회 탐색했다. Optuna HGB의 전체/최대 시간 MAE 6.963/13.251보다 기존 6.738/11.751이 좋아 기존 설정을 유지했다. 유지 설정은 최대 잎 수 15·반복 150·학습률 0.05·잎의 최소 표본 20·L2 규제 1.0, 시드 42·조기 종료 미사용이다. 기존 설정은 초기 개발 결과로, Optuna는 평가월 이전 내부 검증으로 선택했다는 이력 차이를 명시한다. 상세 원고 4.4와 실행 기록에 종합 판단·튜닝 비교·유지 설정을 추가했다.

M02의 외부 예측은 1~3월→4월 720시간, 1~4월→5월 744시간, 1~5월→6월 720시간으로 모든 적격 시각을 평가한다. 내부에서는 1월→2월, 1~2월→3월 등으로 확장한다. 평가월 모델은 고정하고 관측 입력만 매시간 갱신한다. 7~8월은 후속 M05이며 이번 튜닝·선택에 쓰지 않았으나 과거 관찰 이력이 있어 완전한 독립 시험으로 부르지 않는다.

Optuna 700회·내부 학습 1,630회·외부 학습 15회, 30,576예측행·1,988지표행 독립 검증을 완료했다. 모델과 설정이 그대로이므로 M03 재실행 조건은 충족되지 않았다. 기존 M03의 B 후보와 결과를 유지하며 ExtraTrees B의 우열은 미검증이다. 이후 M04의 직전 낮은 상태 규칙은 전체 MAE와 상승/최대 시간 오차의 상충으로 기각했다. 후반기 M05는 아직 실행하지 않았다.

### 먼저 비교할 단순 기준

다음 최대전력에 대해 직전 시간 최대값, 전날 같은 시간 최대값, 전주 같은 시간 최대값을 그대로 사용하는 세 기준을 비교한다. 보조 평균 목표도 같은 방식으로 비교한다. 전날·전주 비교는 최초 Analysis 계획에서 남은 질문을 해결하는 단계다.

전체 오차와 월별·생산조건별 결과를 확인해 이후 모형이 넘어야 할 기준을 정한다. 최종 평가 기간에서 잘 나온 기준을 사후 선택하지 않는다.

### 학습 모형

사용자 승인으로 초기 비교를 Ridge·Elastic Net·RBF SVR·HGB(HistGradientBoostingRegressor) 네 계열로 확대했다. 선형 규제·변수 선택·커널 비선형·트리 부스팅의 차이를 같은 A 입력에서 비교한다. 정규 Python 3.13 환경에서 실행하며 추가 패키지 설치는 필요하지 않다. 후보와 전처리·선택 규칙은 기존 M01을 보존한 별도 [M02 조건](config/m02_contract.json)에 실행 전에 기록했다.

Ridge는 alpha 1·10, Elastic Net은 표준화한 목표의 alpha 0.001·0.01·0.1과 L1 비율 0.1·0.5·0.9, SVR은 표준화한 목표의 C 1·10·100, gamma scale·0.03, epsilon 0.05·0.1을 비교한다. HGB는 기존 잎 수 7·15의 설정을 유지한다. 총 25개 설정을 각 개발 분할·최대/평균 목표에 적용해 150회 학습한다. Ridge는 입력 표준화, Elastic Net·SVR은 입력과 목표 표준화를 각 학습 자료 안에서 수행하고 예측을 원척도로 복원한다. 후보 수가 계열마다 다르고 탐색이 제한적이므로 결과를 모든 설정에서의 알고리즘 우열로 확대하지 않는다.

기본 입력은 달력, 과거 생산량과 0 여부, 직전·그 이전 평균 및 최대 전력이다. 설정은 개발 평가에서 선택하고, 비슷한 성과이면 단순한 구성을 우선한다. 많은 알고리즘을 결과가 좋을 때까지 추가하지 않는다.

**M02 판단:** 단순 기준을 충분히 넘지 못하면 예측 정렬·달력 패턴·오류 조건을 먼저 점검한다. 근거 없이 더 복잡한 모형으로 확대하지 않는다.

제2장의 모델 비교표에는 베이스라인을 포함해 2개 이상의 모델을 동일 조건에서 비교하고, 학습·평가 기간, 입력, 평가 행 수, 전체·월별 성능과 선택 이유를 남긴다. 네 계열의 비교에서는 같은 입력을 사용해 모델 차이를 확인하고, M03에서는 같은 모델의 입력 유무를 비교한다. 첫 예측부터 M04의 기본 오류 요약을 생성해 다음 비교의 우선순위를 정한다. A06에서 확인한 전력 구간 상승·하락·유지와 생산량 전환을 별도로 진단하고, 실제 목표값으로 정한 구간을 입력에 넣지 않는다.

## 5. M03 — 마지막 15분 값의 추가 가치

[M03 실행 기록](10.04_M03_마지막값추가와시차입력_실행기록.md) · [A/B 조건](config/m03_ab_contract.json) · [C 조건](config/m03_c_contract.json) · [통합 비교](tables/m03/c/comparison.csv) · [조건별 오류](tables/m03/c/condition_errors.csv) · [독립 검증](tables/m03/c/independent_verification.json).

HGB 설정·학습 행·개발2,184시간을 고정했다. 마지막 값 하나를 추가한 A→B는 최대MAE6.738→6.191(8.1% 감소), 실제 일별 최대 시간 평균 과소예측11.260→6.987(37.9% 감소)였다. 각 개발 월과 새 배열에서도 개선 방향이 유지됐다. 최대 시간의 평균 과대예측은0.491→0.602로 증가했다.

첫 결과에 따라 전날·전주 입력을 추가한 C_A/C_B를 비교했다. C_A→C_B도MAE7.047→6.231로 마지막 값 효과가 남았지만, C_B는 B보다 전체·최대 시간 오차가 컸다. 개발 후보는 입력18개의 B로 유지하며 계절 시차는 기본 구성에서 제외한다. 날씨D는 Analysis3.3의 약한 관계와 새 근거가 없는 점을 고려해 보류했다. 날씨의 무효를 검증한 것은 아니다.

2026-10-05 M04에서 예측 시점에 아는 직전 낮은 구간에서만 직전 기준을 쓰는 규칙을 실제 비교했다. 전체 MAE6.191→6.061이나 실제 일별 최대 MAE7.589→7.875·상승 과소48.772→75.400으로 악화해 사전 기준에 따라 기각하고 B를 유지했다. 아래 M04 및 원고4.6에 근거를 연결한다. M05 전에 방법과 허용 범위를 기록하며, 후반기는 아직 평가하지 않았다.

새학습18회와 부모모델 재사용 대조,8,736/17,472예측행 및4,368/17,472전후비교행의 독립 검증이 모두종료0이다. [m03_ablation.py](scripts/m03_ablation.py)는 회차별 학습·저장, [m03_verify.py](scripts/m03_verify.py)는 원본시차·지표·동일행·최대가중치·전후차이, [m03_error_followup.py](scripts/m03_error_followup.py)는 저장예측의 최소 오류진단을 수행한다. 재현 명령은 실행 기록에 있다.

### 출발 계획과 비교 원칙

주 질문은 **같은 모형·설정·학습 기간·평가 행에서 마지막 값 하나를 추가하면 성능이 개선되는가**다.

| 입력 비교 | 확인 목적 |
|---|---|
| A. 달력 + 과거 생산 + 과거 평균·최대 | 기준 성능 |
| B. A + 직전 마지막 15분 값 | 3.4의 핵심 가설 검증 |
| C. 기준에 전날·전주 전력 추가, 마지막 값 유무를 다시 비교 | 마지막 값의 이득이 단순한 계절 시차 누락 때문인지 확인 |
| D. 선택한 개발 구성에 과거 날씨 추가 | 3.3의 남은 예측 가치 확인 |

C·D는 기준과의 변경 사항을 하나씩 구분한다. 마지막 값의 효과를 다른 변수·설정 변경과 섞지 않는다. 처음부터 전체 네 구간·변환·전환 확률을 모두 넣지 않는다. 추가 입력은 실제 오류나 잔여 질문이 생겼을 때만 비교한다.

**M03 판단:** 전체 평균 점수뿐 아니라 개발 월별 방향과 최대전력 시간의 오차를 함께 본다. 입력 추가가 불안정하면 필수 입력으로 채택하지 않는다. 마지막 값 추가가 실패해도 결과를 보존하고 원인을 M04에서 확인한다.

각 비교에서 같은 목표 시각의 실제값, 기준·후보 예측값, 절대오차·과소예측량·과대예측량 및 두 방법의 차이를 저장한다. 이 결과를 제2장의 입력 기여와 제3장의 조건별 오류 감소에 공통으로 사용한다. C·D의 순서와 범위는 앞선 결과에 따라 갱신하며, 보류하거나 다른 비교로 바꾸면 기존 질문을 종료·대체한 근거를 기록한다.

[비교 코드](scripts/m04_compare.py)와 [검증 코드](scripts/m04_verify.py)의 전체 소스·의존성을 원고4.5/보존 목록에 추가했고, 상세4.6에 개선·실패·기각 이유를 작성했다. 새학습·튜닝·7~8월 평가·압축본은 실행하지 않았다.

[첫 조건](config/m04_rise_contract.json), [후속 조건](config/m04_rise_gate_contract.json), [최종 비교표](tables/m04_rise_gate/selection_metrics.csv), [독립 검증](tables/m04_rise_gate/independent_verification.json)에 근거를 보존한다. 총 Optuna750회·학습840회 후 선언한 비교는 종료하고 B를 유지한다. 원고4.7·4.5의 전체25코드와 재현 파일을 연결했다. 다음 질문은 고정 A/B의 효과와 실패조건이 7~8월에서도 유지되는가이며 M05는 아직 실행하지 않았다.

M04는 M02·M03에서 예측이 생길 때마다 수행한다. 먼저 기본 오류를 요약하고, 중요한 실패조건이 확인되면 그 원인에 필요한 최소 분석으로 좁힌다. 이 결과에 따라 M02·M03의 후속 비교를 갱신한다.

### 공통 지표

- MAE를 기본 오차로, RMSE를 큰 오차의 보조 지표로 보고한다. 개선율에는 기준 오차와 평가 시간 수를 함께 적는다.
- 평균 과소예측량은 모든 평가 행에서 `max(실제−예측, 0)`의 평균이다. 평균 과대예측량도 반대 방향으로 계산한다. 해당 방향의 오류가 없는 행에는 0을 포함한다.
- 발생 비율과 발생한 행에서의 평균 크기는 별도로 계산한다. 크기 감소를 횟수 감소로 표현하지 않는다.
- 0값이 있으므로 단순 MAPE를 주 지표로 쓰지 않는다.
- 실제 일별 최대전력이 발생한 시간도 별도로 평가한다. 완전한 하루의 가용성을 확인하고, 동률 최대 시간은 하루 가중치 합이 1이 되도록 처리한다. 전 시간 평균과 일별 최대 시간 평균의 분모를 구분한다.
- 일별 상대적 최대는 낮은 전력의 날에도 존재한다. 최대값 자체의 크기와 오류를 함께 제시하고, 모든 일별 최대를 절대적으로 위험한 피크라고 부르지 않는다.

### 이전 결과에서 정한 오류 조건

먼저 생산량 0→양수·양수 지속·양수→0·0 지속, 기존 낮은 전력 구간의 지속·변화, 월·평일/주말·시간대별 오류를 본다. 실제 목표 생산량·전력으로 나눈 조건은 사후 오류 진단이다. 운영 시 미리 아는 상태로 사용하지 않는다.

각 조건의 표본 수·전체 오류 기여를 같이 보고, 오차가 집중된 조건에서만 추가 원인을 진단한다. 표본이 적은 교차집단의 유리한 결과를 대표 성과로 선택하지 않는다. 일별 오차 차이와 기간별 결과를 보고 반복 기록의 영향을 점검한다.

제3장에서는 잘 작동하는 조건과 실패조건을 모두 제시하고, 마지막 값 추가 전후의 동일 시간 오차 차이로 무엇이 개선됐는지 설명한다. 오류 기여는 조건별 절대오차 합과 전체 절대오차 합의 비율 등 정의와 분모를 명시한다. 생산 전환·월·시간대처럼 서로 겹치는 구분의 기여율을 합산하지 않는다. Analysis의 생산·날씨 관계는 오류 해석의 근거로 연결하되, 관측 변동이 큰 조건을 예측 실패조건으로 대신하거나 관측 관계를 인과효과로 표현하지 않는다.

현재 연속값 예측에는 수치 오차분석을 적용한다. 보고서 양식의 미탐지·오경보 항목 때문에 새 이진 피크 기준을 의무적으로 만들지 않는다. 경보 성과를 제시할 경우에만 별도의 판정 규칙과 검증 설계를 정한다.

### 수정과 재검증

1. 이전 결과에서 어느 조건의 어떤 오류가 남았는지 적는다.
2. 구현·정보 시점·표본 구성 문제인지, 입력 정보나 모형의 한계인지 구분한다.
3. 변경 이유와 판단 지표를 먼저 기록하고 하나의 변경을 적용한다.
4. 영향을 받는 개발 비교만 재실행하고 전후 결과를 남긴다.
5. 개선이 반복되지 않거나 새 근거가 없으면 중단한다. 고정 후 평가를 보고 반복 조정하지 않는다.

과소예측에 대한 비대칭 손실·분위수 예측 등은 실제 오류 분석에서 필요성이 확인될 때만 검토한다. 그 경우 과대예측 증가와 예측 구간의 적정성까지 함께 평가한다. 현재 확정된 핵심 방법으로 미리 내세우지 않는다.

## 7. M05 — 고정 평가와 필살기 채택 판단

개발에서 입력·모형·전처리·평가 지표를 고정한 뒤 후반기 평가를 실행한다. M01의 분할대로 1~6월 자료로 각 모델을 한 번 학습하고, 같은 모델을 고정해 7~8월을 평가한다. 7월 정답을 추가해 8월용 모델을 다시 학습하지 않는다. 결합 규칙과 경보 경계도 6월 말까지의 자료로 확정해 두 평가 월에 고정한다. 매시간 직전 관측이 완료되면 전력·생산량 등의 입력만 갱신해 다음 한 시간을 예측하며, 이 과정은 재학습과 구분한다. 각 목표 시각의 정답·예측값과 모델 버전, 사용한 입력 시각을 저장한다.

차별적 성과로 채택하려면 다음 근거를 함께 제시해야 한다.

- 비교 가능한 기준보다 최대전력 예측오차를 줄이고, 중요한 최대 시간의 과소예측도 개선했는가?
- 과소예측 감소가 과도한 과대예측 증가나 전체 성능 악화로 얻어진 것은 아닌가?
- 개선이 한 월·소수 사례·반복 배열에만 의존하지 않는가?
- 입력 추가의 이득을 같은 조건의 비교로 설명할 수 있는가?

허용할 전체 오차·과대예측의 악화 범위와 최종 선택 규칙은 개발 결과를 바탕으로 후반기 평가 전에 명시한다. 현장 비용 비율이 미식별이므로 임의의 경제적 최적값을 주장하지 않는다. 상충하는 결과는 숨기지 않고 조건별 장단점으로 남긴다. 큰 안정적 개선이 없으면 마지막 값 추가를 필살기로 포장하지 않는다.

## 8. M06 — 관리시간과 저감방안의 제안

예측 결과를 바탕으로 최대전력 상승이 예상되는 시간의 점검과 생산·가동 시점 조정 검토 방안을 제안한다. 현재 자료에는 설비별 이동 가능 부하와 생산 제약이 없어 실제 최적 일정·절감 전력·비용을 입증하지 못한다. 이전에 제외한 가정 기반 재배치 실험을 자동으로 재개하지 않는다.

기본 예측은 매시간 다음 한 시간을 보는 방식이다. 이 방식으로 하루 전체를 사전에 알고 관리시간을 골랐다고 표현하지 않는다. 같은 수의 관리시간에서 높은 최대전력을 더 잘 찾는 성과까지 제시하려면, **동일한 예측 시점에 비교할 미래 구간과 관리 가능 시간 수**를 먼저 정해야 한다. 여러 시간 앞 예측이나 사전 일정 제안이 필요한 경우에는 별도 예측 문제로 정의하고 검증한다. 현재 계획에서 성과로 보장하지 않는다.

저감방안은 실제로 확인된 예측 가능 범위·실패조건과 함께 기술한다. 제안과 실행된 절감 효과를 구분한다.

제4장에는 '직전 시간 관측 완료 → 다음 한 시간 최대전력 예측 → 전력·생산 담당자가 예정된 가동·생산계획과 함께 확인 → 동시 가동이나 시작 시점 조정 가능 여부 검토'의 활용 흐름을 제안한다. 담당자의 실제 계획 확인은 현장 적용 시 필요한 절차이며, 예정 계획이 현재 데이터의 예측 입력으로 제공됐다고 가정하지 않는다. 각 단계의 확인 시점·출력값·판단·가능한 조치와 적용 가정을 설명하고, 오류분석에서 확인한 실패조건에는 추가 확인이 필요함을 연결한다. 자동 제어·실제 일정 최적화·절감량을 검증한 성과로 쓰지 않는다.

| 제3장. 영향요인 및 오류분석〔15점〕 | 반복 수행하는 M04와 관련 Analysis | 잘 맞는 조건·실패조건, 표본 수·오류 기여, 최대 시간 과소·과대예측, 기준 대비 개선과 남은 한계 |
| 제4장. 현장 활용방안〔10점〕 | M06 | 예측 확인 시점·담당자·판단·조치, 적용 가정과 실패조건 |
| 제5장. 창의성 및 차별성〔10점〕 | 제2·3장의 확인된 성과 | 마지막 값 등 채택한 방법이 성능·오류 감소·활용에 기여한 근거 |
| 제6장. 코드 구성 및 재현성〔10점〕 | M01부터 축적한 전 단계 산출물 | 전처리·학습·추론·결과 생성의 실행 순서, 환경·설정·검증 결과 |

제1장은 Analysis 원고 전체를 옮기기보다 예측 설계에 필요한 근거를 선별한다. 생산 전환·날씨의 상세 분석은 제3장에서 실제 오류와 연결되는 부분을 사용한다. 제2·3장의 55점과 제5장의 요구에 맞춰 모델 선택 → 입력의 기여 → 오류 감소·실패조건 → 현장 판단의 연결을 우선한다. 제5장은 새로운 알고리즘을 썼다는 설명이나 관계 계수만으로 성과를 주장하지 않는다.

제출 편집 기준은 사용자 제공 양식의 휴먼명조14pt·줄간격160%, 세부 주석10pt·줄간격160%다. 기존 압축 원고의 페이지 수를 제출 분량으로 간주하지 않는다. M03 핵심 A/B·C와 M04 오류 진단·낮은 상태 규칙 비교까지 실행했고 날씨D·후반기 평가·최종 제출 편집은 미실행이다.
