## 현재 필살기 후보와 검증 목표

**최대전력이 높아질 시간을 미리 찾아내고, 그 크기를 작게 예상하는 문제를 줄이는 예측**을 프로젝트의 필살기 후보로 삼는다. 관측을 마친 직전 시간의 정보로 다음 한 시간의 네 15분 전력값 중 최댓값을 직접 예측한다.

핵심 방법은 달력·과거 생산량·과거 평균 및 최대 전력을 쓰는 모형에 **직전 시간의 마지막 15분 값**을 추가하는 것이다. Analysis 3.4에서 직전 평균·최대 등을 고려한 뒤에도 마지막 값과 다음 최대값의 관계가 +0.409로 남아 이 비교를 선택했다. 엄격한 동일 평균 비교의 초기 기간에는 관계가 거의 없었던 예외도 있다. 이 수치는 예측 정확도나 오차 개선률을 뜻하지 않는다.

필살기로 제시하려면 같은 시간순 평가 조건에서 단순 기준과 기본 모형보다 최대전력 예측오차와 중요한 최대 시간의 과소예측을 줄였다는 근거가 필요하다. 전체 오차·과대예측이 과도하게 늘지 않고, 개선이 특정 월이나 반복 기록에만 의존하지 않는지도 함께 확인한다. 마지막 값 추가의 이득이 작거나 불안정하면 차별적 성과로 채택하지 않는다.

**현재는 M03 마지막 값·계절 시차 비교, M02 확장 모델 비교, M04 조건별 오류·낮은 상태 규칙·상승 결합 비교까지 완료했다.** 확장 비교에서도 기존 HGB를 유지했고 M04 규칙은 기각해 기존 B를 유지한다. 마지막 값의 개발 개선은 확인했지만 M05에서는 전체 개선0.92%와 최대시간 악화가 나타나 안정적 기여를 확정하지 못했다. 최신 판단은 문서 상단 및 원고4.9를 따른다. 결과에 따라 다음 비교를 갱신하고 M06에서는 검증된 범위의 관리·저감방안을 제안한다.

2026-10-04 [M01 실행 기록](Modeling/10.04_M01_자료시차평가조건_검증기록.md): 공통 비교 표본 5,520시간, 개발 평가 4·5·6월 720·744·720시간, 후반기 7 ~ 8월 1,344시간을 확인했다. 5·6월 평가에는 학습과 같은 하루 배열이 각각17/31일·26/30일 있어 성능을 겹침·새 배열별로도 확인한다. 이 준비 회차는 학습 없이 검증했고 정규 Python·독립 검증 모두 종료0이다.

[M02 실행 기록](Modeling/10.04_M02_기본모형비교_실행기록.md): 단순 기준3개와 Ridge·Elastic Net·SVR·HGB를 같은 A입력·개발2,184시간에서 비교했다. HGB는 최대전력 MAE6.74로 직전 기준13.79보다51.1% 작고, 실제 일별 최대 시간 평균 과소예측도36.59→11.26으로 줄었다. 상승20시간의 과소예측47.87과 낮은 구간 유지 악화가 남아 아래M03으로 연결했다. 이 회차에서는 마지막 값을 넣지 않았다.

[M03 실행 기록](Modeling/10.04_M03_마지막값추가와시차입력_실행기록.md): 같은 HGB에 마지막 값만 추가한 B는 최대MAE6.74→6.19(8.1% 감소), 일별 최대 시간 평균 과소예측11.26→6.99(37.9% 감소)였다. 전날·전주 입력을 고려해도 마지막 값 효과는 남았지만 더 복잡한 C_B보다 B가 전체·최대 시간에서 좋았다. 상승 전환은 해결되지 않았고, 최소 진단에서 그20시간과 일별 최대시간의 겹침은0이었다. 개선은 주로26초과가 유지되는 날의 최대 시간에서 나타났다. 새학습18회·독립검증·그림확인이 완료됐으며, 날씨D는 근거에 따라 보류하고 후반기는 미평가다.

[M02 확장 재실행](Modeling/10.04_M02_확장모델비교_실행기록.md): 기본 A 입력에서 HGB·XGBoost·LightGBM·CatBoost·ExtraTrees의 Optuna 시간순 튜닝과 두 앙상블을 비교했다. 전체·실제 일별 최대 시간 MAE를 함께 평가한 규칙에서 기존 HGB 6.738/11.751을 유지했고, ExtraTrees 6.825/11.540의 상충을 공개했다. 모델·설정이 같아 M03 재실행 조건은 충족되지 않았으며 기존 B 후보를 유지한다. Optuna 700회와 독립 검증을 완료하고 상세 원고 4.4에 결과를 연결했다. M02는 1~3월→4월, 1~4월→5월, 1~5월→6월의 모든 적격 2,184시간이며 내부 검증은 1월→2월부터 순차 확장한다. 7~8월은 후속 M05 구간으로 이번 선택에 쓰지 않았으며 과거 관찰 이력은 유지한다.

[M04 실행 기록](Modeling/10.05_M04_조건별오류와낮은전력규칙_실행기록.md): 직전 낮은 상태650시간에만 직전 기준을 쓰면 전체MAE6.191→6.061로 좋아지지만, 실제 일별최대MAE7.589→7.875·상승과소48.772→75.400으로 악화해 기각했다. 조건별오류 기여와 예측전 입력을 점검하고 기존B를 유지한다. 새 학습 없이 독립검증을 마쳤으며 상세 원고4.6과 전체 코드 보존 목록에 연결했다. 후반기 M05는 아직 실행하지 않았다.

[M04 상승 추가 개발](Modeling/10.05_M04_상승예측결합_실행기록.md): 변화 입력·상승 가중 HGB·Logistic/HGB 분류 결합과 한 번의 결합 점수 수정을 시간순으로 비교했다. HGB 결합은 상승 MAE48.772→40.217(17.5% 감소), 전체6.191→6.146이지만 낮은 유지 MAE4.110→4.228(2.9% 증가)로 사전1% 허용을 넘었다. 상승20시간 중9시간을 찾아 재현율45%·정밀도60%, 비상승630시간 중오경보6시간이었다. Optuna750회·새학습840회와 독립 검증을 마쳤고 모든 교체 요건을 통과한 후보가 없어 B를 유지했다. 원고4.7·전체25코드·제출 보존 목록에 연결했으며 M05는 미실행이다.

같은 수의 관리시간으로 높은 최대전력 시간을 더 잘 찾는 성과는 별도 검증이 필요하다. 관리시간을 고르는 시점, 비교할 미래 구간, 관리 가능 시간 수와 선택 규칙을 먼저 정해야 한다. 매시간 갱신하는 다음 한 시간 예측을 하루 사전 일정 선택으로 해석하지 않으며, 실제 절감 전력·비용도 아직 입증하지 않았다.

## 결과보고서 구성과 분석의 연결

사용자가 제공한 결과보고서 양식에 따라 아래와 같이 배치한다. 작업 폴더의 EDA·Analysis·Modeling 구분과 제출 보고서의 장 구분은 목적에 맞게 연결한다.

| 보고서 장과 배점 | 가져올 내용 | 작성할 근거 |
|---|---|---|
| 제1장. 데이터 이해 및 진단〔15점〕 | 데이터 정의·전처리, 핵심 EDA, Analysis의 입력 선택 근거 | 기록이 나타내는 공장 전력·생산 상태와 해석 한계, 분석 목적, 목표·입력·검증 설계를 정한 이유 |
| 제2장. AI 예측모델 개발 및 성능평가〔40점〕 | M01·M02·M03·M05 | 베이스라인 포함 2개 이상 모델의 동일 조건 비교, 마지막 값의 추가 효과, 최종 모델 선택 이유 |
| 제3장. 영향요인 및 오류분석〔15점〕 | M04와 관련 Analysis 결과 | 잘 맞는 조건과 실패조건, 조건별 표본 수·오류 기여, 제안 방법이 줄인 오류와 남은 한계 |
| 제4장. 현장 활용방안〔10점〕 | M06 | 예측을 확인하는 시점·담당자·판단·조치와 적용 가정 |
| 제5장. 창의성 및 차별성〔10점〕 | 제2·3장에서 검증한 핵심 성과 | 데이터에서 찾은 정보가 성능·오류 감소·현장 활용에 기여한 과정 |
| 제6장. 코드 구성 및 재현성〔10점〕 | 모든 단계의 실행 코드·설정·산출물 | 제출자료로 전처리부터 학습·추론·결과 생성을 재현하는 절차 |

제1장에는 평균과 최대값의 차이, 시간 오류와 반복 배열, 생산량 0의 해석 범위, 마지막 값의 선행 관계를 중심으로 예측 설계의 이유를 설명한다. Analysis 전체 원고를 그대로 넣기보다, 생산 전환·날씨의 상세 결과는 제3장의 실제 오류 해석에 필요한 부분을 연결한다. 관측된 전력 변동과 모델의 예측오차는 각각 확인하며, 관측 관계를 모델의 영향요인이나 인과효과로 단정하지 않는다.

제2장에서는 모델 간 성능 차이와 같은 모델에서 입력만 추가한 효과를 구분한다. 제3장에서는 같은 시간의 기준·후보 예측을 비교해 전체 오차, 일별 최대 시간의 과소·과대예측, 월·시간대·생산조건별 개선과 실패를 설명한다. 현재 연속값 예측에는 수치 오류분석을 적용하며, 미탐지·오경보 성과를 주장할 때는 별도 판정 규칙과 검증이 필요하다.

제4장은 '직전 시간 관측 완료 → 다음 한 시간 최대전력 예측 → 담당자가 예정된 가동·생산계획과 함께 확인 → 동시 가동·시작 시점 조정 가능 여부 검토'의 활용 흐름을 구체화한다. 예정 계획은 현장 적용 시 담당자가 확인할 정보이며, 현재 자료에 있는 예측 입력으로 가정하지 않는다. 실제 절감량과 비용은 미입증 상태로 구분한다. 제5장은 제2·3장의 결과를 인용해 차별성을 설명하고, 제6장의 코드·설정·실행 명령·예측 파일은 M01부터 축적한다.

최종 편집에는 제공 양식의 휴먼명조 14pt·줄간격 160%, 세부 주석 10pt·줄간격 160%를 적용한다. 기존 원고의 압축본·배치 확인 결과와 제출 양식 적용 후 분량은 구분한다.

## 결과에 따라 갱신하는 Modeling 계획

**분석 결과에 따라 후속 질문·방법·우선순위를 바꾸는 것을 권장한다.** M01~M06은 시작 시점의 기본 흐름이며, 각 결과를 확인한 뒤 다음 비교의 필요성과 조건을 갱신한다. 마지막 15분 값은 첫 검증 후보이며, 결과에 따라 제외하거나 다른 입력·모형·오류 대응 방법을 검토할 수 있다.

실행은 M01 조건·재현 준비 → M02 기본 비교 → M03 입력 비교와 M04 오류진단의 반복 → M05 고정 평가 → M06 활용안 정리로 진행한다. M04는 첫 예측부터 함께 수행하고, 재현 기록은 전 단계에서 남긴다. M06의 현장 판단 흐름은 개발 중에도 검토하되 최종 제안은 실제 성능·실패조건에 맞춘다.

계획을 바꿀 때에는 이전 결과의 수치·예외 → 새 질문 → 변경 이유·범위 → 비교 조건·판단 기준 → 실행 결과 → 채택·기각·종료 이유를 기록한다. 개별 비교의 조건은 실행 전에 정하고, 변경 회차는 같은 표본·지표의 비교 가능성을 확보한다. 최종 후반기 평가를 보고 같은 기간에 반복 조정하지 않으며, 이후 새 개발을 시작하면 해당 기간을 선택에 사용한 이력을 명시한다. 새 근거 없이 유리한 결과가 나올 때까지 반복하지 않는다.

구체적인 분기와 산출물은 [Modeling 진행 계획](Modeling/README.md)에 기록한다. 현재 후보는 HGB 잎15·B 입력이다. 마지막 값의 최대 시간 개선과 상승/낮은 유지의 한계를 구분했으며 확장 M02에서도 기존 HGB를 유지했다. M04에서는 직전 낮은 상태의 단순 기준 규칙을 비교해 유지의 평균 개선과 상승/상대적 최대의 악화를 확인하고 기각했다. M05는 고정 후반기 평가를 완료했으며 마지막 값의 최대 시간 개선이 유지되지 않았다. 다음 작업은 문서 상단에 연결한 재분석 계획의 R01 조건별 진단이다. 새 재분석과 M06은 아직 수행하지 않았다.
