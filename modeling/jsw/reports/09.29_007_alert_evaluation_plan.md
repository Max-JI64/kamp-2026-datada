# 007: 고정 경보 정책의 부담과 사건 시작 전 포착

작성·실행: 2026-09-29 | 상태: M004 재현, Q1~Q3 실제 집계·독립 검증 완료

개발 2시간/일 예산에서 고정한 q75 정책은 7~8월 시작 전 포착을 HGB의 47/76건에서 54/76건으로 늘렸다. 원시 경고 시간은 184→209시간, 새 알림은 67→76회로 함께 증가했다. q75를 포착과 부담의 교환관계 후보로 남기고, 기본 HGB를 유지한다. 혼합은 사건 중 포착을 늘렸지만 시작 전 포착은 46건으로 HGB보다 1건 적었다. 실행 계약과 결과는 11~19절에 있으며, 1~9절은 실행 전 계획이다. 새 모델 학습·다중 시간 예측·재배치 최적화는 수행하지 않았다.

## 1. 이전 결과와 질문

[M004](09.26_004_high_hour_selection.md)에서 5~6월 실제 높은 79시간의 놓침은 q75로 25→16, 높지 않은 1,385시간의 잘못 선별은 20→34로 바뀌었다. 같은 실제 기준을 예측값에 적용하면 더 많이 경고하는 모델이 포착률을 높일 수 있다. 이번 질문은 **비슷한 경보 부담에서 사건 시작 전에 얼마나 더 포착하는가, 실제 이후 기간의 부담은 얼마인가**다.

기본 비교군은 lag1, 기존 HGB, 기존 q75, M006에서 근거를 가진 후보 하나다. M006이 개선을 찾지 못해도 기존 모델로 평가할 수 있다. M007은 예측값으로 경보 정책을 평가하는 단계이며 필요 없이 모델을 재학습하지 않는다.

## 2. 사건 기준과 경보 기준을 분리

실제 사건은 `P≥u`, 원시 경고 플래그는 `P_hat≥c`로 정의한다. u는 실제 높은 상태의 연구용 기준, c는 경보 부담을 조절하는 예측값 기준이다. u와 c가 같을 필요는 없지만 각 값의 결정 자료와 목적을 남긴다.

M004 재현에서는 각 학습구간의 u를 유지하고 c=u로 기존 집계를 먼저 대조한다. 이후 7~8월의 공통 주 사건 기준은 기존 182다. 개발·평가의 사건 기준 차이를 숨긴 합산 포착률로 비교하지 않는다. 실제 운영 계약 한계가 있는 것처럼 이름 붙이지 않는다.

입력은 M005 사건·coverage와 M001/M002/M006의 시간순 예측이다. 후보별 기간·target·record_key를 맞추고 동일 실제값·사건 ID를 사용한다. 후보에 예측값이 없는 기간을 다른 달 점수로 채우지 않는다.

## 3. 경보를 발행하는 규칙

완료된 직전 기록으로 목표 기록의 플래그를 만든다. 연속된 플래그는 하나의 경보 묶음으로 표시하되 원시 경고 시간 수를 모두 보존한다. 낮은 플래그 또는 기록 공백에서 묶음을 끊는다. 날짜가 바뀌었다는 이유만으로 같은 연속 묶음을 쪼개지 않는다.

기본 규칙은 첫 플래그에서 새 알림, 이어지는 플래그는 유지 상태, 다음 비경고 플래그에서 해제다. 별도 냉각시간·2회 연속 확인·히스테리시스는 기본에 넣지 않는다. 이런 규칙은 시작 지연을 바꿀 수 있어, M005에서 반복 알림 문제가 확인될 때만 별도 정책으로 설계한다.

시작 경고 성능에는 `목표 시작 시간에 발행한 플래그`, `사건 시작 직전 이미 활성인 경보`, `그 시점의 새 알림`을 구분해 남긴다. 활성 경보가 오래 유지돼 이후 모든 사건을 잡은 것처럼 보일 수 있으므로 활성 시간 비율·묶음 길이·정밀도를 반드시 함께 보고한다.

## 4. 개발에서 부담을 맞추는 방법

연구용 비교 예산으로 날짜당 평균 원시 경고 시간 **1·2·4시간**을 제안하며 **2시간**을 주 비교로 둔다. 실제 작업자의 허용량을 확인한 숫자가 아니며 예산별 성능을 보고 유리한 예산만 본문으로 바꾸지 않는다.

1. 개발 예측에서 각 후보의 가능한 점수 경계와 경보 없음 경계를 후보 c로 만든다. 정답을 보며 새로운 사건 기준 u를 바꾸지 않는다.
2. 공통 예측이 있는 개발 날짜를 분모로, 평균 원시 경고 시간이 예산 이하인 경계 중 가장 많은 시간을 경고하는 경계를 고른다. 동률 점수 때문에 정확히 예산을 맞추기 어려우면 예산을 넘기지 않는 쪽을 선택한다.
3. 같은 원시 플래그를 만드는 경계가 여러 개면 가장 보수적인 경계를 고정한다. 같은 점수 일부만 무작위로 켜거나 실제 정답을 보고 골라내지 않는다.
4. 결정한 c를 이후 구간에 그대로 적용하고 실제 원시 경고 시간·새 알림 수·활성 시간 비율을 모두 보고한다. 평가 자료의 점수 분위수로 c를 다시 맞추지 않는다.

주 부담은 원시 경고 시간 기준이다. 이는 경보 묶음 개수와 다르므로 `같은 알림 수` 비교라고 부르지 않는다. 후보들의 달성 부담이 크게 다르면 정확히 같은 부담이라는 주장도 하지 않고 달성값을 병기한다.

5·6월 예측 전체로 c를 정했다면 그 기간의 포착 점수는 정책 선택에 사용한 개발 점수다. 시간순 내부 점검은 5월에서 정한 c를 6월에 적용하는 식으로 구분할 수 있지만 표본이 작음을 적는다. 최종 개발 c를 고정한 뒤 7·8월을 월별 탐색 확인으로 사용한다. 개발과 평가 모델의 학습량 차이로 점수 척도가 변할 수 있으며, 이때 발생하는 경보량 변화 자체가 결과다.

분모에는 전체 날짜·공통 예측 있는 날짜·완전 예측 날짜와 시간 수를 함께 둔다. 부분 예측 날짜를 완전한 24시간 서비스처럼 해석하지 않는다. 비가용 시간은 별도 상태이며 임의의 안전한 저위험으로 채우지 않는다.

## 5. Q1: 시간을 얼마나 잘 선별하는가

같은 적격 시간에서 TP·FP·FN·TN, 정밀도·재현율·F1, 원시 경고 시간/일, 활성 시간 비율을 보고한다. 실제 높은 시간이 0인 집단의 재현율이나 경고가 0인 집단의 정밀도는 분모 0으로 미정의 처리한다. 0으로 대체해 합산 순위를 만들지 않는다. 전체 정확도 하나로 높은 상태의 포착 성능을 대신하지 않는다.

새 경보 묶음/일, 묶음당 길이, 실제 고부하 없이 끝난 묶음 수를 추가한다. 시간 단위 FP 수와 잘못된 경보 묶음 수는 다른 부담 지표다. 주요 결과는 월별·전체 공통 범위와 실제 달성 경보량을 나란히 보여 준다.

## 6. Q2: 사건을 시작 전에 포착하는가

| 지표 | 정의 | 분모·경계 |
|---|---|---|
| 시작 전 포착률 | 사건 첫 목표 기록에 대한 사전 예측이 경고 | 시작 예측 가능한 사건 |
| 시작 평가 가능률 | 첫 목표에 예측이 있는 사건 | 시작을 식별할 수 있는 모든 관측 사건 |
| 사건 중 포착률 | 사건 중 하나 이상 대상 기록에 경고 | 하나 이상 평가 가능한 대상이 있는 사건 |
| 지연 포착 | 첫 기록은 못 잡고 이후 기록에 경고 | 시작 예측 가능한 사건 중 해당 수 |
| 완전 누락 | 평가 가능한 사건 기록 모두 비경고 | 위 사건과 불가 기록 포함 여부 별도 |
| 첫 포착 지연 | 사건 첫 기록과 첫 경고 대상 기록의 차이 | 기록 단위. 물리적 대응시간으로 바꾸지 않음 |

시간 공백·평가 경계의 불명 사건 처리는 M005 정의를 따른다. 사건 기록 일부만 예측 가능하면 완전 누락 여부의 관측 범위를 표시한다. 경보 없는 평가 불가 시간을 성공이나 정상으로 넣지 않는다.

실제 일최대가 여러 시간에 동률이면 일별 `하나라도 사전 경고`와 `모든 동률 시간 경고`를 나눠 날짜 수로 보고한다. 최대가 u 미만인 날과 높은 날은 분리한다. 월최대는 사례·불가 여부를 포함해 설명한다. 사후의 날짜별 최고 예측을 골라 당일 아침 경보 성능이라고 쓰지 않는다.

시작보다 얼마나 빨랐는지는 상대적인 기록 경계로만 표현한다. 다음 한 시간 최대 예측만으로 정확한 60분 선행 경고나 15분 칸 시작 전 특정 분의 조치 여유를 입증하지 않는다.

## 7. Q3: 목적별 정책을 어떻게 선택하는가

주 비교는 개발 2시간 예산에서 고정한 c의 이후 결과다. 기존 모델보다 시작 전 포착이 높더라도 이후 실제 경고 부담이 증가했다면 두 변화가 함께 생겼다고 기록한다. 경보 부담·정밀도·일최대 부족량·월별 결과 중 손실을 숨기지 않는다.

정책 선택은 다음과 같이 남긴다.

- 같은 개발 부담에서 이후 시작 전 포착이 개선되고 경보 부담도 비슷하면 피크 점검 후보로 채택할 근거가 있다.
- 포착과 부담이 함께 늘면 선택 가능한 교환관계로 제시한다. 특정 경보 예산을 운영 최적값으로 확정하지 않는다.
- 한 달·몇 사건에만 개선이 있으면 사례 수준으로 좁히고 보편적 개선으로 채택하지 않는다.
- 이득이 없으면 기존 HGB 또는 단순 기준선 정책을 유지한다. c·묶음 규칙을 시험 결과에 맞춰 반복 조정하지 않는다.

필요할 때만 연구용 상대 손실 `r×FN+FP`를 r=1·2·5 등 실행 전 고정한 값으로 비교한다. 이는 시간 단위 놓침과 오경보의 상대 중요도 가정이며 원화가 아니다. 사건 단위 손실과 시간 단위 손실을 합산하지 않는다. r을 바꾸면 선택이 달라진다는 사실 자체를 보고한다.

## 8. 사용자에게 보여 줄 출력과 활용 범위

예정 출력 항목은 예측 발행 기준 기록, 목표 기록, 평균·최대 점예측, 연구용 기준과 경고 상태, 예측 불가 사유다. 모델·정책 버전과 평가 한계는 보고서에 남긴다. 화면이 필요해지면 기본 흐름은 위험 시간 확인과 점검 우선순위로 제한한다.

q75는 75% 분위수 값이지 고부하 확률 75%가 아니다. 확률·예측구간을 출력하려면 별도 검증이 필요하다. 현재 경고 플래그를 안전 보증으로 표현하지 않는다.

A047에는 실제 경보 성능을 넘기고, A045의 재배치 수치를 AI가 달성한 효과로 귀속하지 않는다. 예측은 점검할 기록을, 시나리오는 가정상 이동 필요량·최대 변화 범위를 설명한다. 현재 데이터에는 일정·가동 조정의 관측 결과가 없어 실제 절감액·생산성 향상은 검증할 수 없다.

## 9. 조건부 여러 시간 예측

일정 이동 후보의 순위를 직접 비교하려는 경우에만 별도 작업을 시작한다. 같은 결정 시점에서 모든 후보 시간의 부하를 예측하고, 필요한 수평선·목표·학습·평가·미래 입력 가용성을 다시 정의한다. 현재 한 시간 순차 예측들을 이어 붙인 경로와 구분한다.

해당 기능을 만들지 않아도 다음 시간 경보와 가정별 저감 제안으로 현재 핵심 과제를 마무리할 수 있다. 여러 시간 모델·새 최적화 알고리즘은 이번 계획의 필수 목록이 아니다.

## 12. 개발에서 고정한 정책

작은 검증 사례를 먼저 통과한 뒤 **2026-09-29T17:11:59+09:00**에 개발 예측만으로 c를 저장했다. [frozen](../tables/09.29_007_frozen.json)의 `created_at`이 이 시각을 보존한다. 이후 평가 집계는 이 파일을 읽었으며 기준을 다시 고르지 않았다. 선택 함수에는 실제값·사건·포착률을 전달하지 않는다.

후보 c는 개발의 서로 다른 예측 점수와 최댓값 바로 위의 경보 없음 경계다. `prediction≥c`로 같은 점수 전체를 켜고, 공통 예측 61일에서 예산 이하인 가장 많은 경고 시간을 선택했다. 같은 플래그를 만드는 후보 경계 중 가장 높은 c를 고정했다. 표의 c는 표시용 반올림이며 코드와 JSON은 전체 정밀도를 쓴다.

| 후보 | 1시간 예산 c / 달성 시간·시간/일 | 2시간 예산 c / 달성 시간·시간/일 | 4시간 예산 c / 달성 시간·시간/일 |
|---|---|---|---|

세 AI 후보의 개발 원시 부담은 동일하다. lag1은 동률로 예산에 못 미쳤으므로 정확히 같은 부담이라고 부르지 않는다. 예산은 날짜당 **평균** 연구 경고 시간이고 일별 상한이 아니다. 2시간을 주 비교로 유지했다.

첫 true 플래그에서 새 알림을 발행하고, 정확히 다음 시간도 true면 같은 묶음을 유지한다. false·기록 공백·예측 불가에서 끊으며 날짜·월 경계는 유지한다. 개발과 이후 기간의 시작에서는 상태를 초기화한다. 냉각시간·히스테리시스·추가 확인 규칙을 넣지 않았다. 이번 기본 규칙의 활성 시간은 true 대상 기록마다 한 시간인 **명목 기록 시간**이므로 원시 경고 시간과 같다. 물리적 앱 가동 시간이나 현장 조치 시간을 측정한 값이 아니다.

실제 높은 대상 기록이 하나도 없는 경보 묶음을 관측상 잘못된 묶음으로 세었다. 비경고로 끝난 완결 묶음과 공백·비가용·평가 끝에서 잘린 묶음을 나눴다. 이후 정책 12개에서 잘못된 묶음은 모두 비경고로 끝났고 잘린 잘못된 묶음은 0개다. 월별 묶음 수와 길이는 **첫 알림이 발생한 월**에 귀속하며 원시 시간은 해당 목표 월에 귀속한다.

## 18. A047에 넘길 근거와 활용 문장

Analysis 문서는 직접 수정하지 않았다. 다음 표와 문장을 A047에 전달할 수 있다.

| 활용 주장 | M007 근거 | 같이 밝혀야 할 한계 |
|---|---|---|
| 다음 기록의 피크 점검 우선순위 | 주 정책 47→54건 사전 포착, 경고 184→209시간·새 알림 67→76회 | 실제 일정·가동 조정이나 절감효과 검증 아님 |
| 관측 공백과 서비스 상태 표시 | 정상 1,440→가용 1,344시간, 시작 불가 9사건 | 비가용을 낮은 위험·안전 상태로 표시하지 않음 |
| 발생 후 감지와 시작 경고 구분 | 혼합 46건 사전·17건 지연, HGB 47건 사전·5건 지연 | 지연 포착을 사전 예방으로 합산하지 않음 |
| 피크 크기 오차와 경보의 차이 | q75 일최대 부족량 10.83, 높은 날 25/32 하나라도 포착 | c를 조정해도 크기 오차를 수정한 것은 아님 |
| 월최대 점검 사례 | 8월 11일 q75 경고, 다른 후보 비경고 | 네 월 사례이며 보편적 보장 아님 |

사용 가능한 문장: "완료된 직전 전력 기록으로 다음 한 시간의 최대값을 예상하고 점검할 기록을 선별했다. 개발에서 평균 2시간/일의 연구 경보 예산으로 기준을 고정한 q75 정책은 이후 시작 평가 가능한 76사건 중 54건을 시작 전에 경고했다. 기존 HGB의 47건보다 많았지만 원시 경고는 184에서 209시간, 새 알림은 67에서 76회로 늘었다. 정상 96시간과 사건 시작 9건에는 예측이 없어 별도 불가 상태로 남겼다."

시나리오 연결 문장: "예측 경보는 다음 기록을 점검할 우선순위를 제공하고, A045의 시나리오는 이동량·이동 가능 시간에 대한 가정 아래 최대값이 달라질 수 있는 범위를 설명한다. 서로 다른 시점의 한 시간 예측을 하루 사전 일정으로 합치거나 시나리오 감소를 AI가 실제 달성한 절감효과로 귀속하지 않는다."

표시 항목의 근거는 행별 경보에 있다. 직전 완료 기록 기준·목표 기록·최대 점예측·u/c·경고/유지/새 알림·불가 사유·정책 버전을 사용할 수 있다. q75는 **0.75 조건부 분위수 예측값**이며 고부하 확률 75%가 아니다. 실제 단위·계측 전달 지연·현장 허용 부담·설비 원인·실제 조치 효과는 현 자료에서 미식별이다. 실제 전력 0은 보존했고 정상 상태 의미를 추정하지 않았다.
