# 006: 고부하 지속 부족량의 최소 개선 비교

작성·실행: 2026-09-29 | 상태: 동일행 비교·q75 이후 예측·독립 검증 완료, M007 미실행

기본 점예측은 평균·최대 모두 기존 HGB를 유지한다. M005가 선정한 지속 부족량에 맞춘 혼합 후보는 7~8월 부족량을 13.20→6.87로 줄였지만 하강 과대량을 4.29→18.27로 높였다. 개발 두 달의 전체 MAE도 악화해 기본 모델 교체 조건을 충족하지 못했다. 혼합과 기존 q75는 M007의 피크 대응 비교 후보로만 보존한다.

실행은 [M005 14절](09.29_005_peak_error_audit_plan.md#14-m006-선정과-바로-실행할-조건)과 [인계 설정](../tables/09.29_005_m006_handoff.json)을 따랐다. 최대 목표의 직전 고부하 조건 혼합 한 가지를 비교했고, q75는 M002 개발 예측을 재사용한 뒤 빠져 있던 7~8월 예측만 생성했다. 아래 1~7절은 사전 계획이며 실제 고정 조건·결과·판정은 9~15절에 있다. 다른 특징·모델 분기는 실행하지 않았다.

## 1. 왜 새 모델 종류보다 실패 대상이 먼저인가

기존 M001은 전체 오차를 줄였지만 고부하 지속과 0 기록에서 약했다. M002의 q75는 개발 구간 부족량을 일부 줄였지만 전체 최대 MAE를 5.27→6.17로 높였다. M003의 생산량·날씨 추가는 월별·고부하 개선이 유지되지 않았다. 따라서 이번 질문은 **M005에서 확인한 주 실패를, 같은 정보 시점·같은 평가행에서 개선 하나로 줄일 수 있는가**다.

M005가 필요한 실패를 특정하지 못하면 새 학습을 생략하고 기존 HGB·직전값·기존 q75 결과로 경보 평가를 진행한다. 모델 종류 수를 늘리는 것 자체는 완료 기준이 아니다.

## 2. 기본 비교군과 변경 통제

| 비교군 | 입력·학습 | 역할 |
|---|---|---|
| lag1 | 직전 실제 목표값 | 필수 단순 기준선 |
| lag24·lag168 | 정확히 전날·전주 같은 시각 | 저장 결과 재사용, 동일 적격 행에서 보조 비교 |
| 기존 HGB 전력+달력 | M001 설정·특징 유지 | 필수 AI 비교군 |
| 기존 q75 HGB | M002의 0.75·동일 트리 설정 | 피크 부족량과 과대량의 교환관계 후보 |
| 질문에 맞춘 개선 1개 | 아래 분기에서 하나만 선택 | 이번 실험의 주 변경 |

Ridge 등의 기존 결과는 배경 비교로 유지하되 모든 후보를 다시 학습할 필요는 없다. 목표 actual·평가행·학습 종료·전처리·음수 예측 0 제한·모델 갱신 정책을 맞춘다. 후보가 짧은 시차를 써 표본이 늘면 공통행 성능과 추가 커버리지를 별도 표로 나눈다.

## 3. 개발·확인 설계

기본은 기존 분할을 유지한다. 1~4월→5월, 1~5월→6월에서 최소 후보를 비교하고 설정을 기록한다. 이후 1~6월 학습 모델로 7월·8월을 각각 평가한다. 기존 M001은 6월까지 학습한 모델에 평가 중 과거 관측만 갱신한 것이므로, 이번에도 7월을 다시 학습에 넣는 정책과 섞지 않는다.

7~8월 실패를 이미 보고 후보를 설계했으므로 이 결과는 탐색적 후속 검증이다. q75의 7~8월 예측이 필요하면 해당 구간 이전 학습으로 새로 생성하고 M002의 개발 성능을 이후 성능으로 전용하지 않는다. 전체 변환·결측 처리·새 특징 경계·가중치·FA를 쓰는 경우 적합은 해당 학습구간 안에서 수행한다.

사건 기준은 5·6월 각각의 학습구간 기존 기준과 7~8월의 기존 182를 보존한다. 모델별로 정답 사건 기준을 다르게 만들지 않는다. 경보 기준 선택은 M007으로 넘긴다.

9월 확인은 모델과 경보 정책을 고정한 후 필요한 경우 한 번 실시한다. 그때 9월 목표에 정확히 연결되는 과거 기록만 사용하고 공통행 수를 새로 기록한다. 9월은 이미 EDA에 노출된 14일이므로 독립 시험으로 부르지 않는다. 결과를 보고 설정을 바꾸면 해당 기간도 개발 이력에 포함한다.

## 4. 주 개선 후보를 고르는 분기

| M005의 근거 | 선택 가능한 최소 변경 | 반드시 함께 볼 반대 효과 |
|---|---|---|
| 시작 부족량이 일최대 누락의 주요 부분 | 직전 S 한 특징 추가. D 명시 표현은 E025가 필요성을 보일 때 대안 하나로 선택 | 일반·지속 성능, 소표본 시간대 의존 |
| 과거 고부하 뒤 체계적 과소예측 | 과거 상태에서 기존 HGB와 lag1의 단순 혼합 | 고부하 뒤 하강·0의 과대예측 |
| 모든 고부하에서 부족량 관리가 핵심 | 기존 q75를 우선 평가, 필요할 때 단순 편향 보정 하나 | 일반 과대량, 전체 MAE, 실제 분위수 포함 비율 |
| 공백 이후 입력 부족으로 피크 평가 누락 | 이용 가능한 lag1 대체 또는 짧은 시차 모델 하나 | 더 넓은 범위에서의 실제 오류·경보 증가 |
| exact unseen 프로필에서만 악화 | 학습 내부 프로필 가중 비교를 별도 주 후보로 선택할 근거 검토 | 날짜 빈도가 반영된 전체 성능 손실 |

위 행을 모두 실행하지 않는다. 선택 이유와 선택하지 않은 후보의 보류 이유를 실행 설정에 기록한다. 새로운 실패가 확인돼 추가 실험이 필요하면 별도 회차·변경 이유를 적고 같은 시험 점수에 맞춰 무제한 탐색하지 않는다.

### 과거 상태 혼합의 구체적 후보

지속 편향을 주 문제로 선택한 경우 예시 기본안은 직전 최대가 학습 기준 이상일 때 `0.5×HGB + 0.5×lag1`, 그 외에는 HGB다. 0.5는 최적이라고 추정한 값이 아니라 이 계획의 단일 검증 후보다. 실제 다음 시간이 지속인지 하강인지는 분기에 쓰지 않는다. 평균 목표는 기존 모델을 유지하고 최대 목표에만 변경해 효과를 분리할 수 있다.

혼합 비율을 이후 평가 점수로 탐색하지 않는다. 개발에서 개선이 없으면 0.1 단위로 반복 검색하지 않고 이 후보를 폐기한다. 개발 지속 사건이 적으면 그 한계를 기록하고 이후 결과도 탐색 사례로 제한한다.

### 보정 모델을 선택할 경우

평균 예측+최대 차이 보정은 E025 결과가 필요성을 보일 때의 단순 기준모델이다. 정확 평균 예측인지 CSV 평균 예측인지 식을 구분한다. CSV 평균 모델에 더할 상수라면 학습 자료의 `P−CSV평균`으로 MAE 목적의 중앙값 등을 정해 일관되게 적용한다. 정확 평균 D를 그대로 더해 정의를 섞지 않는다.

편향 보정은 학습 내 적합 잔차를 이후 성능처럼 쓰지 않는다. 앞선 시간순 개발 예측의 잔차로 보정을 정한다면 그 개발 구간 점수는 보정 선택 점수로 표시하고, 같은 행을 독립 검증처럼 재평가하지 않는다. 자료를 더 쪼갤 경우 학습→보정→평가의 순서를 명시한다.

## 5. 입력 금지와 중복 점검

현재 목표 전력, 목표 시간의 생산량·실황 날씨, 공장인원·비용, 미래 하루 프로필·FA, 실제 시작/지속/하강 라벨은 입력에 넣지 않는다. 같은 날짜 전체를 알아야 얻는 상태를 그날 도중 가용하다고 가정하지 않는다.

최대 P와 범위 R는 기존 입력이다. D는 이미 있는 평균·최대의 표현과 중복되며 S는 첫·마지막 칸 정보의 차이를 점검한다. 새 특징과 모델 구조를 동시에 바꾸지 않는다. 생산량·날씨는 현재 새 실패 근거가 없어 기본 후보에서 제외하며 M003 결과를 재사용한다.

## 6. 평가 지표와 채택 기준

공통표에는 월별·전체 MAE/RMSE, 고부하 부족량, 시작·지속·하강의 오차·부족량·과대량, 일최대 동률 시간의 날짜 가중 부족량, 실제 0의 오류, seen/unseen 성능·표본 수를 담는다. 같은 행의 후보−기준 차이를 날짜·주 단위로도 요약한다. 새 특징·손실의 개선을 다른 평가행 구성 효과와 분리한다.

실행 전에 다음 채택 구분을 고정한다.

1. **점예측 기본 모델 대체:** 개발 두 달의 전체 최대 MAE가 각각 악화하지 않고, 주 실패 지표가 합산에서 개선되며, 한 달의 큰 손실로 다른 달의 개선을 상쇄하지 않는지 확인한다. 이후 월에서 재현되지 않으면 안정된 개선이라고 부르지 않는다.
2. **피크 대응 별도 후보:** 전체 MAE가 나빠져도 주 실패의 부족량이 감소하면 후보로 보존할 수 있다. 이 경우 기본 모델을 자동 대체하지 않고 과대량·경보 부담을 M007에서 비교한다.
3. **폐기 또는 근거 부족:** 주 실패 개선이 없거나 소수 날짜에만 의존하면 폐기한다. 두 후보의 장단점이 갈리면 하나를 무조건 최적이라고 정하지 않고 목적별 선택을 남긴다.

모든 지표를 통과할 때까지 값을 조정하는 계획이 아니다. 비교 전 실질적으로 허용할 수 있는 손실 폭이 필요하면 연구용 가정을 설정에 기록하고 결과를 본 뒤 완화하지 않는다. 실제 비용·운영 허용치가 자료에 없다는 사실은 유지한다.

q75에는 pinball loss와 실제값이 예측 이하인 비율을 월별로 함께 기록한다. q75 출력은 고부하 확률이 아니며, 포함 비율이 모든 조건에서 75%일 것이라고 보장하지 않는다.

## 7. 산출물 계약과 재현

실행 위치는 `modeling/jsw`. 코드는 `scripts/09.29_006_targeted_models.py`, 설정은 `tables/09.29_006_frozen.json`, 행별 예측은 `predictions/09.29_006_{development,review}_predictions.csv`, 비교표는 `tables/09.29_006_{scores,paired_differences,coverage,selection}.csv`다. q75의 6월 말 학습 모델은 joblib로 저장하고 라이브러리 버전·학습 종료와 특징 순서를 기록했다. 파일 링크는 15절에 있다.

행별 예측에는 모델·target·record_key·학습 종료·실제값·예측값·원본 행 키·평가 구간·입력 가능 여부를 남긴다. 예측 정책이 달라지면 명확한 policy_id로 구분한다. 실행 전후 원본·기존 설정·기존 예측의 보존을 확인한다.

검증은 작은 기간의 입력 시간 관계와 기존 모델 예측 재현부터 시작한다. 학습 목표가 평가 기간에 들어가지 않는지, 스케일러·보정이 미래를 보지 않는지, 공통행이 정확히 일치하는지, 0·불가 표본·음수 처리 기준이 방법 간 같은지 확인한다. 정규 Python 3.13의 실제 종료 코드와 패키지 버전을 기록한다.

E025 Q1·Q2는 완료됐고 평균·최대 정의 유지와 기존 P·R·마지막 칸의 중복 판단만 참고했다. 주 실패가 시작 부족량이 아니므로 S 추가 조건에 해당하지 않는다. D 표현·평균+상수 보정·당일 프로필·FA·생산량·날씨 추가도 이번 후보에 필요 없어 실행하지 않았다. 실제 다음 상태·일최대·생산 기록·하루 프로필은 예측이 고정된 뒤 진단에만 사용했다.

## 12. q75의 포함 비율과 변경 없는 기준의 경보 진단

[선정표](../tables/09.29_006_selection.csv)의 기준은 결과를 본 뒤 완화하지 않았다.

| 최대 기본 | HGB 유지 | 혼합·q75 모두 개발 두 달의 전체 MAE 비악화 조건 실패 |

주 실패 감소에는 답을 얻었고, 균형 있는 기본 모델 개선은 확인하지 못했다. 기존 HGB를 유지하며 설정 검색을 종료한다. 혼합과 q75의 이득·손실이 달라 하나를 운영 최적으로 확정하지 않았다. 둘의 목적별 순위는 같은 구간에서 경보 부담을 평가할 M007의 질문으로 남긴다.

기록값의 원단위·실제 0의 현장 의미·운영 허용 손실·설비 원인은 현 자료에서 미식별이다. 입력 불가 96시간·사건 시작 9건, 시작 오류, 0 오류는 이번 혼합으로 해결되지 않았다. 이들을 함께 해결하려고 새로운 특징·fallback·0 분기·월별 갱신을 추가하지 않았다.

## 14. 실행·독립 검증과 변경 범위

정규 CPython 3.13.1, pandas 3.0.1, NumPy 2.2.6, scikit-learn 1.7.1, joblib 1.5.1을 사용했다. 모든 Python 호출은 첫 시도부터 승격된 `Start-Process -Wait -PassThru -NoNewWindow`였고 실제 자식 종료 코드는 설정 저장 0, 첫 비교·q75 학습 0, 보조 기준선 포함 집계 0, 독립 검증 0이다. [실행 사실](../tables/09.29_006_facts.json)과 [독립 검증](../tables/09.29_006_verification.json)에 환경·해시·행 수가 있다.

새 학습은 q75 최대 목표의 6월 말 모델 한 번뿐이다. HGB·기준선·개발 q75는 저장 결과를 재사용했고 혼합은 학습 없는 예측 결합이다. 모델을 저장 후 다시 읽어 같은 예측을 확인했다. 독립 검증은 M006 코드를 가져오지 않고 원본 시간 키로 26개 특징을 따로 복원해 q75의 1,344예측을 대조했다.
