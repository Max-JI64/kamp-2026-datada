# M008 — 생산량 크기·증감별 실제 모델 오류 비교 계획

작성: 2026-09-29 | 상태: 실행·검증 완료 (2026-09-29)

## 1. 이전 근거와 이번 질문

[E003 기준선 분석](../../../EDA/jsw/reports/09.23_003_baselines.md)은 생산량 크기와 증가·감소·유지에 따라 단순 예측의 오류가 다름을 확인했다. [M005](09.29_005_peak_error_audit_plan.md)·[M006](09.29_006_targeted_model_plan.md)은 실제 HGB 오류를 생산량 0/양수로 비교했지만 크기와 증감까지 이어서 비교하지 않았다. [A048](../../../analysis/jsw/reports/09.29_048_report_scope_gap_audit.md)은 이를 작은 보완 과제로 남겼다.

이번 질문은 두 가지다.

1. 생산량 수준에 따른 기준선의 오류가 HGB에서는 줄었는가? 아직 남는 큰 오류나 편향은 무엇인가?
2. 생산량 증가·감소·유지 구간에서 HGB의 개선과 손실은 어떻게 다른가?

**저장된 예측을 재집계하는 사후 오류 진단**이다. 목표 시각 생산량을 새로운 예측 입력이나 모델 분기에 넣지 않는다. 새 모델 학습·경보 평가·F점수 선택·미관측 원인 추정은 범위에 포함하지 않는다.

## 3. 실행 전에 고정할 비교 조건

### 기간·목표·공통행

- 주 기간은 2021년 7~8월이다. 이미 탐색한 이후 평가 구간이며 새로운 독립 시험이라고 부르지 않는다.
- 평균과 최대 목표는 분리한다. 저장 평균을 정확 산술평균으로 바꾸지 않는다.
- 각 목표에서 네 방법 모두 예측 가능한 동일 원본 키의 교집합을 주 비교로 사용한다. 기존 공통 비교의 1,344시간과 일치하는지 확인하되, 다르면 숫자를 맞추려고 삭제하지 말고 차이를 진단한다.
- 원본 키×목표×방법의 유일성, 방법 간 actual 일치, 생산량 일치를 확인한다. 방법별 행 수를 독립 관측 수로 합산하지 않는다.
- 실제 전력 0·생산량 0·입력 불가를 구분한다. 오류가 크다는 이유로 제외하지 않는다. 예측 불가 시간은 공통행 밖 분모로 기록한다.

### 생산량 크기

| 그룹 | 정의 |
|---|---|
| zero | 생산량 = 0 |
| positive_low | 0 < 생산량 ≤ 487 |
| positive_high | 생산량 > 487 |
| unknown | 기록 누락 등 위 정의에 해당하지 않는 경우. 발생 시 이유를 명시 |

487은 E003에서 정한 1~6월 양수 생산량 중앙값이다. 이번 7~8월 진단에서도 고정 재사용하며, 이후 성능을 보고 구간을 다시 고르지 않는다. 이를 5~6월 개발 규칙으로 소급 적용하는 작업은 하지 않는다. 예상 밖 음수 기록 등이 있으면 자동으로 양수 구간에 넣지 말고 확인한다.

### 생산량 증감

`production_delta(t) = production(t) - production(t - 1시간)`

- 정확히 한 시간 전의 유효한 원본 기록과 연결한다. 단순 이전 행·앞 행 채우기를 쓰지 않는다.
- 증가: delta > 0, 감소: delta < 0, 유지: delta = 0. 직전 기록이 없거나 값이 유효하지 않으면 unknown으로 남긴다.
- 평가 첫 시점의 직전값은 필요하면 6월 말 원본에서 읽는다. 날짜가 달라졌다는 이유로 연결을 끊지 않는다.
- 직전 생산량은 ‘예측 공통행 안의 직전 행’이 아니라 전체 유효 원본에서 가져온다. 모델 입력 누락 때문에 실제 존재하는 직전 생산 기록까지 없애지 않는다.
- 증감 그룹은 0→양수·양수→0뿐 아니라 양수 안의 증감도 포함한다. A003의 생산 전환 비교와 같은 정의로 부르지 않는다.

생산량 수준과 증감은 별도의 두 집계다. 처음부터 월×시간×수준×증감을 교차해 작은 집단을 만들지 않는다.

## 4. 집계와 판단 순서

1. **기준 재현:** 선택한 공통행의 방법별 전체 MAE가 같은 범위의 기존 M006 결과와 맞는지 확인한다. 범위가 다르면 먼저 분모를 설명한다.
2. **크기별 비교:** 목표×방법×생산량 수준별 표본 수·날짜 수·MAE·평균오차를 집계한다.
3. **증감별 비교:** 같은 지표를 증가·감소·유지·unknown별로 집계한다. unknown을 조용히 제외하지 않는다.
4. **동일행 개선:** 각 기준선과 HGB의 `MAE 차이 = HGB MAE - 기준선 MAE`를 계산한다. 음수는 HGB 개선, 양수는 악화다. HGB 대 lag1을 기본 설명으로 하고 전일·전주 비교를 함께 보존한다. 유리한 기준선만 골라 보고하지 않는다.
5. **월별 확인:** 같은 두 집계를 7월·8월로 나눠 개선 방향이 같은지 확인한다. 풀링 결과가 한 달에 의존하면 그 사실을 보고한다.
6. **해석:** 개선이 남는 조건, 절대오차가 큰 조건, 과소·과대 방향이 남는 조건을 구분해 본문 후보 문장 2~3개로 압축한다.

오차는 `prediction - actual`로 통일한다. 양수 편향은 과대예측, 음수 편향은 과소예측이다. 평균오차는 양·음 오차가 상쇄될 수 있으므로 MAE와 함께 해석한다.

최대 목표의 과소예측을 설명할 필요가 있을 때만 `mean(max(actual - prediction, 0))`을 추가한다. 이 지표는 과대·정확 예측 행의 0도 분모에 포함하며, 과소예측 행만의 평균과 구별한다. RMSE·MAPE·상관·유의성 검정을 형식적으로 모두 추가하지 않는다.

## 9. 실행 결과 — 7~8월 저장 예측 재집계

### 9.1 평가행과 재현

고정한 4방법의 교집합은 **1,344시간·56일**이다(7월 600시간·25일, 8월 744시간·31일). 정상 1,440시간 중 7월 96시간은 입력 불가로 공통행 밖에 남겼다. 평균과 최대는 같은 원본 키를 사용했고, 목표별 `actual`, 원본 행 번호와 생산 기록을 원본 CSV와 대조했다. 목표 시각 생산량은 사후 그룹 분류에만 사용했다.

487 고정 경계의 크기별 행 수는 0 **612**, 양수·487 이하 **360**, 487 초과 **372**다. 정확히 한 시간 전의 전체 유효 원본 기록과 연결한 증감별 행 수는 증가 **414**, 감소 **364**, 유지 **566**, 미식별 **0**이다. 두 분류는 각각 1,344시간을 빠짐없이 나누며 서로 합산하는 집단이 아니다. 같은 행의 네 방법을 네 관측으로 세지 않았다.

전체 MAE는 평균 목표에서 HGB **6.896**·lag1 **13.612**, 최대 목표에서 HGB **7.915**·lag1 **12.678**이다. M006 월별 점수(7월 600, 8월 744)와 일치하며, E003의 직전·전일·전주 기준선 및 M005의 0/양수 집계도 원수치 허용오차 `1e-9` 안에서 재현했다. 7~8월은 이미 탐색한 이후 평가 구간이다.

### 9.2 생산량 크기와 증감

아래 MAE와 편향은 같은 행에서 계산했다. 편향은 `예측−실제`라서 음수는 과소예측이며, ΔMAE는 `HGB−lag1`이라서 음수는 HGB 개선이다. 날짜 수는 각 조건이 나타난 서로 다른 날짜 수다. 전력과 생산량은 원본 수치 단위로 적는다.

| 목표 | 분류·조건 | 시간 / 날짜 | HGB MAE | HGB 편향 | lag1 MAE | ΔMAE |
|---|---|---:|---:|---:|---:|---:|
| 평균 | 크기·0 | 612 / 48 | 4.98 | +3.42 | 4.76 | +0.21 |
| 평균 | 크기·(0, 487] | 360 / 40 | 6.43 | +0.02 | 18.53 | -12.09 |
| 평균 | 크기·487 초과 | 372 / 39 | 10.50 | -5.24 | 23.42 | -12.92 |
| 평균 | 증감·증가 | 414 / 40 | 8.87 | -3.54 | 21.20 | -12.33 |
| 평균 | 증감·감소 | 364 / 40 | 8.03 | -0.85 | 22.77 | -14.75 |
| 평균 | 증감·유지 | 566 / 37 | 4.72 | +3.39 | 2.17 | +2.55 |
| 최대 | 크기·0 | 612 / 48 | 6.55 | +4.08 | 6.60 | -0.06 |

| 최대 | 크기·487 초과 | 372 / 39 | 11.13 | -5.42 | 18.98 | -7.85 |

양수 생산량과 증가·감소에서는 평균·최대 모두 HGB가 직전값보다 낮은 MAE를 보인다. 다만 487 초과에서 HGB의 절대 MAE가 가장 크고 편향은 평균 **-5.24**, 최대 **-5.42**로 과소 방향이다. 즉, 상대 개선이 남는 조건과 잔여 실패 조건이 같다. 유지 구간은 직전값이 특히 정확해서 HGB가 평균 **+2.55**, 최대 **+2.37**만큼 불리하다. 0 생산량의 통합 차이는 평균 **+0.21**, 최대 **-0.06**으로 작아 우열을 단정하기 어렵다.

전일·전주 기준선도 같은 행에서 모두 보존했다. 전일 대비 통합 조건 12개 모두 HGB MAE가 낮았다. 전주 대비 통합 조건 12개도 낮지만, 7월만 보면 생산량 0·유지에서 HGB가 평균·최대 모두 조금 불리하다(ΔMAE 각각 0 생산량 **+0.09/+0.42**, 유지 **+0.17/+0.62**). 8월에는 이 네 비교를 포함한 모든 조건에서 HGB가 전주보다 낮았다. ### 9.4 해석·검증·종료

보고서에는 HGB가 생산량 증가·감소와 양수 구간에서 직전값보다 오류를 줄였고, 이 방향이 두 달에 걸쳐 유지됐다고 쓸 수 있다. 다만 487 초과에서는 평균·최대의 큰 MAE와 과소 편향이 남았다. 생산량 유지에서는 직전값이 더 정확했고, 0 구간의 우열은 월과 날짜 구성에 민감했다. 이 사후 비교만으로 생산량의 인과효과나 목표 시각 생산량의 예측 시점 가용성을 말할 수는 없다.

첫 집계 시도는 M006 점수표의 숫자 월과 문자 기간이 섞인 `period` 열을 문자열로 비교하지 않아 검증에서 종료 1이었다. 기간 비교만 고쳤다. 추가한 E003 직접 대조의 첫 시도도 기존 `unchanged`와 이번 `same`의 이름 차이로 종료 1이었고, 명칭 대응만 고쳤다. 고정 조건·입력·예측값·집계식은 유지했으며 최종 `--phase run`의 실제 자식 종료 **0**을 확인했다. 원본 키 유일성·원본 행/목표값/생산량 일치, exact-hour 결합, 그룹 전수, 방법별 공통행, 가중 MAE·편향 재구성, E003 생산조건 36행, M005 0/양수 및 M006 월 점수를 검사했다. 검증 내용과 입력 해시는 [verification](../tables/09.29_008_verification.json)에 있다. 코드는 [M008 집계 스크립트](../scripts/09.29_008_production_error_comparison.py), 고정 정의는 [frozen](../tables/09.29_008_frozen.json)에 둔다. 새 학습·예측 생성·경보 설정 변경은 없었다.

재현은 `modeling/jsw`에서 정규 CPython 3.13으로 `scripts/09.29_008_production_error_comparison.py --phase run`을 실행한다. 이번 실행은 첫 시도부터 승격된 `Start-Process -Wait -PassThru -NoNewWindow`로 진행했고, 이미 존재하는 `frozen.json`을 다시 쓰지 않았다.

M008 두 질문은 현재 7~8월 자료 범위에서 답했다. 조건별 오차 차이만으로 원인을 식별하지 않으며, 원단위·계측 지연·실제 조정 가능성과 운영 효과는 현 자료에서 미식별이다. 새 임계값 탐색이나 모델 학습으로 이어가지 않는다. 이번 결과는 기존 기본 HGB 유지 판단의 적용 범위와 손실 조건을 설명하는 보완 근거로 넘긴다.
