# 005: 저장 예측의 피크·사건·평가범위 감사

작성·실행: 2026-09-29 | 상태: Q1~Q4 집계·독립 검증 완료, 새 학습·예측 생성 없음

M006의 주 개선 질문은 **고부하 지속 구간의 과소예측을 과거 정보만으로 줄일 수 있는가**로 선정했다. 기존 HGB를 유지한 상태에서 단일 혼합 후보를 비교하도록 넘긴다. 이번에 후보의 예측을 만들거나 M006을 실행하지 않았다. 실행 결과와 선정 근거는 10~15절, 기계가 읽을 실행 조건은 [M006 인계 설정](../tables/09.29_005_m006_handoff.json)에 있다. 1~8절은 실행 전에 정한 감사 계약이다.

## 1. 이전 결과에서 생긴 질문

[M001](09.26_001_power_models.md)의 7~8월 1,344시간에서 전력·달력 HGB의 전체 최대 MAE는 7.91로 직전값 12.68보다 낮았다. 그러나 고부하 지속 119시간에서는 13.38로 직전값 6.95보다 나빴고 111시간 과소예측이었다. 시작 76시간은 39.86→15.79로 개선됐지만 여전히 큰 오차가 남았다. 실제 0인 17시간의 최대 MAE는 2.76→23.12로 악화됐다.

[E024](../../../EDA/jsw/reports/09.28_024_guidebook_domain_interpretation.md)는 고전력 빈도와 일·월 최대 위치가 다름을, [A042](../../../analysis/jsw/reports/09.28_042_slot_event_comparison.md)는 시간 사건과 높은 칸의 연속이 다름을 확인했다. 이번에는 **기존 모델의 오류가 실제 최대 기록, 사건 시작, 학습에서 처음 보는 프로필과 어떤 관계인지** 묻는다. 새 모델을 학습하지 않고 저장 예측을 재집계한다.

날짜 표기의 `YYYYMMDD`와 `YYYY-MM-DD`, 예측의 datetime을 명시적으로 변환한다. 행별 예측의 유일 키는 `(stage,target,method,record_key)`다. 서로 다른 방법·목표의 반복 행을 독립 시간으로 세지 않는다. 기준 모델이 M001·M002에 중복돼 있으면 값 일치를 확인하고 한 번만 쓴다. 사건/프로필 결합으로 예측행이 복제되지 않는지 확인한다.

파일만으로 부족한 목표·직전값·시각 적격 정보는 원본 또는 기존 coverage에서 필요한 열만 읽는다. 매번 전체 EDA·모델을 재실행하지 않는다.

## 3. 시간·사건·평가기간 계약

예측은 직전 기록 네 칸이 완료됐다고 놓고 정확히 다음 시간 한 개를 대상으로 한다. actual은 목표 시간의 평균 또는 최대이며, 생산 기록·프로필·일최대 여부는 사후 진단 라벨이다. 이 라벨을 M006 입력으로 넘기지 않는다.

저장된 기존 점수는 저장된 학습구간 임계값을 사용해 먼저 재현한다. 7~8월의 주 기준은 기존 182 이상이다. 개발 5·6월은 해당 학습구간 임계값을 보존한다. A042의 고정 182 사건은 그 기준과 일치하는 비교에만 직접 사용한다. 다른 기준의 사건은 명시한 기준으로 필요한 범위만 묶고 ID에 기준·평가기간을 포함한다.

사건은 정확히 한 시간 간격으로 `P≥u`인 최대 연속 묶음이다. 직전 유효 기록이 없거나 평가 시작 전 상태를 모르면 왼쪽 경계 불명으로 표시한다. 공백 뒤 첫 높은 기록을 자동으로 새 시작 성공/실패에 넣지 않는다. 평가 끝이나 공백에서 진행 중인 사건도 오른쪽 경계 불명으로 표시한다. 시작 직전 기록이 있고 낮다면 시작 평가에 포함할 수 있지만, 끝이 잘렸으면 전체 지속시간 분석에는 완전 사건처럼 쓰지 않는다.

주 집계는 5월·6월·7월·8월을 각각 보고, 합산은 같은 정의임을 확인한 뒤 보조로 제시한다. 9월 새 예측 생성은 이번 M005 범위가 아니다. 개발과 7~8월 모두 사전 분석 이력이 있으므로 탐색적 감사로 명명한다.

## 4. Q1: 최대 발생 시점과 상태별 오류

오차는 `e=prediction−actual`, 부족량은 `max(−e,0)`, 과대량은 `max(e,0)`이다. 각 그룹의 시간 수·날짜 수와 MAE, RMSE, 편향, 과소예측 비율, 0을 포함한 평균 부족량·평균 과대량을 낸다. 부족량 90/95백분위와 큰 오류 사례는 분포 확인용으로 남기고 최악 사례 하나를 대표 성능으로 쓰지 않는다.

| 상태 | 목표·직전 실제 최대의 조건 | 주로 볼 오류 |
|---|---|---|
| 시작 | P≥u, 직전 P<u | 피크 포착·부족량 |
| 지속 | P≥u, 직전 P≥u | 기준선 대비 편향·부족량 |
| 하강 | P<u, 직전 P≥u | 과대량·불필요 경보 |
| 일반 | P<u, 직전 P<u | 전체 정확도·경보 부담 |
| 경계 불명 | 직전 기록 없음 | 분류 불가 수, 점수에서의 처리 |

네 상태는 최대 목표를 기준으로 나눈다. 평균 목표 점수를 같은 상태에서 볼 수 있지만 그 라벨이 평균 임계값으로 정의됐다고 쓰지 않는다. 실제 0은 일반/하강과 겹칠 수 있는 별도 감사 표로 두고, 상태 합계에 중복 더하지 않는다. 생산량 0/양수별 오류도 사후 기록 조건으로만 요약하고 두 조건의 시간·날짜 수를 적는다.

일최대는 E024의 원래 하루 전체 정상 기록에서 정한 위치를 사용한다. 모델 적격 행만으로 새로운 일최대를 정하면 원래 피크를 놓칠 수 있다. 네 칸에서 같은 최대가 반복된 한 시간은 한 시간으로 중복 제거한다. 같은 날 여러 시간이 동률이면 모든 동률 시간 점수와 날짜별 동률 시간의 평균 부족량을 함께 낸다. 날짜별 평균을 다시 평균해 동률 많은 날의 가중이 커지지 않도록 한다. 하루 중 어떤 피크라도 포착/모든 피크 시간 포착은 별도 정의로 구분한다.

월최대는 사례별 actual·prediction·부족량·입력 가능 여부를 나열한다. 몇 개 월의 결과를 대규모 독립 검증으로 해석하지 않는다.

## 5. Q2: 사건을 시작 전에 경고했는가

우선 기존 예측에 `prediction≥u`를 적용한 변경 없는 기준을 감사한다. 최적 경보 기준 선택은 M007의 책임이다.

사건 시작 기록 s를 예측한 값이 s 직전 완료 기록 뒤 발행됐고 기준을 넘으면 `시작 전 경고`다. 시작 이후의 기록을 대상으로 한 경고만 있으면 `뒤늦은 포착`, 없으면 `완전 누락`이다. 첫 기록을 예측할 입력이 없으면 `시작 평가 불가`로 따로 세고, 지연 포착 여부는 별도로 남긴다. 가능한 경우 기록 단위의 첫 포착 지연을 계산하되 실제 계측 전달 지연을 안다고 가정하지 않는다.

시간 사건의 경고를 칸 사건 하나하나의 예고로 복제하지 않는다. 사건별로 시작·끝·길이·최대, 시작 전 경고, 첫 경고 대상 시각, 입력 부족, 소속 날짜·프로필을 남긴다. 예측 대상 시간의 실제값으로 경보 시점을 소급해 만들지 않는다.

## 6. Q3: 평가에서 빠진 피크가 있는가

전체 정상 대상→직전 연결→모델 특징 확보→모든 방법 공통 행의 수를 구분한다. 기존 7~8월 정상 1,440시간과 M001 평가 1,344시간의 차이는 coverage 규칙에서 설명하고, 새로운 숫자는 실행 후 확정한다.

월·날짜별 예측 가능률, 원래 일최대 중 예측 가능한 시간 비율, 시작 평가 가능 사건 비율을 낸다. 입력 부족으로 빠진 피크를 맞힌 것으로 세거나 단순 오경보/미탐지 점수에서 감추지 않는다. 주 성능은 공통 적격 행, 서비스 범위는 전체 대상의 예측 가능/불가로 함께 제시한다. 짧은 시차 대체 정책이 필요하면 M006의 별도 후보로 넘기며 이번 감사에서 새 예측을 만들지 않는다.

## 7. Q4: 학습에 없는 프로필에서도 개선이 남는가

각 학습 종료일 이전의 완전한 날짜만 사용해 96값 전력 프로필 목록을 만든다. 기존 profile_id를 쓸 경우 동일 ID가 동일 원값임을 대조하고, 전체 기간의 profile_days 같은 미래 빈도를 학습 여부·가중치에 쓰지 않는다.

`학습에서 관측한 프로필`과 `학습 적격 표본에 실제 기여한 프로필`을 구분한다. 주 점수의 seen/unseen은 실제 학습에 기여한 날짜의 프로필을 기준으로 한다. 해당 날짜의 하루 전체 형태를 학습 입력으로 사용했다는 뜻은 아니다. 불완전 날짜·프로필 대응 실패는 unknown으로 남긴다.

월×seen/unseen에서 방법별 시간·날짜·프로필 수, MAE·고부하 부족량을 비교한다. 처음 보는 프로필에서 나쁘면 월 변화와도 겹치는지 확인한다. 시간순 분할을 유지하며 평가 프로필을 보고 학습 날짜를 삭제하지 않는다.

핵심 개선 차이에 한해 날짜·주별 짝지은 오차 차이, 한 주 제외 민감도를 확인한다. 같은 프로필이 여러 주에 남을 수 있으므로 이를 독립 모집단 신뢰구간으로 부르지 않는다. 최근접 프로필 거리·학습 중복 가중 실험은 exact seen/unseen 결과만으로 설명이 부족할 때 M006 이후 별도 질문으로 남긴다.

## 8. M006에 넘길 결정

후보를 다음 기준으로 우선순위화한다: 실제 일최대·사건 시작 포착에 미치는 영향, 부족량 크기, 여러 날짜·월에 걸친 반복 여부, 과거 정보만으로 개선을 시도할 수 있는지. 빈도만 많은 작은 오차가 큰 피크 오류를 가리지 않도록 한다.

시작 형태, 지속 편향, 하강 과대예측, 입력 부족 중 **주 개선 질문 하나**를 선정한다. 근거표·영향 표본·기준선·해당 판단을 바꿀 수 있는 최소 실험을 기록한다. 어떤 후보도 충분히 뒷받침되지 않으면 기존 모델을 유지하고 M007로 넘어갈 수 있다.

## 9. 실제 산출물·검증·완료 체크

실행 위치는 `modeling/jsw`다. [감사 코드](../scripts/09.29_005_peak_error_audit.py)는 저장 예측을 읽고 기존 점수를 재현한 뒤 추가 집계만 수행한다. 학습 코드나 추론 함수를 호출하지 않는다. [실행 설정](../tables/09.29_005_frozen.json)은 추가 집계 전에 입력 해시·기간·정의·가중 계약을 기록했다. [facts](../tables/09.29_005_facts.json), [독립 검증 코드](../scripts/09.29_005_verify.py), [검증 결과](../tables/09.29_005_verification.json)를 함께 남겼다.

M001의 전체·월·시간·기존 상태·0 및 개발 상태 표, M002 교환관계, M004 전체·월·시작·지속 선별을 포함한 기존 12표를 재현했다. [재현 차이](../tables/09.29_005_reproduction.csv)는 그룹 키·분모가 같고 수치 차이가 허용 오차 1e-9 이하다. M002에 중복 저장된 HGB 1,464행은 값 일치 후 제거했다. 원본 실제값·행 키, 공통 적격 시각, 결합 전후 행 수, 상태 합계, 사건 시간 연결, 일최대 동률 중복 제거, 불가 사례 보존, 과거 프로필 구성도 검증했다.

[날짜·주별 짝지은 차이](../tables/09.29_005_paired_differences.csv)와 [한 주 제외 민감도](../tables/09.29_005_week_sensitivity.csv)는 HGB−lag1을 계산했다. 7~8월 전체 MAE 차이는 한 주 제외 10가지 모두 −6.22~−4.21이다. 지속이 있는 9주를 하나씩 제외한 MAE 차이는 +3.71~+7.27, 평균 부족량 차이는 +7.65~+11.39로 악화 방향이 유지됐다. 시작 MAE 개선도 −25.98~−21.74로 남았다. 같은 프로필이 여러 주에 남을 수 있으므로 독립 모집단의 신뢰구간으로 부르지 않는다.

## 14. M006 선정과 바로 실행할 조건

주 실패는 **고부하 지속의 부족량**으로 정한다. [실패 우선순위 표](../tables/09.29_005_failure_priority.csv)와 [행 진단](../predictions/09.29_005_row_audit.csv)이 근거다. 7~8월 119시간·29일·51사건 중 111시간·27일·49사건에서 과소예측했다. 고부하 전체 195시간의 부족량 합계 2,728.13 중 지속이 1,570.87(57.6%)을 차지한다. 지속에 있는 일최대 18시간·17일도 모두 과소예측했고 부족량 합계는 326.49였다.

시작의 일최대 17시간 부족량 합계 343.50은 지속보다 크고, 8월 11일 월최대 실패도 시작이다. 이번 선택으로 시작 오류가 해결됐다고 보지 않는다. 시작은 기존 HGB의 개선을 유지하면서 M007의 경보 부담으로 평가한다. 지속은 두 달·여러 날짜·한 주 제외에서 lag1보다 나빴고 기존 과거 정보로 단일 후보를 검증할 수 있어 우선 선정했다.

| 항목 | M006에 고정해 넘길 조건 |
|---|---|
| 주 질문 | 과거 고부하 뒤 기존 HGB의 지속 부족량을 줄일 수 있는가 |
| 최소 후보 | 최대 목표만, 직전 실제 최대≥해당 학습 기준이면 `0.5×HGB+0.5×lag1`, 나머지는 HGB. 계수 0.5 하나만 시험. 평균 목표는 기존 결과 유지 |
| 비교군 | M001 HGB·lag1 필수. lag24/lag168은 저장 결과 보조. q75는 5~6월 저장 결과를 비교하고, 7~8월 평가가 필요하면 향후 M006의 학습 승인 범위에서 생성 |
| 분모·기간 | 1~4월→5월 744시간(183), 1~5월→6월 720시간(181). 이후 1~6월 학습을 유지해 7월 600·8월 744시간(182). 7월을 재학습에 넣지 않음 |

입력 범위를 넓히는 lag1 대체, S 특징 추가, 프로필 가중, 0 분기, 월별 재학습은 이번 후보에 더하지 않는다. 입력 누락에는 확인된 영향이 있으나 예측 정확도 변경과 별개다. 0은 2일뿐이어서 그 17시간을 보고 규칙을 조정하지 않는다. 실제 상태·하루 프로필·일최대 라벨·대상 생산량은 사후 평가 열로만 넘긴다.
