# EDA·Analysis·Modeling 이력 재검토와 남은 질문

작성: 2026-09-29 | 범위: 기존 보고서 76개(EDA 25·Analysis 44·Modeling 7)의 질문·결과·후속 연결 검토. 관련 코드와 저장 결과를 대조했으며, 새 통계 계산·학습·경보 기준 선택은 실행하지 않았다.

## 1. 이번 검토의 결론

**추가로 확인할 질문은 있다. 다만 EDA부터 전면 재분석하거나 새 모델을 잔뜩 추가할 필요는 없다.** 보고서의 핵심 주장에 직접 필요한 보완은 다음 두 가지로 좁힌다.

1. **생산량 크기·증감에 따라 최종 모델의 오류가 어떻게 달라지는지 확인한다.** E003은 단순 기준선을 이 조건으로 비교했지만, M005·006의 실제 HGB 진단은 생산량 0/양수까지만 나눈다. ‘생산조건에 따른 예측오차’를 설명하려면 기준선에서 발견한 문제가 HGB에서도 남는지 연결해야 한다.
2. **경보를 보고서에 포함한다면, 어떤 이득·부담을 기준으로 선택할지 대안들을 비교한다.** M007의 경보 예산 비교는 이미 실행됐다. F점수는 사용자가 제시한 아이디어이며 채택된 기준이 아니다. 최소 recall, 최소 precision, 허용 경보량 등과 함께 설명하고 사용자가 선택한다.

EDA·Analysis에서 빠진 핵심은 새 계산보다 **이미 있는 중요한 결과를 보고서 논리에 반영하는 일**이다. 전체 평균이 낮아져도 높은 값의 빈도가 늘어날 수 있다는 A033~037, 생산 전환과 피크의 단순 관계가 조건을 맞추면 달라진다는 A003을 다시 활용해야 한다.

‘고전력 지속에서 왜 낮게 예측하는가’에 대한 입력 지지도 진단 등은 미실행 부분이 남아 있다. 그러나 미실행이라는 이유만으로 필수로 추가하지 않는다. 상세 원인 설명이나 새 개선안을 시도할 때에만 수행한다. 모든 오차의 원인 규명은 이번 프로젝트의 종료 조건이 아니다.

| 언제 높아지고 무엇을 놓치는가? | E024, A030·042, M005·007 | 높은 시간의 빈도, 월최대 위치, 사건 시작, 시간 기록의 연속은 다른 질문이다. 8·13시 시작 집중을 모든 고전력 증가의 설명으로 확대하지 않는다. |

본문은 이 연결을 설명하는 대표 표·그림만 선택한다. 모든 월·모든 조건·FA와 군집 세부 결과는 본문에 넣을 필요가 없다.

## 3. 실제로 보완할 최소 분석

### 3.1 우선: 생산조건별 실제 모델 오류

**이전 근거 → 질문:** E003은 생산량 0, 0 초과~487 이하, 487 초과와 증가·감소·유지 조건에서 기준선의 오류 차이를 확인했다. 487은 당시 1~6월 양수 생산량 중앙값이다. 반면 M005 코드의 `production_scores`와 M006의 `production_condition`은 0/양수 비교다. 생산량 수준과 전환 방향에 따른 기준선의 약점이 HGB에서 줄었는지는 별도로 확인되지 않았다.

**수행할 최소 작업:**

- 저장된 평균·최대 예측에서 HGB와 같은 행에 예측이 있는 기준선을 비교한다. 새 모델은 학습하지 않는다.
- 7~8월 사후 진단에는 E003의 고정 구간을 재사용한다. 생산량 증감은 정확히 한 시간 전 기록과 연결하고 공백은 별도 처리한다. 이 구간을 개발용 규칙으로 소급 적용하지 않는다.
- 생산량 수준별 표와 증가·감소·유지별 표를 각각 만든다. 처음부터 월×시간×생산량×증감을 모두 교차하지 않는다.
- 표본 수, MAE, 부호 있는 평균오차를 기본으로 비교한다. 최대 목표에서 중요한 차이가 있을 때만 과소예측 크기를 덧붙인다. 작은 집단의 차이를 일반화하지 않는다.

**판단 후 조치:** HGB에서도 특정 조건의 오차가 크면 보고서의 실패조건으로 남긴다. 기준선의 문제가 충분히 줄었다면 그 개선을 쓴다. 차이가 작거나 표본이 부족하면 생산조건 오류 설명을 짧게 끝낸다. 목표 시각 생산량은 사후 진단용이며 예측 입력·경보 분기에 사용하지 않는다. 추가 모델 개발로 자동 연결하지 않는다.

### 3.2 경보를 포함할 때: 선택 기준의 비교

**이전 근거 → 질문:** M007은 개발 평균 1·2·4시간/일의 연구 예산으로 기준을 정하고 이후 기간에 고정 적용했다. 주 2시간 정책에서 HGB→q75는 사전 포착 47→54건, 경고 184→209시간, 새 알림 67→76회였다. 이미 이득과 부담이 수치로 있다. 추가로 필요한 것은 F점수 계산 자체가 아니라, 사용자가 어떤 교환관계를 선택할지 판단할 비교다.

| 기준 후보 | 선택 방식 | 장점 | 부담·주의점 | 현재 상태 |
|---|---|---|---|---|
| F2·F1·F0.5 | 개발 구간의 선택한 F점수를 최대화 | precision·recall을 한 수치로 비교 | 놓침 허용량·경보 상한을 직접 보장하지 않음. β를 실제 비용비로 읽지 않음 | 아이디어, 미채택 |
| 최소 recall 조건 | 목표 recall 이상에서 precision이 높은 기준 선택 | ‘얼마나 놓쳐도 되는가’를 직접 표현 | 목표가 높으면 오경보·경보량 증가. 달성 불가도 그대로 보고 | 비교 가능, 미실행 |
| 최소 precision 조건 | 목표 precision 이상에서 recall이 높은 기준 선택 | ‘경보를 얼마나 믿을 수 있어야 하는가’를 직접 표현 | 높은 요구에서는 많은 피크를 놓칠 수 있음 | 비교 가능, 미실행 |
| 경보량 제한 | 허용 경보량 안에서 포착을 비교 | 업무 부담과 연결하기 쉬움 | 원시 경고 시간·새 알림 수·일별 상한은 서로 다름. 개발 평균 예산은 이후 실제 상한을 보장하지 않음 | M007의 평균 시간 예산 비교 완료 |
| 여러 후보의 교환관계 표 | precision·recall·포착·경보량을 나란히 제시하고 사용자 선택 | 효용을 임의의 한 점수로 확정하지 않음 | 최종 판단이 필요함 | M007에서 일부 완료, 가장 먼저 재사용 |
| 놓침·오경보의 가중 손실 | 사용자가 정한 상대 부담으로 후보 비교 | 두 오류의 선호를 직접 반영 | 현재 실제 금액·피해량 근거 없음. 가상의 원화 비용을 만들지 않음 | 필요할 때만 선택 |

PR 곡선과 AP는 예측 점수가 높은 시간들을 잘 앞세우는지 비교하는 보조 수단이다. 그 자체로 최종 경보 기준이나 사건 시작 포착률을 정하지는 않는다. 모든 지표를 새로 계산해 본문에 넣을 필요도 없다.

**권하는 순서:** 기존 M007 표를 먼저 제시한다. 그것만으로 사용자가 선택할 수 있으면 새 기준 탐색을 하지 않아도 된다. 특정 recall·precision 수준에서 HGB와 q75를 비교해야 한다면 저장된 개발 예측에서 기준별 비교표를 한 번 만든다. 사용자가 목적을 선택한 뒤 필요한 기준만 고정 평가한다. 이후 구간을 보며 다시 조정하지 않으며, 7~8월은 이미 탐색한 기간이라는 점을 밝힌다.

실제 고전력 정의 `u`와 예측값에 적용하는 경보 기준 `c`를 구분한다. M007의 `u`는 개발 5월 183·6월 181, 이후 182로 서로 다르므로 개발과 이후 차이를 모두 모델 변화로 해석하지 않는다. 실제 피크 정의를 점수를 높이기 위해 바꾸지 않는다.

시간별 precision과 사건 시작 포착률은 단위가 다르다. 이 둘을 한 F점수에 섞지 않는다. 사용자 목적이 사건 시작을 미리 알리는 것이라면 사건 포착과 새 알림 부담을 주로 비교하고 시간별 F점수는 보조로 둘 수 있다.

M007의 ‘두 달 모두 포착과 모든 부담을 함께 개선’은 강한 채택 기준이다. 그 조건을 만족하지 못했다고 경보 활용 가치가 없는 것은 아니다. 사용자가 부담 증가를 받아들일 수 있으면 q75 같은 교환관계 후보를 선택할 수 있다. q75의 효과를 주장하려면 HGB도 자체 경보 기준을 조정할 수 있다는 공정한 비교를 유지한다. M007의 동일 개발 예산 비교는 이미 이 취지를 일부 반영했다.

| 비전력 조건의 군집·세부 제약 최적화 | A036 후속 5, A044~047의 조건부 범위 | 현재 선택을 바꿀 질문이 없어 추가하지 않는다. 시나리오 가정은 이미 명시한다. |

추가로, A036 후속 7의 **q75 실현 비율과 분위수 손실은 M006 12절에서 이미 확인했다.** 실제값이 예측값 이하인 비율은 5월 75.67%, 6월 68.19%, 7월 67.33%, 8월 67.88%였다. ‘75% 분위수니까 실제 75%를 덮는다’고 쓰지 않으면 된다. 이를 누락 분석으로 다시 제안하거나 자동으로 재보정할 필요가 없다.

유사한 과거 조건에서 다른 목표값이 나온 사례가 있어도 모든 입력이 정확히 같았다는 뜻은 아니다. 관측된 사례만으로 ‘어떤 모델도 예측할 수 없다’고 입증한 것은 아니다. 그렇다고 모든 원인을 밝혀야 하는 것도 아니다. **현재 모델·가용 정보에서 안정적으로 구분하지 못한 범위**로 한계를 적는다.

## 6. 단계별 현재 상태와 종료 기준

| 단계 | 현재 판단 | 다음 작업 / 종료 기준 |
|---|---|---|
| EDA | 현재 보고서 중심 질문에 필수인 새 원자료 탐색은 발견하지 못함 | E025와 기존 구조·반복·기간 결과에서 핵심 근거를 선택. 주장에 필요한 근거가 충족되면 해당 범위 종료 |

| Modeling | 새 모델 학습보다 작은 진단 보완과 목적 선택이 남음 | 생산 크기·증감별 저장 예측 비교. 경보 포함 시 기존 교환관계부터 검토하고 필요한 기준만 평가 |

사용자의 선택을 기다려야 하는 것은 경보에서 감수할 놓침과 부담이다. **기존 결과 정리와 생산조건 오류 비교까지 그 선택을 이유로 보류할 필요는 없다.** 이번 요청에서는 이전 기록 검토와 누락 판정까지 수행했으며, 위 보완 계산의 실행 결과가 나온 것으로 기록하지 않는다.

## 7. 검토·검증 범위

- 각 보고서의 질문·핵심 결과·후속 항목을 검토하고 후속 문서의 실행 결과로 연결했다. 총 76개는 문서 수이며 독립 실험 수가 아니다.
- 관련 README·LOG, M005·006의 생산조건 집계 코드, M007의 기준 선택·채택 규칙, 저장 결과·검증 기록을 대조했다. 모든 코드 줄·모든 표 셀을 재감사하거나 원자료에서 재계산한 것은 아니다.
- 실행·검증 완료라는 표시는 기존 실행 및 독립 검증 기록을 확인했다는 뜻이다. 이번 세션에서 해당 실험을 재실행했다는 뜻이 아니다.
- 이전 문서의 지시·계획은 과거의 검토 대상으로 취급했다. 현재 사용자의 요청은 중요한 누락을 찾는 것이므로, 과거 계획의 모든 후보를 자동 실행 대상으로 삼지 않았다.
- 원본 데이터·모델·예측·기존 결과표는 변경하지 않았다. 수정 대상은 이 감사 문서와 현재 상태 안내다.
