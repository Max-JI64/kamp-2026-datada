# 팀원 cjh EDA 전체 검토와 기존 jsw EDA 비교

검토일: 2026-10-02 | 작업: E026 | 비교 기준: 현재 저장된 `EDA/cjh` 전체와 `EDA/jsw` E001~E025

**팀원 결과의 중심은 기본 통계·분포·단순 상관·달력 패턴이다. 이 부분은 기존 EDA와 대부분 겹친다. 보탤 만한 것은 시간대별 생산량 곡선과 월별 평균 생산량의 직접적인 시각화다. 다만 노트북의 시간 대체와 일부 해석 오류를 수정해야 한다. 생산·인력 기반 가동 상태는 새 분류 아이디어지만, 현재 값의 계산 구조상 독립적인 운영 정보를 제공하지 않는다.**

## 2. 팀원은 어떤 내용을 분석했나

### 데이터 구조와 기초 결과

팀원이 제시한 6,168행·18열, 257일, 2021-01-01~09-14, 완전 중복 0행, 평균 전력의 평균 93.42·중앙값 104·최대 208, 생산량 기록값 합 2,882,582, 생산량 0인 2,657행은 기존 E001과 같은 내용이다. `111,024개`는 6,168×18의 셀 수이며 관측 행 수가 아니다. 생산량 합은 CSV 기록의 산술합으로 읽고 공식 ERP 실적 총량으로 확정하지 않는다.

보고서는 정상 시간의 평균 전력이 8시 121.25로 가장 높고 0시 52.56으로 가장 낮다고 정리한다. 생산량–평균 전력 Pearson 0.5179, 공장인원–평균 전력 약 0.289, 네 전력 칸–평균 0.985~0.995의 높은 상관을 보고한다. 이 숫자들은 기존 기초 분석과 방향이 같다.

노트북 cell 10은 14개 수치형 변수를 한 이미지에 그린다. 원본 그림은 한글 글꼴이 빠져 일부 제목·축 문자가 네모로 보인다. 변수 순서는 셀의 `numerical_cols`와 대조했다.

### 변수 간 상관관계

cell 12는 위 변수들의 Pearson 히트맵이다. 전력 열끼리 높은 상관, 생산량–공장인원 약 0.79, 기온–계절요금 약 0.81, 습도–계절요금 약 0.53을 보여 준다. 모두 기존 [E007 Pearson 행렬](../tables/09.23_007_pearson_matrix.csv)에 해당 관계가 있다.

팀원은 전체 상관을 중심으로 해석했다. 기존 EDA는 계산상 중복, 생산 유무, 월·시각·요일 조건, 반복 전력 패턴, 시차와 기간 안정성까지 구분했다. 따라서 동일한 양의 전체 상관을 제시했더라도 해석 깊이와 사용 조건은 다르다.

## 4. 기존 EDA와 겹치지 않는 것은 무엇인가

“새 결과”, “기존 결과의 새 표현”, “아직 결과가 없는 방법”을 나눠야 한다.

| 후보 | 중복 판정 | 판단 |
|---|---|---|
| 시간대별 **생산량 자체의 평균 곡선**, 19시 최대 | 보완 결과 | 기존 시간대 표의 주 목표는 전력이었다. 생산 유무·증감·기록 형태는 이미 분석했지만, 이 곡선과 19시 최대를 독립적으로 정리한 기존 표·본문은 확인하지 못했다. 정상 시각만 재집계해 소개에 보탤 수 있음 |
| 월별 **평균 생산량**의 한 표·막대그림 | 보완 요약 | 일별 생산량 합·월별 생산 유무·생산 기록 형태는 기존에 있음. 팀원의 1~9월 평균 생산량 나열은 기존 정보의 별도 요약이며 새로운 영향요인 발견은 아님 |
| 생산·인원 조합의 가동 상태 이름·시간/요일별 구성비 | 새 분류 제안, 유효한 새 운영 결과 없음 | 원본에서 두 변수의 0/양수 조합이 계산식상 일치한다. 예외 집단은 0건이거나 결측 대체로 생긴다. 상태 이름을 실가동 라벨로 채택하지 않음 |
| 변동계수 CV·첨도 | 기존 EDA에 없던 명시적 계산 항목 | 코드 설명에만 있고 실제 결과표 없음. “새로 확인한 결과”로 세지 않음. 기온처럼 0점의 의미가 임의적인 척도에는 CV 비교도 주의가 필요 |
| 14변수 분포 모음·생산량 박스플롯 | 표현 보완 | 기존 E004~E006이 이미 수치·빈도·변환·IQR로 분석. 새 데이터 사실이 아님 |
| 생산–인원 0.79, 기온–요금 0.81, 습도–요금 0.53 | 중복 | 기존 E007 행렬에 이미 포함. 새 변수 관계로 제안할 이유 없음 |

최소 재집계한 [시간별 정책 비교](../tables/10.02_026_cjh_audit/hourly_policy_comparison.csv)는 다음과 같다. 전력·생산량은 모두 원본 기록값 단위다.

| 범위 | 시각당 행 수 | 19시 평균 생산량 | 8시 평균 전력 |
|---|---:|---:|---:|
| 1~9/14 전체의 정상 시간 | 255 | 1,323.24 | 121.25 |
| 기존 후속 EDA의 1~8월 정상 시간 | 241 | 1,320.66 | 120.63 |

**생산량 평균이 가장 높은 19시와 전력 평균이 가장 높은 8시는 서로 다른 지표의 최대다. 서로 모순되는 결과가 아니다.** 이 어긋남은 생산량만으로 전력의 시간 패턴을 대표할 수 없다는 기존 판단과도 맞는다. 생산·전력의 공통 단위나 집계 생성 규칙을 확정하는 결과는 아니다.

[월별 최소 재집계](../tables/10.02_026_cjh_audit/monthly.csv)에서 평균 생산량은 1월 260.50, 2월 473.36, 3월 410.22, 4월 517.94, 5월 499.89, 6월 557.28, 7월 530.13, 8월 462.64, 9월 537.99다. 9월 분모는 336행이고 나머지는 월별 672~744행이다. 이는 **관측된 시간당 기록값 평균** 비교이며 생산 총량이나 계절효과 비교가 아니다.

## 5. 실제로 다른 점과 수정할 오류

### 시간 오류 처리: 팀원 자료 내부에도 세 방식이 있다

| 구분 | 48개 오류 시간 처리 | 결과·사용 기준 |
|---|---|---|
| 팀원 초기 보고서 | 시간대 분석에서 제외 | 초기 jsw E001·E002와 같은 정상 시간 6,120행 |
| 팀원 시간 정제 설명 | 날짜별 파일 행 순서로 0~23 복원 | 6,168행에 시간을 부여하는 가정 기반 대안 |
| 팀원 실제 저장 노트북 | 오류 → NaN → 전역 중앙값 11.5 | 오류 이틀의 48행을 모두 같은 날 11:30으로 배치 |
| jsw 후속 EDA | 정상 시각만 사용하고 공백 보존 | 1~8월 5,784행·241일. 오류 시각을 복원하지 않음 |

원본의 정상 시각 6,120행은 날짜별 파일 순번 0~23과 모두 일치했다. 따라서 행 순서 복원은 내부 정렬과 부합하는 **검토 가능한 가정**이다. 그러나 오류가 있는 7/13·7/15에는 정상 시각이 하나도 없어, 해당 날짜의 실제 시각을 확인한 복원이라고 부를 수 없다. 현 자료에서 실제 오류 시각은 미식별로 종료한다. 기본 EDA 기준을 바꿀 근거로 채택하지 않았다.

반면 중앙값 대체는 시간 복원으로 부적절하다. 48개 오류 행은 생산량이 모두 0이다. 대체 후 `시간=11.5` 그룹은 48행·생산량 평균 0·전력 평균 135.875가 된다. 날짜·시간을 합치면 이틀에서 각각 24행이 11:30에 모여 **중복 초과 46행**을 만든다. cell 14의 꺾은선이 11시와 12시 사이에서 0까지 급락하는 것은 이 인공 점을 연결했기 때문이다.

실제 정상 12시의 평균 생산량은 전체 정상 시각에서 **308.47**, 1~8월 정상 시각에서 **301.68**이다. 주변보다 낮은 모습은 별도로 기술할 수 있지만, 0으로 떨어지는 그림을 실제 점심·공장 정지로 설명하면 안 된다. 실제 원인은 현 자료에서 미식별이다.

### 결측 69개는 원본 결측 수가 아니다

원본 결측은 **공장인원 17+풍속 3+강수량 1=21셀**이다. 시간 열에는 원래 결측이 없고 범위 밖 값 48개가 있다. 팀원 노트북에서 그 48개를 NaN으로 바꾼 뒤에는 21+48=69가 된다. 초기 보고서의 “원본 결측 69개”는 이 둘을 섞은 수치다. 노트북의 첫 결측 출력은 실제로 21을 보여 준다.

### 공장인원·가동 상태 해석은 유지하기 어렵다

기존 [변수 진단표](../../../data/origin/데이터_변수표.md)·E001·E007의 계산 관계를 현재 원본으로 다시 확인했다.

```text
공장인원 = 생산량 / (15분 + 30분 + 45분 + 60분)
```

원본의 비결측 6,151행에서 최대 절대 차이는 약 `4.94e-9`다. 이 변수는 독립적인 실인원 관측으로 해석할 수 없다. 생산량–공장인원 0.79도 인력을 늘려 생산이 증가했다는 근거가 아니다. 같은 시점의 생산량과 공장인원을 함께 쓰면 전력 합계를 역산할 수 있어 미래 전력 예측 입력의 누출 위험도 있다.

팀원이 제안한 분류를 [최소 집계](../tables/10.02_026_cjh_audit/operation_conditions.csv)하면 다음과 같다. 팀원의 분류 계산을 확인하기 위한 이번 감사 결과이며 팀원이 저장한 결과표가 아니다.

| 기록 조합 | 원본 전체 | 노트북 방식으로 인원 결측 대체 후 |
|---|---:|---:|
| 생산량 양수·공장인원 양수 | 3,511 | 3,511 |
| 생산량 0·공장인원 0 | 2,640 | 2,640 |
| 생산량 양수·공장인원 0 | 0 | 0 |
| 생산량 0·공장인원 양수 | 0 | **17** |
| 공장인원 결측 | 17 | 0 |

17개 인원 결측은 생산량과 네 전력값이 모두 0인 기록이다. 중앙값 약 0.113을 넣으면 “생산량 0·인원 양수”를 인공적으로 만든다. 이를 정비·청소·관리 업무의 증거로 읽어서는 안 된다. `비가동`, `정상 가동`, `무인 가동 후보`, `비생산 인력 투입`보다 **생산량 0/양수와 인원 계산값 결측**이라는 기록 조건으로 표현하는 편이 정확하다.

### 상관 설명의 변수 쌍·부호 오류

저장 히트맵과 노트북 방식 재집계 [상관표](../tables/10.02_026_cjh_audit/notebook_correlations_recomputed.csv)를 대조했다.

### 평균과 네 전력값: 상관이 높아도 역할을 나눠야 한다

같은 행의 네 전력값으로 그 행의 평균을 예측하는 것은 정답 계산에 가깝다는 팀원 보고서의 누출 경고는 타당하다. 다만 노트북의 “대표 변수 선택 또는 차원 축소가 필수”라는 결론은 목적을 구분해야 한다.

- 미래 한 시간의 전력 네 값은 미래 평균 예측 입력으로 쓸 수 없다.
- 관측 완료된 과거의 네 값·최대·마지막 칸은 정보 시점 계약에 따라 예측 입력 후보가 될 수 있다.
- 피크 분석에서는 평균과 최대를 함께 남겨야 한다. 높은 상관만으로 평균 하나를 대표로 고르면 평균에 가려진 최대를 놓친다.

기존 E015의 1~8월 정상 시각·최대 187 이상 **287시간 중 194시간(67.60%)**은 저장 평균이 187 미만이었다. E025에서 정확 산술평균으로 정의를 바꾸면 **202/287(70.38%)**다. 팀원의 높은 상관은 이 차이를 부정하지 않는다.

### 분포·달력·큰 값의 해석

- 기온 그림으로 정규성을 확인했다고 볼 수 없다. 풍속을 Weibull/Gamma로 명명하는 것도 적합도 검증이 없다.
- 월별 생산량은 4월→5월, 6월→7월→8월에 감소한다. “4월부터 점진적으로 증가”라는 문구는 “월별 차이가 있고 6월 평균이 가장 높다”로 좁힌다.
- 9월은 14일뿐이다. 전체 달의 평균 생산량·합계·계절성을 대표하는 것으로 일반화하지 않는다.
- `day/d/m`은 기존 변수표에서 날짜의 요일/일/월과의 관계를 확인했다. `day`를 단순 숫자 상관 순위로 해석하지 않는다.
- 계절요금은 1~2월 109.8, 3~5월·9월 167.2, 6~8월 191.6으로 배정된다. 팀원 설명의 경부하/중간부하/최대부하 시간 요금 구간은 이 열에서 확인되지 않는다. 소개 문서의 청구 제도 문장은 제공 자료의 배경 설명이며 현재 계약·실제 절감액을 검증한 결과가 아니다.
- 생산량 박스플롯의 IQR 밖 점은 오류 판정이 아니다. 전체 6,168행 기준 상한 1,593.125·표시 대상 548행과 기존 E004의 1~8월 5,832행·533행은 범위가 다르다. 원하는 결론을 얻기 위한 삭제 대상이 아니다.

## 7. 채택할 내용과 이번 검토의 종료

1. **생산량의 시간별 곡선은 보완 자료로 채택 가능하다.** 11.5시 인공 점을 빼고 정상 시각의 곡선으로 읽는다. 19시 생산량 최대와 8시 전력 최대의 차이는 기록 수준의 관찰로만 설명한다. 이번 표에서 전체와 1~8월의 해당 수치를 비교했으므로 별도의 복원·모델 실험은 필요 없다.
2. **월별 평균 생산량은 소개용 요약으로 활용 가능하다.** 9월의 14일 분모와 비단조 변화를 표시한다. 생산이 늘어난 물리적 원인·계절효과는 현 자료에서 미식별로 종료한다.
3. **분포·전체 상관은 기존 분석에 연결한다.** 중복 분석을 다시 수행하거나 새로운 발견으로 세지 않는다. 잘못 읽은 상관 부호와 실인원 해석은 수정 대상으로 기록한다.
4. **생산·인력 가동 분류를 실가동 라벨로 채택하지 않는다.** 원본 조합·결측 대체 전후를 계산했고, 예외 17개가 대체로 만들어지는 것까지 확인했다. 추가 상태 세분화는 하지 않는다.
5. **시간 기준은 기존 EDA를 유지한다.** 행 순서 가정은 내부 일치성을 확인했지만 실제 오류 시각의 복원은 미식별이다. 중앙값 시간 대체는 채택하지 않는다.

이번 요청의 전체 파일·이미지 내용 파악, 중복/보완/다른 해석 판정은 종료한다. 팀원 자료에서 기존 전력 결론을 바꿀 검증된 근거는 확인되지 않았다. 팀원 원문을 수정하거나 새 모델을 학습하지 않았으며, EDA 전체 재실행·제출 검수를 완료했다는 뜻도 아니다. 추가 자료 대기나 막연한 추가 분석을 후속으로 남기지 않는다.

## 8. 재현·검증 범위

이전 근거는 E001·E004·E007·E013·E023~E025의 저장 수치다. 이번 질문은 “팀원 결과에서 기존과 다른 내용은 무엇이며 그 차이가 처리 조건 때문인가”였다. 그래서 전체 모델·EDA를 재실행하지 않고, 팀원 노트북 이미지 추출과 원본의 최소 비교 집계만 수행했다.

- [감사 코드](../scripts/10.02_026_cjh_comparison_audit.py): 팀원 코드 실행 없이 파일 목록·구문·노트북 출력·PNG를 추출하고 시간/월/인원 조합·상관을 집계한다.
- 실행: `EDA/jsw`에서 정규 CPython 3.13.1, pandas 3.0.1. 사용자 지정 승격 `Start-Process -Wait -PassThru -NoNewWindow` 사용, 실제 종료 코드 **0**.
- [facts.json](../tables/10.02_026_cjh_audit/facts.json): 원본 SHA-256, 분모, 실행 환경·시각, 플롯별 셀/크기, 오류 시각·중복·인원 비율식을 기록했다.
- 원본 SHA-256은 `8f7af2e49366c93e1d6f5fdef4b5e350066c1792ac463c2c2886e370f4674830`으로 기존 EDA와 같다. 원본·팀원 파일·기존 결과표를 수정하지 않았다.
- 노트북의 저장 PNG 5개를 직접 확인했다. 한글 글꼴 누락은 변수 순서 코드·재집계 표로 보완했다. 노트북 전체를 새로 실행하거나 모든 팀원 코드 조각의 실행 가능성을 검증한 것은 아니다.
- “노트북 방식 재집계”는 현재 pandas에서 같은 값 대체를 명시적으로 구현한 것. 팀원 노트북의 `fillna(..., inplace=True)`는 저장 출력에 pandas 버전 변경 경고가 있어 그대로 재실행한 것으로 표시하지 않았다.
- 판단 갱신: 새 운영 영향요인 발견이라는 해석은 채택하지 않고, 생산 기록의 별도 시간/월 요약을 보완 가치로 분류했다. 처리 오류·상관 오독·비율 변수의 운영 명명을 분리했다.
- 최종 파일 확인: 보고서 상대 링크 25개가 모두 존재하며, 팀원 파일 11개의 해시와 원본 해시가 감사 시작 때와 같다. 확인 기록은 `tables/10.02_026_cjh_audit/validation.json`에 저장했다.
